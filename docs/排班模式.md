# 排班模式

> 文档角色：canonical
> 生命周期状态：current
> 代码范围：crates/infra-core/src/schedule/、crates/infra-cli/src/commands/plan*.rs
> 知识库桥接：docs/知识库引用.md（机制正文与版本由隔壁知识库裁决）
> 代码锚点：TimedRotationProfile、compute_plan
> 关联链路：docs/定时换班.md、docs/调用链/定时轮换.md
> 核验基线：入口参数解析和 profile 闭集

| 模式 | 状态 | 触发模型 | 当前入口 |
|---|---|---|---|
| timed_rotation | current | 固定 profile 和相对间隔 | plan、layout team-rotation、serve plan.compute |
| auto_rotation | 未实现 | 游戏内置按组合耗尽 | 无 |
| mower_dynamic | 暂停 | 实时心情、宿舍和动态替补 | 无 |

未声明模式默认 timed_rotation。MAA 是输出格式，不是另一套求解语义；Mower 不能套用固定班次、菲亚目标或宿舍策略。若恢复其他模式，必须新增独立输入合同和验证基线。

## 模式隔离

timed_rotation 的输出是 TeamRotationReport，外部可以继续投影到 MAA，但触发时刻不写入 solver。auto_rotation 若将来恢复，必须定义自己的耗尽/替补状态；mower_dynamic 必须定义实时心情、宿舍黑名单和动态替补。任何新入口不能仅通过给 timed_rotation 加一个布尔开关来冒充另一种模式。
