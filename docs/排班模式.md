| 模式 | 状态 | 触发模型 | 当前入口 |
|---|---|---|---|
| timed_rotation | named current；generic WIP | 本次 WIP 源码包含 named timing、普通二/三班拓扑和有序时长；generic 尚未完成当前源码的 fresh release 验收 | plan、layout team-rotation、serve plan.compute（generic WIP） |

| mower_dynamic | 暂停 | 实时心情、宿舍和动态替补 | 无 |

未声明模式默认 timed_rotation。MAA 是输出格式，不是另一套求解语义；Mower 不能套用固定班次、菲亚目标或宿舍策略。若恢复其他模式，必须新增独立输入合同和验证基线。

当前保留的 named timings 包含 ABC `12/6/6`、ABC `12/12/12`、主备 `12/12`、主备 `24/24`、菲亚 `8/8/4/4`、深海 `7/5/7/5`。本次 WIP 的普通泛型拓扑接受按序时长：CLI 使用 `main-backup@H1/H2` 或 `abc@H1/H2/H3`；Worker `plan.compute` v7 WIP 使用 `{ "topology": "main_backup" | "abc", "shift_hours": [...] }`，尚未 fresh release 验收或部署。普通二/三班分别保留 topology-specific 构造，再进入共同完成/终态流程；主备互斥与 ABC 2 上 1 休仍是不同 topology policy。调用方负责过滤不合法时长组合，后端按拓扑承载时长并求解。旧 named timings 保留原 wire 与既有行为；普通自定义时长不新增 profile 枚举。主备 `12/12`（24h 周期）和 `24/24`（48h 周期）仍是独立兼容输入。

普通拓扑把最长时段映射到 α；ABC 并列最长时把休班相位放在较短班，尽量覆盖全部并列最长班，完全等长保留旧相位。普通泛型周期由前端限制为 24h、36h 或 48h；单个班次超过 12h 时该班最多生成一次菲亚动作，仍受 ready 和最终 assignment 核对。24/24 named 与泛型长班都按实际 ETA/心情准入，不再使用姓名黑名单；泛型超过 24h 使用实际输入时长。规则和交付边界见 [ADR 0011](ADR/0011-generic-two-three-shift-rotation.md)。本次不把 `fiammetta_8_8_4_4`、`abyssal_7_5_7_5` 等四班特殊模式改为通用时长模式。

独立“龙巫二班”已从产品支持中删除。`fiammetta_witch_12_12`、`fiammetta-witch-1212`、`witch-1212` 等旧请求明确返回不支持，不映射到普通主备，也不生成 fallback 排班；普通贸易同站组合不受影响。Worker v6 保持闭集；本次 v7 WIP 新增 topology + `shift_hours` 对象，v1–v6 schema 与 wire 含义不变。

## 模式隔离

timed_rotation 的输出是 TeamRotationReport，外部可以继续投影到 MAA，但触发时刻不写入 solver。auto_rotation 的替补状态是每站一主一替：按组内首人红脸或 36 小时中较早者评估在岗时长，各站独立换班，不模拟错班；其完整语义见 [自动轮换](自动轮换.md)。mower_dynamic 必须定义实时心情、宿舍黑名单和动态替补。任何新入口不能仅通过给 timed_rotation 加一个布尔开关来冒充另一种模式。
