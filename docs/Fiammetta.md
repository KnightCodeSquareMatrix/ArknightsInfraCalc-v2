# 菲亚梅塔换心情规则

> 文档角色：canonical
> 生命周期状态：current
> 领域键：schedule.fiammetta
> 当前真源：self
> 摘要：裁决菲亚梅塔在当前排班中的目标和边界

> 实现快照：ABC 可在班次边界让但书、可露希尔或清流保留核心并重新搜索队友；`12/12/12` 可将巫恋+龙舌兰作为原子组连续使用，并以两只不同裁缝 β 形成 AAB。具名 `fiammetta-witch-1212` 提供同组 AB 二班，且不放宽普通 `main_backup_12_12` 的全员互斥合同。目标顺序按贸易站数量区分 153、243/252、333/342；精0/精二但书均可成为目标。具名 `fiammetta-8844` 保留单点事件插班；换心情可用 `--no-fiammetta`（CLI）或 `plan.compute` v3 `options.fiammetta_enable=false` 关闭；完整实时收益率和跨周期永续心情排班仍未实现。
> 规则来源：公孙长乐 2026-07-11 评审稿。

## 当前已经实现

`plan`、`layout team-rotation` 和 `infra-cli serve` 的 `plan.compute`（兼容期内也包括 legacy `plan`）生成默认 ABC 排班时，会从 peak 主力选择一个菲亚梅塔目标：

```text
153：可露希尔 > 巫恋 + 龙舌兰（两者同时使用，搭配两只不同裁缝 β） > 但书（精0/精二）
243 / 252：但书（精0/精二） > 可露希尔 > 巫恋 + 龙舌兰（两者同时使用，搭配两只不同裁缝 β） > 清流
333 / 342：但书（精0/精二） > 可露希尔 > 清流 > 巫恋 + 龙舌兰（两者同时使用，搭配两只不同裁缝 β）
```

菲亚梅塔回岗默认启用。如需关闭，CLI 使用 `--no-fiammetta`（`plan` 与 `layout team-rotation`）；`plan.compute` 使用 v3 契约的 `options.fiammetta_enable`（默认 `true`）。关闭后 ABC 排班不生成任何回岗动作，输出 MAA 的 `Fiammetta.enable` 全部为 `false`。`fiammetta_enable=false` 与显式 `rotation: fiammetta_8_8_4_4` 组合直接硬错误，不回退三班。

选择规则：

1. 账号必须拥有菲亚梅塔。
2. 在 `S3` 结束时，按上述顺序检查当班生产成员；目标必须也已由下一周期 `S1` 的正常生产搜索选中。
3. 菲亚为目标换心情后，目标与其他干员一样参与 S1 候选搜索；搜索正常决定其是否上班及所在房间。
4. schedule 不得把目标直接塞回 peak 原房，也不得顶替或指定任何 S1 当班干员。
5. 只有实际发生换心情的 S1 输出 `enable: true`、`order: pre`；其余 plan 关闭。

全精二 243 当前示例中，S3 结束时菲亚为但书换心情；但书作为普通候选由下一周期 S1 搜索到贸易站。

菲亚事件发生在 `S3 -> S1` 周期边界。基础 `A+B → B+C → C+A` rotation 仍负责构造 S1 的正常候选和最终房间；菲亚不改写该结果，也不通过房间替换破坏既有的 cohort、bind 或 reserve 语义。

MAA 负责执行具体的宿舍拖动、心情交换和菲亚梅塔返回宿舍。InfraCalc 当前只声明是否启用、目标和使用顺序，不强制宿舍槽位。MAA 自定义基建 JSON 的 `Fiammetta` 契约只含 `enable` / `target` / `order` 三个字段，没有宿舍槽位字段；“菲亚梅塔宿舍一号位”是降低误操作的执行建议，由执行工具落实。

默认 ABC 每个 24 小时 αβγ 周期只安排一次回岗，因此不会再对三个 plan 逐班盲目启用。`12/12/12` profile 最多在三个 12h 班各安排一次；但书、可露希尔、清流可保留核心并逐班重新搜索队友，完整龙巫组使用两只不同裁缝 β 形成 AAB，并分别为巫恋、龙舌兰安排一次菲亚动作。条件不足或改写会破坏其他已认领 bind 时，该组路径 fail-closed。它仍未模拟菲亚的实时剩余心情，不能视为跨多周期永续证明。

具名 `--rotation fiammetta-witch-1212` 使用两个 12h owner：巫恋与龙舌兰固定在同一座三级赤金贸易站，两只不同裁缝 β 按 AB 轮换，两个 plan 分别输出巫恋与龙舌兰的菲亚动作。该 profile 通过预认领 Plan hard anchors 构造，不复用或修改普通 `main_backup_12_12`；缺菲亚、缺完整龙巫、少于两只裁缝 β、无三级赤金贸易站或任一完整 owner 无解时直接失败。

显式 `--rotation fiammetta-8844` 使用另一条已落地路径：先构造 `16/4/4` 的 ABC 状态，再把首段展开为 `8/8/4/4`。第二个 8h plan 是菲亚事件边界；MAA 跳过其他房间和无人机，只执行菲亚并重放目标原工作房，使目标回岗。该目标房按重新进驻后的 8h 计算暖机，其他未换房设施按连续 16h 的后 8h 增量结算。没有菲亚梅塔或没有合法 peak 目标时显式 profile 直接失败，不回退三班。

当前以公孙确认的固定目标优先级为业务规则，在合法替换位中选择瞬时评分最高者，
但不会用当前仍待校正的局部效率数值否决回岗。最终收益应由后续“主力最长工作时间
+ 替补时间 + 恢复”全周期模型判断，而不能只看单个短班的临时评分。

## 已确认的机制与策略原则

菲亚梅塔是独立的心情交换事件，不是普通宿管，也不是一支完整替补班。她的用途是让高价值主力继续工作，减少低效率替补的上班时间。

使用前提和时机：

- 菲亚梅塔本人必须满心情；
- 默认在换班前使用，即 `order = pre`；
- 使用后菲亚梅塔回宿舍恢复；
- 菲亚梅塔自身按每小时 2 点恢复，不叠加其他宿管恢复效果；
- 下一次理论就绪时间为 `(24 - 交换后菲亚梅塔心情) / 2` 小时。

后续排班层选择目标时，基础收益率建议为：

```text
菲亚收益率 = (主力效率 - 替补效率) / 主力每小时心情消耗
```

这表示主力与替补的效率差越大，菲亚梅塔的价值越高；效率差相同时，心情消耗较低、一次交换能维持更久的目标优先。

## 尚未实现的动态规则

公孙长乐确认的当前业务优先级依赖布局和成组关系：

```text
153：可露希尔 > 巫恋 + 龙舌兰（两者同时使用，搭配两只不同裁缝 β） > 但书（精0/精二）
243 / 252：但书（精0/精二） > 可露希尔 > 巫恋 + 龙舌兰（两者同时使用，搭配两只不同裁缝 β） > 清流
333 / 342：但书（精0/精二） > 可露希尔 > 清流 > 巫恋 + 龙舌兰（两者同时使用，搭配两只不同裁缝 β）
```

当前轻量 schedule 已实现上述布局分支顺序，但仍未实现替补收益率和实时心情状态。以下完整实时能力必须继续留在排班策略层，不能塞进 `export/maa.rs`：

- 在同一布局分支内根据房间等级和实际候选比较但书、清流的具体队友；
- 根据菲亚自身实时剩余心情判断固定 AAB / AB 是否能跨多个周期持续执行；
- 根据主力与替补的效率差实时计算收益率；
- 判断菲亚梅塔是否满心情、目标剩余心情和下一次就绪时间；
- 根据班次间隔、中枢心情减免和设施心情消耗决定可服务人数；
- 生成 Mower 的动态主力/替补策略，或基于实时心情展开更多 MAA 固定计划状态；`12/12/12` 的固定三事件上限不属于该未实现范围。

通常不建议把红松林、迷迭香等多人组合或高心情消耗的歌蕾蒂娅作为常规单点目标，但这仍属于后续排班策略，不是当前导出过滤规则。

## 代码边界

| 层级 | 当前职责 |
|------|----------|
| `schedule/` | 选择周期边界目标；S1 仍由正常候选搜索、编排和评分决定 |
| `export/maa.rs` | 忠实把 schedule 已确认的动作写成 `enable`、`target`、`order` |
| `infra-cli` | 调用 ABC 排班并写出 schedule 已确认的菲亚动作 |
| MAA / Mower | 执行宿舍操作与实际换班 |

本功能不等于完整宿舍恢复模拟、全基建连续心情最优化或菲亚梅塔永续证明。
