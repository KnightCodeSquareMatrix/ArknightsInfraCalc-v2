本页是泡泡/火神源石预占的唯一 current owner。其他页面只说明调用位置、摘要或验证入口，不重新裁决条件、房选、班次或失败策略。

## 1. 用户裁决与适用范围

- 用户于 2026-10-20 要求该组合自动优先搓玉、不加产品开关，并沿用对应排班拓扑的轮休。
- 用户于 2026-10-21 裁决：普通二班/三班全部全局强制泡泡/火神预占；两人固定属于 α 队，α 覆盖最长时段（若存在 12h 或更长班次则优先该班，但没有 12h 时也不关闭强制预占）。四班菲亚 `8/8/4/4`、深海 `7/5/7/5` 先不纳入本次改造。
- 实现范围是本次纳入的所有普通二/三班，包括 named timing 与泛型 timing；四班专用路径保持不变。完整状态与开放子项见 [ADR 0011](ADR/0011-generic-two-three-shift-rotation.md) 和 active-change checkpoint。
- 本规则是适用二/三班排班的强制预占事实，不是制造候选的一个收益加分项，也不承诺该组合高于所有其他完整布局方案或全局最优。

## 2. 启用条件与选房

同时满足以下条件时启用：

1. Box 中泡泡至少 E1，火神 E2。
2. 蓝图按原顺序存在第一个满足“制造站、三级、容量至少 3、源石配方”的房间。

选房只取该第一个合法房间：

- 不遍历全部源石房后按当前收益重选。
- 不因赤金、经验或普通制造评分另选房间。
- 不把用户说的“第一个源石房”扩展成任何等级或任意容量。

任一条不满足时，规则静态不启用，保持当前适用的普通二班/三班排班，不产生本规则的 warning 或 Plan anchors。

## 3. Plan 与成员归属

峰值求解前，泡泡和火神分别写为同一 `RoomId` 的 `rotation_originium_pair` hard anchors：

- facility 为制造站，recipe 为源石，fill policy 为制造配方。
- 两者必须同房，不允许被后续阶段拆散或搬走。
- 峰值 Plan 增加两人同组的不可拆 shift bind；工作/休息次数遵循对应二队或三队拓扑，不把 ABC 的 2 上 1 休数字硬套给两队主备。
- 第三席不预绑定姓名；若合法普通制造候选仍可用，正常比较补入。

房身份由冻结的 `RoomId` 在阶段间传播。后续阶段不得通过“房内恰好有两人”重新猜测目标，也不能用干员姓名另找房间替代。

## 4. 班次与休息

普通 topology 的轮休关系保持如下；源石 pair 始终属于 α，并跟随所选 topology 的 α 工作状态：

- S1 工作：α + β，γ 休。
- S2 工作：β + γ，α 休。
- S3 工作：γ + α，β 休。

α 按真实时长和 topology 状态映射确定：普通主备的 α 是主队，β 是替班；ABC 仍为三队两上休一。ABC 并列最长时把休班相位放在较短班，尽量让 α 覆盖全部可覆盖的并列最长班；完全等长时沿用 named `12/12/12` 的原相位。named timing 保留原班序。

- ABC 的标准 cyclic state 中 α 工作两个班、休息一个班；实际输入时长由同一序列驱动，不把某个 Shift 下标或 12h 门槛作为源石组合启用条件。

泛型二/三班必须使用实际输入时长决定最长时段，不固定班次下标或把 12h 当作启用门槛。三队 ABC 保留两班工作、一班休息；两队主备遵循 α 主队与 β 备队各自状态。现有 `12/6/6` 与 `12/12/12` 的时序仅作为兼容实例，不能推导任意新时长仍有相同的固定班数。

## 5. 跨阶段保护

冻结房和 pair 必须跨以下阶段保持同一身份与完整成员：

- 生产房切半及朝向重试；冻结房始终归 α 完整组件，不拆 pair 或换派给 β。
- 巫恋/龙舌兰等 reserve 移房；需要移动含冻结房的组件时拒绝该切分，而不是搬走已预占房。
- Nightmare shadow 生产比较仍可在其他空贸易/制造房运行；generic pipeline 消费显式冻结 `RoomId` claim，只清空、重建其他生产房，不通过泡泡/火神姓名推导策略。
- 暖机整房交换；冻结房、目标房或含 pair 的房不参与交换。
- 适用的二/三班生产重建与普通补位；冻结房从可被清空/重建的房间集合中排除。
- 菲亚梅塔目标重填；冻结房不作为目标写入房。
- 四班专用路径本次不泛型化、不改变；若未来纳入，须单独扩展其 profile 事实和验收，不得由本 ADR 推导已覆盖。

普通补位仍可补第三席。其他方向的选择、评分、轮休和特殊动作继续消费同一最终 assignment，不得在导出阶段重新选人。

## 6. 失败与输出

### 条件不成立

缺泡泡、缺火神、练度不足或没有合法三级源石制造房时，静默普通排班。这是规则不适用，不是失败。

### 目标房预占局部失败

若资格和合法房都成立，但目标房的双 anchor 制造完成无法产出合法命中：

- 丢弃这次预占峰值，重新运行普通峰值求解。
- rotation 与 MAA 必须由重跑后的最终 assignment 生成，保持同房同人。
- 正常产品输出保留普通峰值，并写一条可定位 warning：

```text
rotation_final_invariant: originium pair preclaim failed: …; ordinary peak retained
```

- 显式 `--assert-invariants` 必须失败，因为最终状态已丢失仍应成立的预占事实。

当前“pair 本身无法完成、普通 peak 可重跑”分支尚无真实完整 Box witness；代码路径与显式 gate 已注册，但这不能写成该失败分支已被真实 Box 触发。

### 第三席不足

三级容量下，泡泡与火神仍完整在房、合法普通第三席候选耗尽或全都不能通过房间准入时：

- 保留两人短员房间，不升级成预占失败。
- 输出普通制造短员 warning。
- 显式 gate 允许两人短员，因为规则要求的是 pair 与冻结房，不是制造房必须满员。

## 7. 最终状态不变量

显式 gate 从 `TeamRotationReport.shifts[].assignment` 和对应 owning Plan 核对：

1. 仅对本次纳入的普通二/三班拓扑强制此不变量，且 Box 资格仍成立；四班专用路径不因本次改动而变化。
2. peak Plan 恰有同一 RoomId 下的两个 `rotation_originium_pair` anchors，facility/recipe/fill policy 正确。
3. 冻结房仍是合法三级源石制造房。
4. pair 的工作/休息状态与 owning topology 一致；α 实际承接最长时段，并在 ABC 拓扑允许时覆盖全部并列最长班，休息状态不得残留任一成员。
5. 每个 α 工作状态的最终 assignment 都必须包含两人同房，且 owning Plan 含对应 anchors。
6. 输入时长与 active-team 状态一致；房内不得出现重复 pair 成员。
7. 第三席允许缺失，但不得超容量、重复或非法替换 pair。

该 gate 保证的是最终状态符合本页事实，不证明候选全集完整、布局全局最优或任意输入永不失败。

## 8. 验证

验收必须使用 release 的真实完整 Box 排班入口，生成 rotation、最终 assignment 与 MAA，并同时调用 `--assert-invariants`。不使用局部 helper 检查替代真实 Box；批量 gate 使用 `scripts/assert_rotation_invariants.py` 和 representative/high-owned 持久 Box。本阶段不以源码单元测试作为验收，也未运行源码测试；继承的测试草稿不属于本页的通过证据。

至少覆盖：

- 普通二班与三班的旧 named timing、代表性非均匀时长、最长班 α 归属，以及两种 topology 的队伍/轮休；泛型菲亚槽与自定义 >24h 策略按 ADR 0011 的 2026-10-21 裁决验收。
- 缺泡泡、缺火神、练度不足、无合法源石房，以及预占失败的 warning/final gate 分离。
- 只有 pair、第三席耗尽时的短员 warning 与显式 gate。
- owning Plan anchors、按对应队伍拓扑的工作/休息关系、MAA 与最终 assignment 同房同人。

当前工作区中存在未提交的 `rotation_originium_priority.rs` 草稿；它不是本次审阅或新范围的通过证据。批量通过只证明所列输入与已注册断言，不替代领域审阅。调用位置、状态流和验证边界另见[定时轮换调用链](调用链/定时轮换.md)。
