## 一个可计算的领域问题

用户本会话指出：“大部分人看到这个问题可能会进行复杂的剪枝。我看到的是它问题规模有限而且有统一的量纲。”这给出理解和维护方向，以下责任解释由当前代码核实，并非用户逐字规定的新架构。

物理蓝图的房间和席位有限；单个生产房通常只有一到三人，中枢至多五人。输入账号进一步限定候选。技能组合确实复杂，但组合可直接结算：先确定真实人员与环境，再计算这一组合的收益和资格，按明确目标比较。维护时先用这个模型解释问题，证据证明它不够时才讨论额外搜索或剪枝。

直接效率统一用 `Efficiency` 千分倍率表示，1000为1.000；贸易先把订单单位产出倍率计入最终效率，再与同域候选比较。制造、发电也各用其直接效率。不同产物的绝对数量仍有各自单位，不能因此任意相加。跨域选择需要具名policy或显式词典序，不能把“统一量纲”理解成任何收益都能无条件求总分。排序事实与尚未贯通的跨域纸面效率边界见[评分owner](../机制/SCORING_MODEL.md)。

## 六个责任步骤

| 步骤 | 要回答的问题 | 状态和责任 |
|---|---|---|
| 输入 | 有谁、设施是什么、采用什么模式和时长？ | OperBox、Blueprint、请求；数据层映射技能，不裁决产品规则 |
| Plan | 哪些体系可以进入、必须有谁、依赖谁、会抢谁？ | 有限alternative、required角色、排除、依赖和绑定；先拒绝非法候选，再比较合法候选 |
| execute | 选定计划实际占了哪些位置？ | 把Plan锚点/claim落入BaseAssignment，建立真实used；不是再选一遍体系 |
| fill与搜索 | 剩下的席位由哪个合法组合占用？ | 域搜索结算实际组合；普通补位消费同一Plan、占用、容量与绑定，不再复筛工作心情 |
| resolve | 当前实际人员产生了哪些环境效果？ | Workforce、资源、注入、转换与房间快照；每次人员变化后刷新，不能把“拥有”当“在岗” |
| 排班与输出 | 名单如何组合成班次/建议，最终是否合法？ | 模式决定轮换拓扑；最终真实assignment断言；CLI/导出忠实投影 |

主路径与细节唯一归[Plan owner](ORCHESTRATION_LAYER.md)、[编制owner](BASE_ASSIGNMENT.md)和[状态刷新调用链](../调用链/跨设施状态刷新.md)。此页解释责任关系，不复制技能表或规则清单。

## 三种模式共用什么

两班产生两份工作成员互斥的名单；自动轮换先选择主中枢并完成整份主力工作名单，冻结后才用剩余工作成员选择备中枢和替补；各站独立使用名单，宿舍只保留共用常驻挂件，不生成时间线或恢复过程。三班把生产分为两半，γ分别补两半，形成αβ、βγ、γα，人员两上一休。这个拓扑差异归schedule，设施搜索、required、占用和机制结算仍归原owner。自动挂件在临时可兑现环境下交给设施搜索选人；赢家包含受益者才由Plan保留挂件和依赖，不另比较整份基建收益。普通定时的既有竞争政策保留。

窗口是明确输入。普通两/三班Plan提前比较、设施搜索与最终评分必须消费同一阶段的H；三班Peak的累计窗口是既有拓扑派生，γ两半各有自己的H。自动`auto@24/12`的主力与替补收益分别只算24h和12h，候选可工作30h也不增加24h请求的收益。按2026-10-31裁决，仅保留最初中枢名单与初始Plan中枢认领ETA；后续工作预算不再用于筛选或拒绝，真实心情不足由终态质量提示说明。具体语义只归[定时换班](../排班/定时换班.md)、[自动轮换](../排班/自动轮换.md)。

## 容易被AI改坏的边界

- required是进入和落位条件；tag、priority、shortcut、shift_bind不能冒充准入。shortcut解释实际组合，不能选择人。
- 初始中枢ETA、真实心情/暖机积分、终态质量诊断和菲亚本人ready各有责任；不能以“补全检查”为由恢复逐组合、补位、动作目标工作预算或心情重试。最初试算并非任意完整周期心情充足的代码证明。
- 机制说明、有资格、必须选入、实际触发、最终胜出是不同问题。解释某人为何入选，需要合法候选及比较窗口的证据，不能只指出池中有他。
- 人员变化后旧效率不能继续作新配置事实。诊断报告也要保留完整一致快照；缓存身份要包含影响结算的模式、时长、实际人员和外部状态。
- 同域枚举可完整覆盖指定池，并不意味着整份布局全局最优。有序Plan竞争、逐房提交、中枢顺序、候选截断与模式构造仍有policy/heuristic边界。优化必须在具体owner说明保证等级，不能用“问题有限”宣称全局穷举。

这些是现有结构和约束的解释，不新增禁令。具体保证等级与验收归[质量文档](../质量与维护/QUALITY_AND_AUDIT.md)。本页不定义新的事件系统、搜索框架或知识真源。
