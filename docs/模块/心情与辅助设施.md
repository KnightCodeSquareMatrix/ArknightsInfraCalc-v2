## 心情链

```text
MoodModel::load_default
 -> operator_net_drain(DrainInputs)
 -> shift_eta_with_instances / workable hours
 -> schedule assignment and warnings
 -> dorm_recovery_rates / dorm_finalizer
 -> actual next-shift mood for efficiency
```

`operator_net_drain` 计算当前设施、skill、control/global input 下的净消耗；`shift_eta_with_instances` 还按实际实例的 `cc.g.sui` 标签，使同中枢令的 `sui_only` 消除仅命中岁干员自身心情技能，非岁同房者及其他来源仍保留。`shift_eta*` 不写 assignment。所有定时 profile 的 `schedule/cycle_mood.rs` 从最终 assignment 消费这六类持续设施净耗，按人累计首尾及跨设施连续预算；只有实际离岗满休边界近似或最终菲亚 pre 动作重置预算，周期边界不恢复。该近似不改变 recovery/finalizer 的宿舍落位，export 不推断恢复。训练活动缺输入只作质量诊断，加工站无加工事件只记占位，不伪造每小时成本或恢复。

`control_pair_recovery` 是中枢指定两人的同房恢复数据：按来源干员的实际练度选最高已解锁档，不累计被替换的低档；净消耗在共同下限处理前扣除。它读取当前 `DrainInputs.room_ops`，不把全账号拥有、其他房间成员或全局中枢名单当作同房见证。魔王两档技能沿既有空 atom 形式明确委托到该 owner，候选试放的无实例 ETA 和 contextual ETA 均消费它，无需另一条技能表加载路径。该项不进入 uniform recovery、笑脸扩散或全局恢复族比较；第三人及其他设施不因配对获得恢复。最终 Rust gate 另检查精确映射，并在实际终态 assignment 上比较有/无配对的 ETA，不以 helper 自证或 MAA 文本替代。

## 辅助设施

`evaluate_support_room` 提供共享 notice/contribution/mood delta 类型；office、meeting 分别静态求值。`resolve_base` 将 support results 写入 `LayoutContext`；pipeline 在生产岗位后调用 support assignment。office fallback pool 当前为空，不能静默读取全 roster。power 结果经 `apply_power_to_layout` 写入布局，DroneAction 由 schedule/export 消费。

profile ETA、静态 office/meeting 结果和全局无人机速度都可能是 policy 输入，不等于全局最优连续换班。核验使用 `layout eval --explain-json`、`plan --assert-invariants` 和代表性班次 fixture。

## 发电缺员补位

发电填房先按原有技能候选搜索；不足时才消费 `build_power_pool_with_fillers` 从当前可用 Box 构造的无发电技能补位成员。该池不进入正常技能排序；补位排除 `used` 中的当前占用、Plan 排除和轮换保留成员，使用实际练度，不按上下文ETA复筛。优先保留仍有贸易或制造技能的成员给生产搜索，同层按稳定姓名排序；这是缺员补位 policy，不是联合最优保证。

单班流水线和 ABC 的共享生产池均接入该来源；二班备班先裁剪完整主班占用，再从裁剪后的 Box 建池，不从完整 roster 恢复被排除成员。技能无法建模的干员不会降级成无技能补位。落位后仍由 `resolve_base` 和正式发电结算计算实际效率。确无合法空闲成员时保留真实缺额与质量warning。最终 `--assert-invariants` 的 `power_fallback_admission` 检查实际拥有状态、练度、重复进驻和 Plan 排除。

自动轮换与定时排班的最初中枢ETA名单试算保留，其他后续预算筛选删除。净消耗、control_tag_drain、实际ETA、暖机/心情差效率和菲亚物理ready仍由机制owner结算。自动两态与定时周期的心情不足仅生成质量提示，gate独立核对提示准确性。

## 回收站静态支持范围

`recycle.rs::recycle_skill_efficiency` 只读取 AddFlatEff，不提供通用 phase、condition、selector 解释。2026-11-01、9f55a17 当前两条回收技能均为无条件 Constant/AddFlatEff，适用于现有静态效率范围；历史简化动机未找到。新增动态、条件或其他 action 的回收技能时须重新核对 owner，不默认已建模。`evaluate_recycle` 保留等级容量检查；静态技能限制与删工作心情筛选是不同责任。

## 2026-11-01 新干员会客与办公室技能

机制来源：固定 vault 的「技能-会客室」解锁/提升规则及克莱门莎、埃癸斯、虎狼丸条目，「技能-办公室」德·托莱多条目；解包版本 v078/78.4.0（2026-10-22）。埃癸斯精二会客固定 +10%，线索类型倾向继续 ignored。虎狼丸 Lv.30 会客 +30%。用户 2026-11-01 裁决「线索交流默认开启」，因此虎狼丸、跃跃、响石的交流速度统一按开启结算；这是静态 policy，不模拟交流结束时间，骋风的线索概率仍不计算。

辅助注册表保留原110个机制行并新增391–396的稳定补充行，生成器从上游取得 buff id、slot 和解锁门槛。会客评分与最终结算直接消费该表；无需新增按姓名选位或挂件补偿。候选排序仍是已有 heuristic，不宣称联合最优。

克莱门莎精零 +20%／自身 +1点每小时；精二新解锁合作原则，实际同房人数至少2时额外 +15%／自身 +1点每小时。不同 slot 同时激活，精二双人技能合计 +35% 和额外 +2点每小时，单人仍为 +20%／+1。SupportEffect 的同房人数条件供速度和结果心情明细使用；实际 ETA 由 MoodModel 的 slot 替换、跨slot累加和 min_room_occupancy 条件结算。既有心情条目默认 slot=0，维持原最高精英档替换规则；净耗只在 drain owner 求和，仍接受同房消除自身消耗规则。

德·托莱多办公室初始 +20%、精二替换为 +30%，自身消耗均 -0.25点每小时。辅助注册表负责候选和中枢前联络速度，实例/技能表负责最终办公室解释器，mood_model负责ETA；三个消费者使用相同档位数值。宿舍回复、训练专精和加工副产品不在本次范围。

验收使用固定 assignment 的 layout eval、真实 Box 的 plan --assert-invariants、代表性与high-owned集合；产物保存在 target/codex-runs/new-support-skills-20261101。最终 assignment 验证挂件presence与归属，warning保留真实质量问题，不以“有技能”保证必选。

## 回收站挂件宿主（2026-11-01）

莱茵主动挂件可从回收站取得真实工位，Plan 在现有通用角色编译时预留未占用且与该站既有成员同房兼容的回收技能人的席位；shared_room_facilities允许回收站挂件与原有成员同房，每个角色每房最多一名。公共 vacancy_fill 对回收站按实际技能加成降序、技能人先于普通补位，其他设施顺序不变。回收站实际工作仍按本设施净耗进入周期诊断，休班走普通宿舍。宿主选择和技能优先是 policy，回收效率公式与莱茵人数计数范围未改变；用户裁决和终态证据见莱茵 canonical。
