## 心情链

```text
MoodModel::load_default
 -> operator_net_drain(DrainInputs)
 -> shift_eta_with_instances / workable hours
 -> schedule assignment and warnings
 -> dorm_recovery_rates / dorm_finalizer
 -> next-shift candidate
```

`operator_net_drain` 计算当前设施、skill、control/global input 下的净消耗；`shift_eta_with_instances` 还按实际实例的 `cc.g.sui` 标签，使同中枢令的 `sui_only` 消除仅命中岁干员自身心情技能，非岁同房者及其他来源仍保留。`shift_eta*` 不写 assignment。所有定时 profile 的 `schedule/cycle_mood.rs` 从最终 assignment 消费这六类持续设施净耗，按人累计首尾及跨设施连续预算；只有实际离岗满休边界近似或最终菲亚 pre 动作重置预算，周期边界不恢复。该近似不改变 recovery/finalizer 的宿舍落位，export 不推断恢复。训练活动缺输入明确拒绝，加工站无加工事件只记占位，不伪造每小时成本或恢复。

## 辅助设施

`evaluate_support_room` 提供共享 notice/contribution/mood delta 类型；office、meeting 分别静态求值。`resolve_base` 将 support results 写入 `LayoutContext`；pipeline 在生产岗位后调用 support assignment。office fallback pool 当前为空，不能静默读取全 roster。power 结果经 `apply_power_to_layout` 写入布局，DroneAction 由 schedule/export 消费。

profile ETA、静态 office/meeting 结果和全局无人机速度都可能是 policy 输入，不等于全局最优连续换班。核验使用 `layout eval --explain-json`、`plan --assert-invariants` 和代表性班次 fixture。

## 发电缺员补位

发电填房先按原有技能候选搜索；不足时才消费 `build_power_pool_with_fillers` 从当前可用 Box 构造的无发电技能补位成员。该池不进入正常技能排序；补位排除 `used` 中的当前占用、Plan 排除和轮换保留成员，并使用实际练度与上下文 ETA 检查本班工作时长。优先保留仍有贸易或制造技能的成员给生产搜索，同层按稳定姓名排序；这是缺员补位 policy，不是联合最优保证。

单班流水线和 ABC 的共享生产池均接入该来源；二班备班先裁剪完整主班占用，再从裁剪后的 Box 建池，不从完整 roster 恢复被排除成员。技能无法建模的干员不会降级成无技能补位。落位后仍由 `resolve_base` 和正式发电结算计算实际效率。确无合法空闲成员时保持明确缺员错误，不自动交付部分生产排班。最终 `--assert-invariants` 的 `power_fallback_admission` 检查实际拥有状态、练度、重复进驻和 Plan 排除。
