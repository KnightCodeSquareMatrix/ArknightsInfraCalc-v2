制造接收实际房间和配方，输出 `ManuResult`；没有贸易站的 gold flow、订单机制或 shortcut。L1 阶段解释配方效率、仓库上限、配方条件、tagged/global inject、PeerAbsorb 和心情；L2 由 solver 处理产线、storage 与班次 gap。

```text
ManuRoomInput
 -> ManuContext::from_room
 -> apply_manu_phases
 -> solve_manufacture[_with_shift]
 -> per-line result + storage + mood
```

`search_manufacture_triples` 先按 `full_pool` 过滤，单配方做三人组合；`Lines` 分别搜索金和作战记录，再由 `evaluate_manufacture_lines` 按线数聚合。排班的 `manufacture_fill` 还要满足 Plan anchor、`used`、容量和最新 LayoutContext。

制造候选使用实际 `buff_id` 的 `PeerEffAbsorb(0)` atom 判断同房清零技能：出现自动化或冬时时，只允许其他同类技能持有者与清流同房；没有清零技能时清流可正常与普通效率角色组合。含这类候选的搜索不使用未表达该约束的 Bake 表；固定房间的游戏结算仍由制造 solver 负责。自动化和普通填房两套完整方案的择优由单班 Plan/assignment owner 负责，本模块不反向改 Plan。

预置房可能绕过普通候选搜索；assignment 的制造快照刷新会在结算前用同一个同房准入检查拒绝该组合。`--assert-invariants` 在最终班次 assignment 上检查三级房不超容量与同房准入；合法候选耗尽造成的短员是质量诊断，不是断言失败。

非法配方/人数/等级返回错误；无解不偷换配方。心情 gap 由 rotation policy 处理。跨设施资源异常回 `resolve_base` 和 global chain。

暖机通过 `AddEffRamp` 从每班进驻 `t=0` 连续积分：首小时型保持 initial（20%/15%），之后 `initial + rate×(t−1)` 至 25%；阿罗玛首小时全程 0，之后 `2×(t−1)` 至 20%。有班长使用真实 f64 小时，不 round、不截 24h；None 默认 20h 窗口且心情保持静态；有限非正班取起点静态加成。轻量与完整共用积分 owner：线性路径用真实 elapsed 区间解析平均，含技能面分桶时从原解释器 trace 求真实跨桶时间，按原执行顺序逐消费者细分，最终原始 f64 按时长加权后统一量化。心情区间不重启暖机，仓库按班末求，心情消耗沿用原接口。无暖机保留快速路径；不支持的消费者或超出 f64 分段能力明确报错。在至少两个可表示内点的区间内执行数学分段积分；不足两个内点的微小段保留真实时长，暖机取解析区间平均、其余动作在可用内点或最近中点端点求值。这是 f64 时间分辨率的边界，非线性微小段仍有舍入误差，详见制造状态真源。带班长且池含暖机 atom 的 Bake 查询整体回 live；None 的 20h 行需按新口径重生，不改候选集合。状态：新冻结局部数值验收及指定P1/P2静态闭合完成，最终新语义隔离Bake与统一包已完成：29,783,417行/3,292兼容查询零差异、2,148查询跳过，CLI exit0且但书PASS；152盒147完成、5既有预算失败逐字同基线，新增/移除0，raw same5/changed147。全精二无断言profile11叶/rotation10叶变化、MAA相同；带断言同旧shift2预算失败，均无输出。5949叶差异归因已闭合，不称所有gate全绿。
