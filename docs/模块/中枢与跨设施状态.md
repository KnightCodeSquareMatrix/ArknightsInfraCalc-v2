## 两类快照

Control ledger 记录控制中枢 `ControlEffectKey` 的候选、最大值和来源状态；`GlobalResourcePool`/`GlobalInjectManifest` 保存跨设施 state、转换和生产注入。两者均是当前 assignment 的派生事实，不是游戏机制第二真源。

魔王与阿米娅的两档同房心情恢复由既有 mood domain 单独结算，不伪造全中枢 ledger 数值或全局注入；技能表的空 atom 在此表示明确委托，而非忽略效果。补齐配对 buff 的显式识别也让精二魔王既有的 `期冀之汇` 来源不再随整名干员一起被未知 buff 规则跳过；该 +15% 会客室线索注入仍由原有 control ledger 负责，与两人心情恢复分开。实际房间、来源练度和唯一心情消费链见[心情与辅助设施](心情与辅助设施.md)。本接入不改变 required、顺序选位或未知 buff 的 fail-closed 准入。

## resolve 顺序

```text
BaseAssignment
 -> WorkforceIndex
 -> control solve + ledger/trace
 -> power / office / meeting facts
 -> collect_global_atoms
 -> orchestrate_global_atoms (StateWrite)
 -> global conversions/inject manifest
 -> ResolvedTrade/Manu/Power/Support rooms
```

`resolve_base` 在布局填充和班次阶段可重复调用；每次只读取当前 assignment，不复用未来分支快照。`scope=Global` atom 由 collector 收集并按 phase 排序，当前 interpreter 实际执行 `StateWrite`；`GlobalInject` 仍由 control interpreter 管理。per-room interpreter 不应再次执行 global atom。

旧布局可以携带预置魔物料理，但结算初始池会忽略该字段；该资源只由当前 assignment 中的森西宿舍技能按所在宿舍的 `level` 写入，终态 Rust gate 逐班核对全局值与实际产料 atom 的结算值。旧 `dorm_ambience_level` 可解析但不参与产料，`dorm_beds` 只计算床位。其他全局资源的场景初值不受此限制。

## producer 与失败

producer 必须通过 admission、source 实际在场、target/relation 条件，才进入 manifest；标签存在不能替代 assignment presence。未知 key/unit、缺 source/conversion 或不兼容输入应 delegated/fail-closed，不能用旧快照继续求解。

核验：`layout eval --explain-json` 查看 resolve trace、global pool、manifest；`plan --assert-invariants` 查看最终 assignment；动态 producer 变更需代表性/high-owned fixture。
