本模块把单班 BaseAssignment 组合成固定时长、多状态的轮换报告。游戏机制正文回到隔壁知识库，本项目只记录 capability、runtime dependency 和失败边界。

## 责任边界

负责 profile 解析、班次结构、H1/H2/γ 或专用状态、实际 shift_bind、办公室/会客室补位、菲亚/无人机/dorm_rest、最终效率和 invariant。不负责 Mower、游戏内置自动轮换、机制倍率或全局最优。

## 数据结构

TimedRotationProfile 是七项闭集：abc_12_6_6、abc_12_12_12、main_backup_12_12、main_backup_24_24、fiammetta_witch_12_12、fiammetta_8_8_4_4、abyssal_7_5_7_5。新增 profile 必须同时更新 cli_name、plan_times、分派、终验和 export。

TeamRotationReport 保存 profile、peak_plan、assignment_plans、runtime_shift_binds、peak_mood_eta、teams、shifts、daily、warnings、elapsed。TeamShiftResult 保存 index、plan_index、duration_hours、active_teams、resting_team、assignment、可选动作、transition、三类效率。assignment 是岗位事实唯一 owner。

## 阶段

1. owner solve：layout assign 产生 peak 或 profile owner。
2. split/disjoint：ABC 切 half，二班建立互斥，深海枚举制造人数。
3. bind alignment：shift_binds_from_plan 取真实 dependency，align_shift_binds_in_halves 对齐 half。
4. roster fill：先冻结 `schedule::control_rotation::ControlRotationClosure` 和每班 `ControlShiftAdmission`，再做中枢、办公室、会客室补位；绑定成员不得拆开。
5. special actions：菲亚、无人机、深海 DormRestPlan。
6. finalize：效率、宿舍、warning、profile/绑定/连续工作检查。
7. report：供 CLI、profile、MAA 和 serve 消费。

## 状态模型

ABC：H1→α、H2→β、γ 替补；S1=α+β、S2=β+γ、S3=γ+α，γ/α/β 分别休 S1/S2/S3。12/12/12 复用队伍关系，总周期 36h，daily 按总小时归一。

轮换中枢的候选来源和 work scope 在班次循环前冻结；普通候选只在所属活跃队班次进入 admission，shared 成员保持 required。候选组的 registry slot 来源和适用班次从 Plan/peak/bind 事实解析，最终 Rust gate 从 `shifts[].assignment` 反查容量、唯一性、来源、scope 和 `min_count`。办公室、会客室尚未落位的候选不提前占用；中枢条件读取 `resolve_control_input_layout` 生成的中枢结算前快照。

`schedule_abc_rotation` 只在 `schedule_abc_rotation_once` 明确报告 ETA 失败时重试完整半区的另一朝向；交换发生在自然切分及 reserve 检查之后、γ 与全部队伍构造之前。每次尝试重新建立 Plan、γ、中枢、办公室/会客室和心情状态，不沿用失败尝试的成员或剩余心情。两朝向均失败后才消费可选中枢角色来源进行完整 Plan 重编，其他错误不触发降级。每朝向中枢候选保留 64 个拒绝名单分支上限，不能声称完整搜索或全局最优。

会客室普通候选按实际双人房间求值。精二忍冬可用时，铃兰只作为忍冬搭档组合参与比较；组合胜出才同班落位，未胜出不强制占用。没有当班可用的精二忍冬时，铃兰不作为普通会客室候选；已有 Plan required 落位不受该策略过滤。

main_backup_12_12 是两份完整 assignment 的 owner policy；主班工作成员进入替班禁用集合。main_backup_24_24 复用同一完整状态互斥策略，但两个状态各为 24h，周期为 48h；长班生产使用 24h ETA 口径，带 12h 后心情衰减的制造成员不进入该 profile。fiammetta_witch_12_12 仅允许两个 owner 共享巫恋/龙舌兰。fiammetta_8_8_4_4 的 FiammettaOnly 只重放目标房。abyssal_7_5_7_5 的 5h 状态固定 DormRestPlan，恢复不足前一段 7h 消耗则失败。

## 绑定、宿舍和办公室

shift_bind 只从 AssignmentPlan.resolved_producer_dependencies 和已确认 bind 生成；没有实际贡献的 provider 不绑定。ABC 可选中枢角色如不能覆盖绑定班次，只能回到 Plan 按角色精确重编，不在轮换中删已解析成员。dorm_finalizer 以 previous_work - current_work 得到普通休息，保护已有住员和特殊组后按容量写入，床位不够返回 warning。ABC 普通办公室补位排除已经预留给生产、中枢或轮换会客等角色的成员，绑定办公室成员仍优先落位；办公室/会客室候选按实际组合和班初心情选位，绑定成员 ETA 不足时状态不可行。两个 ABC profile 的 S3 候选均加入下一周期 S1 的消费；`12/12/12` 休班回满近似不豁免首尾连续工作，`12/6/6` 更严格的逐班准入不预支宿舍恢复。

## 失败传播与验证

profile 前提、容量、绑定、跨班 ETA、周期连续心情预算和特殊宿舍失败返回 Error；普通办公室/会客室/宿舍缺员及整周期无休班返回 warnings。所有 profile 在最终 assignment 上经 `cycle_mood::validate_cycle_mood` 检查六类持续消耗设施的首尾连续预算，同人换设施不清零；`--assert-invariants` 再从终态重算。该门禁证明现有 MoodModel 与满休边界近似下的连续预算，不证明实际宿舍恢复、未建模活动、全局最优或 Mower 行为。

## finalize_timed_rotation 的实际顺序

finalize_timed_rotation 不是单纯的格式化：

1. 对每个 shift 执行菲亚宿舍前置检查；菲亚在目标房外、宿舍无床、目标房消失或恢复组超容量会返回带 rotation 的错误。
2. 清除旧 production efficiencies，普通班次调用 evaluate_base_assignment_efficiencies；FiammettaOnly 调用 score_fiammetta_continuation，只计算目标房延续。
3. 用报告中全部 shift 的实际总时长作分母，写入 weighted_trade、weighted_manufacture、weighted_power；调用 annotate_assignment 生成当前事实 notes。
4. 累加 daily 三类周期平均效率和 average_cycle_production；生产同样按全部 shift 的实际 duration_hours 加权为 24h 平均产物。
5. 生成办公室/会客室 shortfall warnings；再调用 dorm_finalizer::finalize_dorms 写入普通休息成员。宿舍候选不足只产生 warning，并由 MAA export 读取该 warning 设置 autofill。
6. 在最终 assignment 上调用 rotation_cycle_rest_warnings，统计所有非宿舍岗位和训练副手；只豁免实际自动化 Lancet-2 与本周期最终菲亚动作目标。按姓名及逐班岗位稳定追加 `rotation_cycle_rest:` 诊断，不改排、不影响候选比较或 MAA 输出。
7. 先核对最终菲亚动作策略，再调用统一周期心情 owner；所有班次起点环绕一轮并另查初始心情前缀。超预算和整轮正消耗无恢复返回 `rotation_cycle_mood failed:`，独立训练副手（`training_assist`）返回 `rotation_cycle_mood_unsupported_activity`；训练室内无训练任务的占位无小时消耗且不是休息边界，不把这些错误当作正常结果。
8. 调用 assert_final_rotation_invariants，重算统一周期预算与 `rotation_cycle_rest_diagnostics`。整周期无休班的诊断与心情预算是独立规则：零消耗可带休班 warning 通过，正消耗且无恢复则硬失败。上层只可从错误对象取得 partial rotation 供诊断。

## 终态 invariant 的范围

当前 Rust gate 检查：

- skill_table 中 runtime skill refs 都能由 instances 解析；
- 魔物料理每班只来自该班最终 assignment 的全局产料 atom，不接受预置值；
- 每班办公室人员不与生产/固定岗位重复，且当前班 ETA 足够；
- notes 可由最终 assignment 重算；
- profile 的 control/production anchor、房间容量和 hard claim 仍存在；
- 24/24 的两个状态各为 24h、分别引用主/备 Plan，实际非宿舍成员属于当班队伍且不跨两班工作，绑定以及六类持续工作岗位的 24h 预算满足；训练室/训练副手没有活动预算时由全模式门禁明确拒绝。加工站仅占位不耗小时心情，也不构成回满边界。宿舍 warning 不证明未落位成员已恢复；
- 二班每个普通工作成员只属于一个 owner；龙巫 profile 只允许巫恋/龙舌兰跨 owner；
- 每个 runtime bind 的成员属于一个完整 team，并按同上同下、上 N 休 M 出现；
- 深海首班存在 control producer 和正好四名 tag consumer，每个 5h 状态有三个不同的 dorm_rest 成员且不在工作房；
- `rotation_cycle_mood` 统一检查中枢、制造、贸易、发电、办公室、会客室的实际连续预算，覆盖首尾、跨设施、初始心情、整轮无恢复正消耗；只消费最终菲亚 pre 动作。离岗边界沿用满休预算近似，训练未知活动明确拒绝，加工事件尚未输入。
- ABC 休息队成员不占办公室；中枢、办公室、会客室还按既有逐班状态重放，`12/6/6` 保留不预支宿舍恢复的更严格检查，不能替代全模式周期预算。制造心情落差技能的 12h 连续制造限制是独立机制约束，继续保留。
- 三类效率的逐班权重与 daily 汇总均按完整轮换周期时长归一；36h profile 不按 24h 分母累加 36h 的岗位效率。
- 每班三级制造房必须满员；从该班最终 assignment 的实际技能档位解析清零 atom 后，同房成员只允许其他清零技能持有者与清流。轮换不能借普通填房把已选自动化房改成混合普通效率组。
- 每班最终贸易房均不允许黑键与巫恋同站，包括 Rosemary 未激活和二发电；巫恋与龙舌兰合法同站不受此禁配影响。
- 赤金链终态检查从各班实际 assignment 独立核对杜林在岗人数、任意贸易站来源与全局虚拟线、双人/三人同房顺序、鸿雪/图耶按技能顺序读取的效率及报告中的贸易房技能效率；成套工作班要求四名杜林实际进驻，选中双房/三房拆站方案时还检查实际站位并要求至少一班完整上岗。
- `rotation_cycle_rest_diagnostics` 从全部班次最终非宿舍 assignment 与 `training_assist` 重算整周期工作人员，核对具名豁免和报告 warning；违规保留正常结果。Lancet-2 每个工作班次必须由当班 owning Plan 的 `automation_group` 入选成员及发电锚点证明实际发电/加工站去向，且周期中至少一班在对应发电岗位；菲亚只读本周期最终 `fiammetta.target`。

该 gate 证明的是最终状态满足代码已编码的 invariant；[每周期休班底线](../定时换班.md#每周期休班底线目标规则)采用诊断口径，gate 证明诊断准确而非人人已经休班。不能用部分岗位 ETA、team 休班或房间成员去重代替实际出勤统计，也不能证明未编码的机制正文、跨周期宿舍最优、Mower 行为或全局搜索最优。
