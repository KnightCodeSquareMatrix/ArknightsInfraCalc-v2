本模块把单班 BaseAssignment 组合成轮换报告。当前提交包含普通二/三班 topology-specific 构造、按序输入时长及共享完成/终态 owner 的 WIP；generic 与源石 pair 仍为 `in-progress`，尚未完成 fresh release 验收。菲亚 8/8/4/4 与深海 7/5/7/5 仍为专用四班路径。游戏机制正文回到隔壁知识库，本项目只记录 capability、runtime dependency 和失败边界。

**范围边界：**named profile 保持原兼容含义；普通二/三班泛型时长、Worker v7 和泡泡/火神 RoomId claim 均为共享工作区 WIP，源码已提交但尚未完成 fresh release 验收；对应用户裁决见 ADR 0011。泡泡/火神计划只在排班层以显式 RoomId claim 预占，全范围固定归 α；四班专用路径不由此扩展。

## 责任边界

负责 profile 解析、班次结构、H1/H2/γ 或专用状态、实际 shift_bind、办公室/会客室补位、菲亚/无人机/dorm_rest、最终效率和 invariant。不负责 Mower、游戏内置自动轮换、机制倍率或全局最优。

`rotation_types::validate_rotation_duration_hours` 是时长数值安全的唯一 helper：generic 请求在搜索前消费，finalizer 与最终 gate 从实际 shifts 复查；不拥有 24/36/48h 组合政策。数值边界见[定时换班](../定时换班.md)，错误表达见[接口错误与诊断](../接口/错误与诊断.md)。`RuntimeShiftBind::on_shifts` 读取 Plan 声明，不由旧 ABC 固定时序推导；本次数值修复只更正相关旧注释，不改变 bind。

## 数据结构

TimedRotationProfile 保留具名兼容 preset：abc_12_6_6、abc_12_12_12、main_backup_12_12、main_backup_24_24、fiammetta_8_8_4_4、abyssal_7_5_7_5；普通二/三班泛型 timing 另由 TimedRotationRequest 的 topology + shift_hours 表达，不按每种时长扩展 profile 枚举，但保留 `GenericMainBackup` 与 `GenericAbc` 两个 topology identity。独立龙巫二班已删除；旧 CLI/Worker wire 明确返回不支持，不降级到普通主备。新增 named preset 才需同时更新 cli_name、plan_times、分派、终验和 export。

TeamRotationReport 保存 profile、peak_plan、assignment_plans、runtime_shift_binds、peak_mood_eta、teams、shifts、daily、warnings、elapsed。TeamShiftResult 保存 index、plan_index、duration_hours、active_teams、resting_team、assignment、可选动作、transition、三类效率。assignment 是岗位事实唯一 owner。

## 阶段

1. owner solve：layout assign 产生 peak 或 profile owner。ABC 在 peak 前解析泡泡/火神资格、首个合法三级源石房和可选 room anchors；失败降级与静默不适用分别处理。
2. split/disjoint：ABC 切 half，二班建立互斥，深海枚举制造人数。
3. bind alignment：shift_binds_from_plan 取真实 dependency，align_shift_binds_in_halves 对齐 half。
4. roster fill：先冻结 `schedule::control_rotation::ControlRotationClosure` 和每班 `ControlShiftAdmission`，再做中枢、办公室、会客室的技能选人；绑定成员不得拆开。`room_admission.rs` 提供候选试算、ETA 和 mood budget helper。
5. special actions：菲亚、无人机、深海 DormRestPlan。
6. completion/finalize：保护专用宿舍，向七类普通工作设施统一补空座；随后普通宿舍最终落位、ready 动作筛除、最终效率、warning、profile/绑定/连续工作检查。
7. report：供 CLI、profile、MAA 和 serve 消费。

### 普通房间 admission 的当前拆分

`room_admission.rs` 的责任边界是纯公共输入输出：把候选追加到临时 `BaseAssignment`，通过现有 ETA owner 读取候选工作时长，并在需要时检查当前班次及下一班次的 mood budget。它不读取 roster 来排序、不决定候选所属策略、不绕过 Plan，也不写最终 assignment。

设施技能选人和专用绑定仍由对应 owner 决定；办公室排序共用 `office::rank_candidates`。普通空座的提交只有 `layout/vacancy_fill.rs::fill_workplace_vacancies` 一个 owner：消费完整 assignment 和调用方已裁剪候选，先试无本设施技能者，再试现有设施池承认的技能余员，不擦除未知 buff。贸易禁配、制造清零同房限制、中枢冻结准入和 Plan 禁配继续生效。训练室、加工站、宿舍不参加普通补位。

当前 HEAD 的 named ordinary paths 在完整周期构造后由既有 completion 入口调用该入口；共享工作区 WIP 另将 generic two/three topology 接入 `complete_timed_rotation`。旧龙巫 wire 在分派前拒绝。候选只可进入其唯一所属的活跃 Team，新成员在合法有休班的队伍中归属。Plan anchor/reserve、bind、专用恢复和菲亚不被普通补位拆用。`FiammettaOnly` 不独立补人：前一普通班新增岗位同步到连续的续班，按合计时长核算心情。回收站保留技能分队，但原 finalizer 中的独立普通 fallback 已删除。

独立单班的 `assign_shift_with_plan` 在技能分配和办公室选择后消费同一普通补位入口，再刷新贸易、制造快照。内部供 peak/main/backup 使用的 skip/preclaimed 流水线不提前补普通人，避免抢走后续队伍候选。贸易技能人数不足不再整份丢弃 Peak 候选；合法空池/部分技能命中、电站剩余人手耗尽和制造 anchor 缺普通 filler 均保留已形成的岗位，交给完成层继续补位。required、输入和资源错误不是人数不足，不被吞掉。

### 结算与策略的边界

`fiammetta_events.rs` 是动作试放和 ready 时间线的共同 owner：菲亚预算跨目标传递，目标按实际 ETA 分别累计消耗，目标休班不回复。候选试放只接受不会破坏整条既有事件时间线的动作；普通最终化与 Rust gate 从最终 assignment 再次重放。它不决定目标优先级、可用 slot、绑定或续班评分。

`rotation_scoring.rs::rescore_standard_shifts` 只承载普通完整时间窗的公共结算：清除贸易/制造/发电缓存，调用 `evaluate_base_assignment_efficiencies`，再按调用者原有周期时长更新三类 weighted 值。普通菲亚回岗、巫恋组动作后的相同结算循环及保留的 legacy 路径已复用它；该函数不选择候选、不写菲亚目标、不处理宿舍、不生成 warnings，也不替代 finalizer。`score_fiammetta_continuation` 仍是专用续班口径：完整编制分别结算 8h 与 16h，目标房保留前段值，其他房间使用续段差值，不能当成普通 8h 评分合并。

## 状态模型

ABC：H1→α、H2→β、γ 替补；S1=α+β、S2=β+γ、S3=γ+α，γ/α/β 分别休 S1/S2/S3。泛型时长按最长班映射 α；并列最长时休班相位落在较短班，尽量让 α 覆盖所有可覆盖的并列最长班；完全等长保持 named 旧相位。输入时长驱动 daily 和周期结算。泡泡/火神预占房作为 `rotation_originium_pair` Plan anchors 随完整生产组件归 α；每个 α 工作状态必须同房工作，休息班不得留在制造房。第三席仍由普通制造候选决定，短员按普通 warning 处理。

轮换中枢的候选来源和 work scope 在班次循环前冻结；普通候选只在所属活跃队班次进入 admission，shared 成员保持 required。候选组的 registry slot 来源和适用班次从 Plan/peak/bind 事实解析，最终 Rust gate 从 `shifts[].assignment` 反查容量、唯一性、来源、scope 和 `min_count`。办公室、会客室尚未落位的候选不提前占用；中枢条件读取 `resolve_control_input_layout` 生成的中枢结算前快照。

`schedule_abc_rotation` 只在 `schedule_abc_rotation_once` 明确报告 ETA 失败时重试完整半区的另一朝向；交换发生在自然切分及 reserve 检查之后、γ 与全部队伍构造之前。每次尝试重新建立 Plan、γ、中枢、办公室/会客室和心情状态，不沿用失败尝试的成员或剩余心情。两朝向均失败后才消费可选中枢角色来源进行完整 Plan 重编，其他错误不触发降级。每朝向中枢候选保留 64 个拒绝名单分支上限，不能声称完整搜索或全局最优。

`OriginiumPairContext` 冻结预占 RoomId，后续只用 RoomId 身份保护，不再靠成员姓名重新猜测。夜烟 shadow 对冻结房直接跳过生产清空；暖机只在非冻结房之间交换；深海 S2 的可变制造列表排除冻结房；reserve 不移动含冻结房的组件；菲亚制造目标重填跳过冻结房。切半组件保持该房整体移动，`reversed_halves` 只交换两个完整半区。普通 vacancy fill 仍可补第三席，不整房跳过。

会客室普通候选按实际双人房间求值。精二忍冬可用时，铃兰只作为忍冬搭档组合参与比较；组合胜出才同班落位，未胜出不强制占用。没有当班可用的精二忍冬时，铃兰不作为普通会客室候选；已有 Plan required 落位不受该策略过滤。

main_backup_12_12 与 generic main_backup 是两份完整 assignment 的 owner policy；主班工作成员进入替班禁用集合。main_backup_24_24 复用同一完整状态互斥策略，但两个状态各为 24h，周期为 48h；共享工作区 WIP 才移除静态姓名过滤，named 与 generic 长班由实际 ETA/心情候选准入决定，泛型班使用实际工作时长；当前 HEAD 的 v6 行为以已提交实现为准。独立龙巫二班已从产品 profile 删除，普通巫恋/龙舌兰同站组合仍由贸易搜索自然评估。`fiammetta_8_8_4_4` 的 FiammettaOnly 使用上述专用续班评分；无动作时保留普通 8/8/4/4。`abyssal_7_5_7_5` 的专用组不可用时以普通主备 owner 交替保留 7/5/7/5；恢复组找不到时不写未经证明的 DormRestPlan，并警告，不宣称深海专用组成立。

## 绑定、宿舍和办公室

shift_bind 只从 AssignmentPlan.resolved_producer_dependencies 和已确认 bind 生成；没有实际贡献的 provider 不绑定。终态 `shift_bind.rs::validate_final_bind_cycle` 从各 Plan 重建闭包，并保留 runtime-only bind；按来源 Plan 区分工作成员、显式宿舍支持和单向依赖支持者，从最终工作岗位重算出勤。宿舍 presence 不算工作，训练/加工普通占位仍是工作岗位；显式 `rest_facility` 只区别该绑定的工作角色与休息去向，不改周期休班统计。exact 组的宿舍支持在工作核心在岗时须实际进入宿舍，不固定宿舍房号；单向支持按 receiver 实际工作时的真实 presence 单独验证，不能用全 roster 或训练副手代替。当前 Plan 把部分单向支持者并入 exact 闭包的生成偏差只在消费视图区分，尚未修复 Plan owner，见活动计划 §6.6。

ABC 可选中枢角色如不能覆盖绑定班次，只能回到 Plan 按角色精确重编，不在轮换中删已解析成员。dorm_finalizer 以 previous_work - current_work 得到普通休息，保护已有住员和特殊组后按容量写入，床位不够返回 warning。ABC 普通办公室补位排除已经预留给生产、中枢或轮换会客等角色的成员，绑定办公室成员仍优先落位；办公室/会客室候选按实际组合和班初心情选位，绑定成员 ETA 不足时状态不可行。两个 ABC profile 的 S3 候选均加入下一周期 S1 的消费；`12/12/12` 休班回满近似不豁免首尾连续工作，`12/6/6` 更严格的逐班准入不预支宿舍恢复。

## 失败传播与验证

质量不足不拒绝正常产品输出。普通制造容量 fallback 保留当前池中合法的 0..N 人；全部普通工作设施（不含训练/加工/宿舍）从最终 assignment 生成缺额 warnings。专用能力不足按原 profile 时序尽力输出，profile 结构与制造心情落差检查追加诊断。所有 profile 仍经 `cycle_mood::validate_cycle_mood` 检查首尾连续预算，同人换设施不清零；该检查在 ABC 候选阶段继续筛选，已有完整 partial rotation 时外层降级已识别的预算拒绝。输入、资源、未知计算故障与显式 `--assert-invariants` 的失败不是质量 warning。具体传播顺序唯一见 [定时轮换调用链](../调用链/定时轮换.md#错误与输出)。该门禁不证明真实宿舍恢复、未建模活动、全局最优或 Mower 行为。

## finalize_timed_rotation 的实际顺序

finalize_timed_rotation 不是单纯的格式化：

1. 前置的 `complete_timed_rotation` 对每个 shift 试算菲亚/专用宿舍保护；结构或容量失败保留该班原 assignment 并警告，再消费已裁剪的完整周期候选统一补普通工作空座。不在 finalizer 重新读全 roster。
2. finalizer 试算普通宿舍落位，成功才提交，失败保留原状态并诊断；在最终 assignment 上筛除不 ready 的菲亚动作，无动作的 FiammettaOnly 改为普通班次及普通无人机动作。之后清除旧 production efficiencies，普通班次调用 evaluate_base_assignment_efficiencies；保留动作的 FiammettaOnly 使用专用续班评分。
3. 用报告中全部 shift 的实际总时长作分母，写入 weighted_trade、weighted_manufacture、weighted_power；调用 annotate_assignment 生成当前事实 notes。
4. 累加 daily 三类周期平均效率和 average_cycle_production；生产同样按全部 shift 的实际 duration_hours 加权为 24h 平均产物。
5. 从最终 assignment 生成普通工作设施 shortfall warnings，保留构造阶段的质量诊断和普通宿舍 warning；不再用重建 warning 列表抹掉上游降级原因。宿舍候选不足由 MAA export 读取 warning 设置 autofill。
6. 在最终 assignment 上调用 rotation_cycle_rest_warnings，统计所有非宿舍岗位和训练副手；只豁免实际自动化 Lancet-2 与本周期最终菲亚动作目标。按姓名及逐班岗位稳定追加 `rotation_cycle_rest:` 诊断，不改排、不影响候选比较或 MAA 输出。
7. 从最终 assignment 生成结构、制造连续工作、菲亚动作策略和连续目标诊断，不保留补位前已经失效的缺员判断。warning 完整性只由公共 gate 按缺员、宿舍和休班三类重建，专用 profile 不再把真实宿舍 warning 当成缺员列表错误。ready 已在评分前沿终态时间线筛除。统一周期心情 owner 覆盖所有环形起点和初始心情前缀；超预算返回带完整报告的 `rotation_cycle_mood failed:` 供候选比较和最外层恢复，独立训练副手（`training_assist`）仍为未支持活动错误；无训练任务占位无小时消耗且不是休息边界。
8. 调用公共终态 gate，重算统一周期预算与 `rotation_cycle_rest_diagnostics`；gate 错误在此降级为 `rotation_final_invariant:` warning。第 7 步的预算类错误若携带完整 partial rotation，外层 `schedule_timed_rotation_request` 也可降级；不支持活动或没有完整报告的错误不走这条恢复。显式验收仍返回失败，不因正常排班输出了 warning 就视为不变量通过。

## 终态 invariant 的范围

当前 Rust gate 检查：

- `rotation_duration_input` 第一项核对最终 `shifts[].duration_hours` 的数值安全；非法数值在评分/权重重放前失败。这不证明任何合法时长都能满足心情，也不扩展时长组合业务限制。

- `ordinary_fallback_admission` 核对七类普通工作岗位实际持有、练度、Plan 排除和唯一性；`ordinary_fallback_complete` 对最终报告克隆重放同一声明的补位 policy，要求不再新增合法岗位。这证明该 policy 的完成稳定性，不是所有可能分队/换位下的全局满编或最优性证明；原容量、ETA、ready 等实体断言独立保留。

- skill_table 中 runtime skill refs 都能由 instances 解析；
- 魔物料理每班只来自该班最终 assignment 的全局产料 atom，不接受预置值；
- 每班办公室人员不与生产/固定岗位重复，且当前班 ETA 足够；
- notes 可由最终 assignment 重算；
- profile 的 control/production anchor、房间容量和 hard claim 仍存在；
- 24/24 的两个状态各为 24h、分别引用主/备 Plan，实际非宿舍成员属于当班队伍且不跨两班工作，绑定以及六类持续工作岗位的 24h 预算满足；训练室/训练副手没有活动预算时由全模式门禁明确拒绝。加工站仅占位不耗小时心情，也不构成回满边界。宿舍 warning 不证明未落位成员已恢复；
- 二班每个普通工作成员只属于一个 owner；已删除的龙巫专用跨 owner 例外不再属于当前产品 profile；
- 普通最终化与显式公共 gate 共用 `rotation_bind` 终态检查：从 Plan 重建绑定并合入 runtime-only bind，宿舍不计工作，单向支持另查 presence；ABC 核对非零 on/off 字段，其他 profile 沿既有团队拓扑及既有专用例外检查。违规在普通报告留 warning，显式验收返回错误；不读取 warning 判断是否合法。候选阶段旧绑定筛选、legacy `verify_shift_binds` 和 24/24 附加校验尚未统一，支持设施合法性与 Plan 关系生成也不由该 gate 完整证明；
- 深海首班存在 control producer 和正好四名 tag consumer，每个 5h 状态有三个不同的 dorm_rest 成员且不在工作房；
