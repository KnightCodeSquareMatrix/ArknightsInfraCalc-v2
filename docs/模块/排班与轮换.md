本模块把单班 BaseAssignment 组合成轮换报告。当前实现包含普通二/三班按输入时长构造和共享完成/只读终检，generic 与源石 pair 已接入同一路径。菲亚 8/8/4/4 与深海 7/5/7/5 仍为专用四班路径。游戏机制正文回到隔壁知识库，本项目只记录 capability、runtime dependency 和失败边界。

**范围边界：**named profile 保持原兼容含义；普通二/三班泛型时长、Worker v7 和泡泡/火神 RoomId claim 已在 main 统一；本轮验收覆盖真实 CLI 和持久 Box，不包含网站部署；对应用户裁决见 ADR 0011。泡泡/火神计划只在排班层以显式 RoomId claim 预占，全范围固定归 α；四班专用路径不由此扩展。

## 责任边界

负责 profile 解析、班次结构、H1/H2/γ 或专用状态、实际 shift_bind、办公室/会客室补位、菲亚/无人机/dorm_rest、最终效率和 invariant。不负责 Mower、游戏内置自动轮换、机制倍率或全局最优。

`rotation_types::validate_rotation_duration_hours` 是时长数值安全的唯一 helper：generic 请求在搜索前消费，finalizer 与最终 gate 从实际 shifts 复查；不拥有 24/36/48h 组合政策。数值边界见[定时换班](../定时换班.md)，错误表达见[接口错误与诊断](../接口/错误与诊断.md)。`RuntimeShiftBind::on_shifts` 读取 Plan 声明，不由旧 ABC 固定时序推导；本次数值修复只更正相关旧注释，不改变 bind。

## 数据结构

TimedRotationProfile 保留具名兼容 preset：abc_12_6_6、abc_12_12_12、main_backup_12_12、main_backup_24_24、fiammetta_8_8_4_4、abyssal_7_5_7_5；普通二/三班泛型 timing 另由 TimedRotationRequest 的 topology + shift_hours 表达，不按每种时长扩展 profile 枚举，但保留 `GenericMainBackup` 与 `GenericAbc` 两个 topology identity。独立龙巫二班已删除；旧 CLI/Worker wire 明确返回不支持，不降级到普通主备。新增 named preset 才需同时更新 cli_name、plan_times、分派、终验和 export。

TeamRotationReport 保存 profile、peak_plan、assignment_plans、runtime_shift_binds、peak_mood_eta、teams、shifts、daily、warnings、elapsed。TeamShiftResult 保存 index、plan_index、duration_hours、active_teams、resting_team、assignment、可选动作、transition、三类效率。assignment 是岗位事实唯一 owner。

## 阶段

1. owner solve：layout assign 产生 peak 或 profile owner。ABC 在 peak 前解析泡泡/火神资格、首个合法三级源石房和可选 room anchors；失败降级与静默不适用分别处理。
2. split/disjoint：ABC 切 half，二班建立互斥，深海枚举制造人数。
3. bind alignment：shift_binds_from_plan 取真实 dependency，align_shift_binds_in_halves 对齐 half。
4. roster fill：ABC 在冻结 `schedule::control_rotation::ControlRotationClosure` 前，当前实现先按初始心情、满员中枢固定减免和候选自身已建模技能筛一次自由 roster；之后每班 `ControlShiftAdmission` 管 scope、required、`min_count`、容量和身份，再做中枢、办公室、会客室的技能选人。绑定成员不得拆开。其他岗位搜索与补位不再执行心情准入；完整周期心情问题统一留 warning，不触发重建。
5. special actions：菲亚、无人机、深海 DormRestPlan。
6. completion/finalize：保护专用宿舍，向七类普通工作设施统一补空座；确认无依赖动作，或验证专用候选的动作承诺；完成普通宿舍后定稿，结算和只读终检不再写岗位或动作。
7. report：供 CLI、profile、MAA 和 serve 消费。

### 普通房间 admission 的当前拆分

2026-10-31 用户最新裁决：只保留最初 ETA roster 试算；后续搜索、组合、补位、逐班和动作候选不再按工作心情预算筛选或拒绝。心情净消耗、暖机与心情差积分仍按真实状态结算；终态心情不足保留质量 warning。显式 gate 核对该 warning 与实际终态是否一致，结构、Plan、绑定和动作事实仍独立验收。本次删除属于 policy，不是 safe reduction，不证明全局最优。

设施技能选人和专用绑定仍由对应 owner 决定；办公室排序共用 `office::rank_candidates`，普通试放/提交共用 `office::fill_vacancies`；三班先安排活跃绑定成员，再提交普通候选，不读取班初心情或首尾预算做准入。全设施普通余员补位由 `layout/vacancy_fill.rs::fill_workplace_vacancies` 提交：消费完整 assignment 和调用方已裁剪候选；回收站按实际技能加成降序先试技能人，再试普通余员，其他设施先试无本设施技能者，再试现有设施池承认的技能余员，不擦除未知 buff。贸易禁配、制造清零同房限制、中枢冻结准入和 Plan 禁配继续生效。训练室、加工站、宿舍不参加普通补位。

当前 HEAD 的 named ordinary paths 在完整周期构造后由既有 completion 入口调用该入口；generic two/three topology 同样接入 `complete_timed_rotation`。旧龙巫 wire 在分派前拒绝。候选只可进入其唯一所属的活跃 Team，新成员在合法有休班的队伍中归属。Plan anchor/reserve、bind、专用恢复和菲亚不被普通补位拆用。`FiammettaOnly` 不独立补人：前一普通班新增岗位同步到连续的续班，按合计时长核算心情。回收站保留技能分队，但原 finalizer 中的独立普通 fallback 已删除。

独立单班的 `assign_shift_with_plan` 在技能分配和办公室选择后消费同一普通补位入口，再刷新贸易、制造快照。内部供 peak/main/backup 使用的 skip/preclaimed 流水线不提前补普通人，避免抢走后续队伍候选。贸易技能人数不足不再整份丢弃 Peak 候选；合法空池/部分技能命中、电站剩余人手耗尽和制造 anchor 缺普通 filler 均保留已形成的岗位，交给完成层继续补位。required 矛盾保留准确构造诊断并由终检核对；输入和资源错误继续传播。

### 结算与策略的边界

`fiammetta_events.rs` 是动作试放和 ready 时间线的共同 owner：菲亚预算跨目标传递，目标按实际 ETA 分别累计消耗，目标休班不回复。named ABC 与 generic ABC 都由 N/A/B 薄适配层各自完整求解后比较；generic ABC 按实际班时和 α 相位恢复输入班序，动作槽限于实际超过 12h 的班。候选试放只接受不会破坏整条既有事件时间线的动作；普通最终化与 Rust gate 从最终 assignment 再次重放。request-aware gate 另外核对 `fiammetta_enable=false` 时无最终动作。模块不决定目标优先级、可用 slot、绑定或续班评分。

最终普通窗口结算由 `finalize_timed_rotation` 统一读取已完成的 assignment 和实际时长，使用 `base_rotation::evaluate_base_assignment_efficiencies`；无消费者的中间重评分 helper 已删除。普通 ABC 构造不再生成报告初值分数和 daily。真实 S2 深海候选比较试算仍保留。`score_fiammetta_continuation` 保留 8h/16h 差分的专用续班口径，不与普通整班评分合并。

## 状态模型

ABC：H1→α、H2→β、γ 替补；S1=α+β、S2=β+γ、S3=γ+α，γ/α/β 分别休 S1/S2/S3。泛型时长按最长班映射 α；并列最长时休班相位落在较短班，尽量让 α 覆盖所有可覆盖的并列最长班；完全等长保持 named 旧相位。输入时长驱动 daily 和周期结算。泡泡/火神预占房作为 `rotation_originium_pair` Plan anchors 随完整生产组件归 α；每个 α 工作状态必须同房工作，休息班不得留在制造房。第三席仍由普通制造候选决定，短员按普通 warning 处理。

轮换中枢的候选来源和 work scope 在班次循环前冻结；ABC 普通候选在冻结前按固定单人预算筛一次，之后只在所属活跃队班次进入 admission，shared 成员保持 required。候选组的 registry slot 来源和适用班次从 Plan/peak/bind 事实解析，最终 Rust gate 从 `shifts[].assignment` 反查容量、唯一性、来源、scope 和 `min_count`。办公室、会客室尚未落位的候选不提前占用；中枢条件读取 `resolve_control_input_layout` 生成的中枢结算前快照。

当前 `schedule_abc_rotation` 不再根据 ETA 或最终周期心情换半区、重组 cohort、退出可选中枢角色。N/A/B 各自调用构造和最终化；心情检查问题直接保留 warning，再按既有收益目标比较。原 Control 拒绝归因、四次重建包装及对应错误已删除。required Control anchors 超容量仍有独立 fallback：跳过 `pozyomka_durin` 后完整重算。

`OriginiumPairContext` 冻结预占 RoomId，后续只用 RoomId 身份保护，不再靠成员姓名重新猜测。夜烟 shadow 对冻结房直接跳过生产清空；暖机只在非冻结房之间交换；深海 S2 的可变制造列表排除冻结房；reserve 不移动含冻结房的组件；菲亚制造目标重填跳过冻结房。切半组件保持该房整体移动，初始落位确保其归属 α。普通 vacancy fill 仍可补第三席，不整房跳过。

会客室普通候选按实际双人房间求值。精二忍冬可用时，铃兰只作为忍冬搭档组合参与比较；组合胜出才同班落位，未胜出不强制占用。没有当班可用的精二忍冬时，铃兰不作为普通会客室候选；已有 Plan required 落位不受该策略过滤。

main_backup_12_12、main_backup_24_24 与 generic main_backup 是两份完整 assignment 的 owner policy；完整主班名单进入替班禁用集合，只有最终实际菲亚动作目标可沿专用分支复用。24/24 的周期为 48h；Peak Plan registry admission 当前对新增固定 Control claim 成员按 owner 时长逐人试算固定中枢减免与自身技能，不构造完整临时五人 roster。主备不再撤掉 `control_work_hours` 重求，主班和替班分别保留各自时长的保守过滤。完成后的周期问题直接留 warning。显式 gate 仍独立检查最终 assignment。独立龙巫二班已从产品 profile 删除，普通巫恋/龙舌兰同站组合仍由贸易搜索自然评估。`fiammetta_8_8_4_4` 以 16h ABC 脚手架和专用 FiammettaOnly 续班评分；其控制室当前按 ABC roster 准入处理，无动作时保留普通 8/8/4/4。`abyssal_7_5_7_5` 专用 owner 的中枢预算按主班 7h、替班 5h 试算；专用组不可用时以普通主备 owner 交替保留 7/5/7/5，宿管身份或床位组合找不到时不写DormRestPlan，并警告，不宣称深海专用组成立。

初始Plan的Rule/registry中枢候选沿既有ETA入口筛选；普通中枢建池与ABC归属后的首次冻结各消费所属工作窗。动态producer mask、固定pin快捷路径及后续搜索不再复筛心情；protected只消费既有Plan承诺。未请求初始ETA窗口的public selector保持原语义。

## 绑定、宿舍和办公室

shift_bind 只从 AssignmentPlan.resolved_producer_dependencies 和已确认 bind 生成；没有实际贡献的 provider 不绑定。终态 `shift_bind.rs::validate_final_bind_cycle` 从各 Plan 重建闭包，并保留 runtime-only bind；按来源 Plan 区分工作成员、显式宿舍支持和单向依赖支持者，从最终工作岗位重算出勤。宿舍 presence 不算工作，训练/加工普通占位仍是工作岗位；显式 `rest_facility` 只区别该绑定的工作角色与休息去向，不改周期休班统计。exact 组的宿舍支持在工作核心在岗时须实际进入宿舍，不固定宿舍房号；单向支持按 receiver 实际工作时的真实 presence 单独验证，不能用全 roster 或训练副手代替。当前 Plan 把部分单向支持者并入 exact 闭包的生成偏差只在消费视图区分，尚未修复 Plan owner，见活动计划 §6.6。

ABC不因心情问题重编Plan、退出角色或修改已解析绑定。dorm_finalizer按previous_work-current_work安排普通休息，保护已有住员与特殊组，容量不足留warning。办公室、会客室保留技能排序、实际心情对数值的影响与Plan绑定，不按心情预算排除候选；S3到下一S1的累计消耗只在终态诊断。

## 失败传播与验证

质量不足一般不拒绝正常产品输出。普通制造容量 fallback 保留当前池中合法的 0..N 人；全部普通工作设施（不含训练/加工/宿舍）从最终 assignment 生成缺额 warnings。专用能力不足按原 profile 时序尽力输出，profile 结构检查追加诊断。当前所有 profile 都由 `cycle_mood::validate_cycle_mood` 检查首尾连续预算，同人换设施不清零；周期心情问题直接写入最终报告 warning，不再用 Control 成员归因触发拒绝或重建。主备前缀候选耗尽不再撤去中枢过滤；可计算的候选不足、容量与绑定问题在构造 owner 保留状态并继续完成；具名可选候选退出保留原政策。输入、资源、未知计算故障与显式 `--assert-invariants` 的失败不是质量 warning。具体传播顺序唯一见 [定时轮换调用链](../调用链/定时轮换.md#错误与输出)。该门禁不证明真实宿舍恢复、未建模活动、全局最优或 Mower 行为。

## 构造完成、结算与终检

1. 私有 `RotationDraft` 保存构造状态；`prepare_rotation_state` 统一确认普通无依赖动作、保护特殊床位和必要 presence、补普通空位、规范贸易进驻顺序并提交普通宿舍和 autofill。已准备的专用候选不重复完成。
2. ABC A/B、24/24 回池、8/8/4/4 的动作依赖在候选提交前核对。reserve 单项在两半整体试放，质量失败保留原状态并继续其他 reserve。资源/执行故障继续传播。
3. `finalize_timed_rotation` 只清派生快照、读取实际岗位/动作评分、按完整实际周期加权并生成 notes 和诊断；它不补人、不落宿舍、不删除动作。
4. `collect_final_rotation_issues` 返回规则名和具体事实，普通产品渲染 warning，显式 gate 核对心情提示准确性并聚合其他结构问题为错误；独立规则继续执行，缺 Plan 等依赖时标明无法评估。构造诊断单独保留，终态 shortfall/dorm/rest 从真实状态生成并去重。
5. 暖机兼容换房在构造时记录房间置换；终检以原 Plan 和已提交置换核对锚点及设施/等级/产物兼容。源石冻结房不参与置换。

## 终态 invariant 的范围

当前 Rust gate 检查：

- `rotation_duration_input` 第一项核对最终 `shifts[].duration_hours` 的数值安全；非法数值在评分/权重重放前失败。这不证明任何合法时长都能满足心情，也不扩展时长组合业务限制。
- `control_pair_recovery` 核对魔王两档明确委托、来源练度/实例映射，并在实际最终 assignment 上比较启用和移除配对后的 contextual ETA；只有实际同中枢的两名指定成员可受益，其他工作成员保持不变。检查机制映射与实际消费，不要求配对必选，也不代替中枢整体选位偏好的专项证明。

- `ordinary_fallback_admission` 核对七类普通工作岗位实际持有、练度、Plan 排除和唯一性；`ordinary_fallback_complete` 逐班只读试探同一声明的补位 policy，要求不再新增合法岗位。这证明该 policy 的完成稳定性，不是所有可能分队/换位下的全局满编或最优性证明；原容量、Plan、ready 等实体断言独立保留。

- skill_table 中 runtime skill refs 都能由 instances 解析；
- 魔物料理每班只来自该班最终 assignment 的全局产料 atom，不接受预置值；
- 每班办公室人员不与生产/固定岗位重复，不按当前班ETA拒绝；
- notes 可由最终 assignment 重算；
- profile 的 control/production anchor、房间容量和 hard claim 仍存在；
- 24/24 的两个状态各为 24h、分别引用主/备 Plan，实际非宿舍成员属于当班队伍且不跨两班工作，绑定按实际岗位核对；24h工作预算及训练副手缺活动输入只作质量诊断。加工站仅占位不耗小时心情，也不构成回满边界。宿舍 warning 不证明未落位成员已恢复；
- 二班每个普通工作成员只属于一个 owner；已删除的龙巫专用跨 owner 例外不再属于当前产品 profile；
- 普通最终化与显式公共 gate 共用 `rotation_bind` 终态检查：从 Plan 重建绑定并合入 runtime-only bind，宿舍不计工作，单向支持另查 presence；ABC 核对非零 on/off 字段；所有多班 profile 都拒绝 Plan 主动支持者每一班都在工作岗位。其他 profile 继续沿既有团队拓扑及既有专用例外检查。违规在普通报告留 warning，显式验收返回错误；不读取 warning 判断是否合法。候选阶段旧绑定筛选、legacy `verify_shift_binds` 和 24/24 附加校验尚未统一，支持设施合法性与 Plan 关系生成也不由该 gate 完整证明；
- 深海首班存在 control producer 和正好四名 tag consumer，每个 5h 状态有三个不同的 dorm_rest 成员且不在工作房；

## 自动轮换建议

`auto_rotation.rs::schedule_auto_rotation`只形成每站主备建议，不生成换班事件或恢复。沿公共Peak seed、互斥替补与普通完成；主备中枢建池初始筛选后不复筛心情，工作房不按组合预算筛选。先完成并冻结第一次主力，再从剩余工作成员选替补；显式宿舍1＋1常驻共用。质量不足保留正常建议和提示，消费者仅CLI auto分支与Rust auto gate。责任见[自动轮换建议调用链](../调用链/自动轮换建议.md)。

普通两/三班与自动建议共用 `RotationRequest` / `schedule_rotation` 的模式及时长分派；定时兼容入口仍只接受 `TimedRotationRequest`，建议输出仍是独立 `AutoRotationReport`。请求窗口经options→Plan seed→编译上下文传到早期比较；ABC累计Peak/γ半区职责保留。

`prepare_rotation_state` 完成岗位、Team、宿舍与动作提交；`finalize_timed_rotation` 从定稿状态结算逐班和日均收益，并收集缺员、宿舍、休班及终态问题。普通质量问题随完整结果输出；未结算草稿不包装为 PartialRotation，真实资源或机制计算故障保留错误通道。终检不补位、不删动作、不重建中枢。24/24回池目标只归动作班 owner，另一班的真实工作按实际动作和绑定独立核对。`dorm_autofill` 由构造写入，终检从相邻班工作差集与最终宿舍 presence 独立核对，MAA只读。

自动建议的中枢roster按H1/H2作初始单人试算；工作房组合、补位、双中枢兼容和固定主力均不复筛预算。真实同房技能与中枢用于效率、ETA与终态质量提示，详见[自动轮换](../自动轮换.md)2.11。

## 2026-11-01 回收站主动挂件

莱茵规则的 recycle 宿主由通用 Plan 先解析，ABC 的 bound_rotating_anchor_operators / assign_rotating_anchors 已覆盖回收站；技能目录排除绑定挂件，公共补位排除 Plan anchors 和 runtime binds。主备使用各自 Plan 及全班成员互斥。无需第二个挂件轮换 owner。回收站成员仍是实际工作岗位，休班宿舍 presence 不计工作。
