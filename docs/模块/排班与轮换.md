# 排班与轮换模块

> 文档角色：module-reference
> 生命周期状态：current
> 当前真源：docs/文档生命周期.md
> 摘要：说明单班 assignment 如何形成多班轮换、绑定和失败边界
> 代码范围：crates/infra-core/src/schedule/team_rotation.rs、base_rotation.rs、shift_bind.rs、dorm_finalizer.rs
> 知识库桥接：docs/知识库引用.md（机制正文与版本由隔壁知识库裁决）
> 代码锚点：schedule_timed_rotation、schedule_team_rotation、TeamRotationReport、TeamShiftResult
> 关联链路：docs/调用链/定时轮换.md、docs/定时换班.md、docs/菲亚梅塔使用规则.md
> 核验基线：assert_final_rotation_invariants、六个 TimedRotationProfile

本模块把单班 BaseAssignment 组合成固定时长、多状态的轮换报告。游戏机制正文回到隔壁知识库，本项目只记录 capability、runtime dependency 和失败边界。

## 责任边界

负责 profile 解析、班次结构、H1/H2/γ 或专用状态、实际 shift_bind、办公室/会客室补位、菲亚/无人机/dorm_rest、最终效率和 invariant。不负责 Mower、游戏内置自动轮换、机制倍率或全局最优。

## 数据结构

TimedRotationProfile 是六项闭集：abc_12_6_6、abc_12_12_12、main_backup_12_12、fiammetta_witch_12_12、fiammetta_8_8_4_4、abyssal_7_5_7_5。新增 profile 必须同时更新 cli_name、plan_times、分派、终验和 export。

TeamRotationReport 保存 profile、peak_plan、assignment_plans、runtime_shift_binds、peak_mood_eta、teams、shifts、daily、warnings、elapsed。TeamShiftResult 保存 index、plan_index、duration_hours、active_teams、resting_team、assignment、可选动作、transition、三类效率。assignment 是岗位事实唯一 owner。

## 阶段

1. owner solve：layout assign 产生 peak 或 profile owner。
2. split/disjoint：ABC 切 half，二班建立互斥，深海枚举制造人数。
3. bind alignment：shift_binds_from_plan 取真实 dependency，align_shift_binds_in_halves 对齐 half。
4. roster fill：中枢、办公室、会客室补位；绑定成员不得拆开。
5. special actions：菲亚、无人机、深海 DormRestPlan。
6. finalize：效率、宿舍、warning、profile/绑定/连续工作检查。
7. report：供 CLI、profile、MAA 和 serve 消费。

## 状态模型

ABC：H1→α、H2→β、γ 替补；S1=α+β、S2=β+γ、S3=γ+α，γ/α/β 分别休 S1/S2/S3。12/12/12 复用队伍关系，总周期 36h，daily 按总小时归一。

main_backup_12_12 是两份完整 assignment 的 owner policy；主班工作成员进入替班禁用集合。fiammetta_witch_12_12 仅允许两个 owner 共享巫恋/龙舌兰。fiammetta_8_8_4_4 的 FiammettaOnly 只重放目标房。abyssal_7_5_7_5 的 5h 状态固定 DormRestPlan，恢复不足前一段 7h 消耗则失败。

## 绑定、宿舍和办公室

shift_bind 只从 AssignmentPlan.resolved_producer_dependencies 和已确认 bind 生成；没有实际贡献的 provider 不绑定。dorm_finalizer 以 previous_work - current_work 得到普通休息，保护已有住员和特殊组后按容量写入，床位不够返回 warning。办公室普通候选按当前 shift ETA/效率选择；绑定办公室成员优先且 ETA 不足时状态不可行。

## 失败传播与验证

profile 前提、容量、绑定、连续工作、特殊宿舍失败返回 Error；普通办公室/会客室/宿舍缺员返回 warnings。--assert-invariants 会检查 skill refs、notes、办公室 disjoint/ETA、容量、profile anchors、绑定、宿舍和连续工作，但不能证明知识库正文、全局最优或 Mower 行为。

## finalize_timed_rotation 的实际顺序

finalize_timed_rotation 不是单纯的格式化：

1. 对每个 shift 执行菲亚宿舍前置检查；菲亚在目标房外、宿舍无床、目标房消失或恢复组超容量会返回带 rotation 的错误。
2. 清除旧 production efficiencies，普通班次调用 evaluate_base_assignment_efficiencies；FiammettaOnly 调用 score_fiammetta_continuation，只计算目标房延续。
3. 写入 weighted_trade、weighted_manufacture、weighted_power，调用 annotate_assignment 生成当前事实 notes。
4. 累加 daily 三类效率和 average_cycle_production；生产按报告中全部 shift 的实际 duration_hours 加权。
5. 生成办公室/会客室 shortfall warnings；再调用 dorm_finalizer::finalize_dorms 写入普通休息成员。宿舍候选不足只产生 warning，并由 MAA export 读取该 warning 设置 autofill。
6. 调用 assert_final_rotation_invariants。失败不会返回一个“部分成功”报告作为正常结果；上层只可从错误对象取得 partial rotation 供诊断。

## 终态 invariant 的范围

当前 Rust gate 检查：

- skill_table 中 runtime skill refs 都能由 instances 解析；
- 每班办公室人员不与生产/固定岗位重复，且当前班 ETA 足够；
- notes 可由最终 assignment 重算；
- profile 的 control/production anchor、房间容量和 hard claim 仍存在；
- 二班每个普通工作成员只属于一个 owner；龙巫 profile 只允许巫恋/龙舌兰跨 owner；
- 每个 runtime bind 的成员属于一个完整 team，并按同上同下、上 N 休 M 出现；
- 深海首班存在 control producer 和正好四名 tag consumer，每个 5h 状态有三个不同的 dorm_rest 成员且不在工作房；
- 连续工作消耗不超过 workable_mood；菲亚动作会将目标的连续消耗重置。

该 gate 证明的是最终状态满足代码已编码的 invariant；它不能证明未编码的机制正文、跨周期宿舍最优、Mower 行为或全局搜索最优。
