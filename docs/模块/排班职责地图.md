## 3. 不要混淆的层

- `BaseAssignment` 是最终房间岗位事实；`AssignmentPlan` 是 Plan admission 事实；`ShiftEfficiencies` 是结算快照。
- `shift_bind` 是同上同下关系，不是 required admission；tag、priority、shortcut 也不能代替 required。
- ETA 是候选准入/提前拒绝工具；最终 cycle mood 和 final-state invariant 必须从最终 assignment 独立重算。
- 菲亚 `FiammettaShiftAction` 是已写入的排班事件；候选目标、预定目标和最终 target 不是同一事实。
- 回收站 `recycle.rs` 负责设施效率和容量语义；普通房间 admission 负责把实际干员放入房间；MAA 不应反过来决定名单。

## 4.1 菲亚事件与加权结算（当前行为）

普通 named/generic ABC 的 N/A/B 各自完整构造，A/B 附上动作提案后交公共最终化。它们不启用 `schedule_abc_rotation_once` 中的旧 `enable_fiammetta_return` 分支；以下旧回岗 helper 的存在和行为不表示该普通入口仍执行它们。

- **旧普通目标补入 helper**：先按设施布局得到的目标优先序尝试菲亚目标；检查它能否在目标缺席的班次重新进入目标生产房。替换会拆散现有多成员绑定时放弃该目标。动作在完整时间线上通过公共 ready 试放后才写入空闲 slot，并服务目标跨班连续性约束；目标房变过的所有班次都重新评分。普通 ABC N/A/B 不经此旧分支。
- **旧 ABC 巫恋组后备 helper**：仅在旧普通目标路径没有接受动作时尝试。它要求三级金单房已有巫恋+龙舌兰、至少两名不同 β 裁缝能补房；裁缝按候选评分配置到各班，前两个动作位分别给巫恋和龙舌兰，并在写动作前检查 ready。该 helper 不等于普通 ABC 当前 N/A/B 策略，也不是独立龙巫 profile。
- **独立龙巫二班**：已从当前产品 profile 集合删除；旧 CLI/Worker 请求明确不支持，不会静默落为普通主备。保留的巫恋后备 helper 不能作为该模式仍存在或普通 N/A/B 仍走旧回岗的依据。
- **主备 24/24 的边界**：两动作目标不同，且分别来自各自动作班普通 Trade 搜索后实际落位的 TradePost；主班动作目标会单独回到备班候选池参与正常搜索，不加 required anchor。若备班正常搜索重选该人，只有 full-cycle mood、菲亚 ready 与 bind 均通过才接受，否则重新使用普通互斥备班。终态 gate 按各动作自己的班次验证 TradePost，不要求两个目标都跨班持续工作；目标回池的跨班重用只有在最终周期开销可行时才通过。动作槽是上限，若仅一名不同目标通过则保留该动作并警告。
- 24/24 的单动作 warning 在共享宿舍、普通补位和最终 ready finalizer 完成后定位被保留的目标、班次、TradePost 与搜索路径；若共享 finalizer 已剔除动作则报告无动作保留。CLI 按动作班单列最终目标，跨班回池目标在队伍花名册只计入动作班 owner，逐班工位行仍忠实显示实际 assignment。Worker JSON 和 MAA 字段不变。
- **完整周期平均**：最终报告对各班贸易、制造、发电效率分别乘 `本班小时 / 周期总小时` 后累加；同一逻辑适用于六种当前 profile。比如 12h×效率2 与 12h×效率1 的 24h 周期，结果为 1.5。周期加权不负责挑选菲亚目标。
- **8/8/4/4 续班**：菲亚动作后的指定班结算完整编制在 8h 和累计16h 的状态差；目标房用前段值，其他房间取累计值减前段值。该行为不属于普通整班评分。
- 普通主备通过 `build_rotation_report_shell` 建立报告壳，效率、权重和 daily 初始为空值，再由公共 finalizer 结算，不走 `finalize_profile_rotation` 的报告初算。普通 ABC 仍先逐班评分、初始化 daily/warnings，并在构造末尾再次汇总，之后公共 finalizer 再从最终 assignment 结算；这部分重复真实存在。`rotation_scoring.rs::rescore_standard_shifts` 在旧回岗 helper 中的调用不构成普通 ABC 当前活跃链上的第三次中间重算。
- 普通宿舍在公共 finalizer 的 ready 筛除和最终评分前提交；宿舍结构试算失败保留原 assignment 并警告。缺员、专用能力和后置不变量问题通过正常报告的 warnings 输出；显式 `--assert-invariants` 仍可独立失败。完整报告尚未构造的未知错误、非法输入和资源故障不在该降级范围，不能把当前覆盖推成任意输入永不失败。

## 4.2 支持角色、试放与最终评分（当前事实）

- **已承诺的支持角色**来自 Plan 选中的 `proactive_support` role anchor 和 `active_dependencies`；普通宿舍入住者不是支持声明。角色选择使用其候选顺序并立即写入候选 assignment/`used`，不是先建立通用 SupportPool/SupportClaim 再延迟占位。
- 在 `rules.rs::place_role_recursive` 中，所有声明 role 完成落位后才进入 `complete_domain_roles` 的竞争比较；比较读取 candidate assignment 与 `used`。对 `b-073-415` / 243 / ABC + 主动挂件的隔离只读插桩运行，16 次制造/发电分数输入中有 8 次已包含 Plan 选中的四名支持角色；这是该样例的状态证据，不外推为全局候选策略。
- 菲亚 ready 试放复制班次状态、读取现有 assignment 的 ETA，并只试写 action；成功后只提交 `TeamShiftResult.fiammetta`。最终效率与周期权重在 dorm finalizer 后从最终 assignment 重算。该样例有两次动作试放，目标是但书、可露希尔；不代表菲亚重排或保留支持者。
- 同一输入中 S1/S2 的四名 Plan 支持者最终实际位于宿舍，S3 缺席；S1/S2 其他宿舍成员是普通休息入住者，不因同住成为挂件。`target/codex-runs/rotation-support-investigation-20261019/observations/support-trace-summary.json` 记录了 44 个隔离观测事件和样例边界。
- 该组 S3 缺席不是所有输入的结构保证。新调查覆盖两种 ABC 各 38 个真实盒：两种时序均有 19 份选中莱茵规则；其中分别有 8、10 份的非生产支持者最终具有三班 presence，但未观察到组员工作三班。`dorm_finalizer::finalize_dorms` 会把加工/训练等实际工作岗位离岗者放回普通休息宿舍；这不等于 shared 或普通工作 fallback 把人重新投入工作。终态 bind gate 仍只对工作核心验证拓扑、在 receiver 工作时核对 required presence，不能凭这次 76/76 通过宣称支持角色班数检查完整。完整事实 owner 见莱茵 canonical §7.1；隔离前后 trace 与正式产物在 `target/codex-runs/rhine-two-on-one-off-20261019/`。
- Astra 已完成一次只读挂件设计思考并经 DeepSeek 阶段复核；这不是获批的产品设计或实现。当前代码仍为上述 eager placement；不把支持承诺与能力影子候选合并，也不把单样例作为通用 SupportPool/SupportClaim 证明。设计思考及未决边界见活动计划 §6.6。

## 5. 当前未收敛与已共用的责任

以下按普通二/三班活跃调用链核对；菲亚四班与深海专用路径按用户要求延期。不同拓扑、候选试算与最终独立验收本身不是重复 owner，不能仅因旧函数仍存在就列为当前待办：

- 普通主备已经绕过 `finalize_profile_rotation`，不再重复报告初算；普通 ABC 仍在构造中逐班初算、重复汇总 daily/warnings，公共 finalizer 又重算最终报告。应收敛的是这条活跃重复，不是删除候选比较或由函数名称推导所有 profile 都有双 finalizer；前置评分错误与 partial-report 行为尚未证明可安全删除。
- ABC 逐班构造与普通补位候选回放都调用同一 `advance_rotation_mood`，各自持有局部状态；当前证据不足以把不同阶段/快照列为未统一心情算法。`cycle_mood::validate_cycle_mood` 负责最终独立预算验证，不能作为候选推进的重复实现删除。正常 finalizer 已避免内部总断言再次完整复算周期心情；显式 gate 继续独立重算。
- `finalize_shift_dorms` 先处理菲亚床位、特殊恢复组和必要 presence，`dorm_finalizer::finalize_dorms` 再合并相邻班离岗成员并提交宿舍。两段仍写同一 assignment，写入责任尚未收敛；不是两次运行相同的普通休息分配，不能机械删除其中一段。
- 终态绑定已由 `shift_bind.rs::validate_final_bind_cycle` 统一工作/支持统计；普通 finalizer 的结构检查和内部总断言仍重复调用这一同一检查器，这是重复消费而非两套算法。旧候选 bind 检查位于普通 ABC 不启用的菲亚回岗/巫恋后备分支；未调用的 `verify_shift_binds` 与 24/24 专用附加检查的保留，不自动构成当前普通路径的迁移缺口。外部显式 gate 的独立检查必须保留；
- 莱茵 `rhine_receivers` 的 `bind_all` 承载已裁决的组班策略，不能仅凭该字段判定实现偏差或完整合规。规则编译器只对被选 alternative 的全部 anchors 生成 bind，双端 alternative 确实包含娜斯提和缪尔赛思，单端不会因规则 ID 自动并入另一端；rotation 跳过已绑定的 required support 全周期 shared pin。公共宿舍 finalizer 仍能让休班成员以住宿身份再次出现；组班活跃、实际工作与阵营 presence 三者不等价。
- 普通 ABC 与主备保留各自合法目标/槽位策略，ready 与动作试放已由 `fiammetta_events.rs` 统一，不再各自重置物理菲亚预算。公共最终动作筛除后会修正 transition/无人机并结算；不能把不同候选策略或已禁用的旧回岗分支直接列为必须重建的事件 owner。独立龙巫 profile 与其固定目标构造已删除；
- 设施技能选人仍归各设施 owner；七类普通工作空座已经由共享完成入口提交，不再由回收站 finalizer 单独认领。专属技能选人与公共普通补位职责不同，不能由前者分散推导后者尚未统一；
- 24/24 与泛型长班统一消费实际 ETA/制造 mood-gap 准入；不再维护 profile-specific 姓名黑名单。
- `room_admission.rs` 保持候选试算、ETA 和 mood budget helper 边界；普通空座由 `layout/vacancy_fill.rs` 统一消费已裁剪候选，专用绑定和技能排序不迁入它。

只有已证实的活跃重复才能在 old/new 差分证明后合并。不要因为函数名称相似、检查阶段不同或局部快照不同就删除其中一个。
