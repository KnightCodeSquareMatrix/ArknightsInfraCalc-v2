### 已确认裁决 D2：终态检查只读

用户通过结构化问答选择（2026-10-30）：

> 接受，终态检查只读（推荐）：名单或动作要改时回到候选构造，重新结算后检查。

选人、普通补位、宿舍安排及菲亚动作修订在候选构造中完成；候选阶段必要的准入试算继续保留。实际名单和动作确定后，结算与最终核验观察同一版本。终态检查只返回问题，不就地换人、删除动作或修正花名册；需要修改时，由候选构造负责，随后重新结算和检查。

“回到候选构造”是责任归属，**不等于每次都从原始 Box 重跑整份排班，也不意味着最终检查必须触发自动重试**。改名单/动作只能由构造负责，是否自动改、何时改并非 D2 单独裁决。后续 D4 已明确排班 error 全部改为 warning，不能再以旧的特定候选拒绝规则保留整次排班失败出口。显式验收工具不等同于正常产品输出。

本裁决没有批准新增重试、缩减尝试次数或开始代码实施。

### 已确认裁决 D3（最新）：删除三类心情补救重试

本次以最新裁决为准：删除 ABC 半区换向重求；删除 ABC 中枢因 ETA 或终态心情问题重建分组/完整候选；删除主备候选耗尽后撤掉保守中枢心情过滤再重求的路径。前置干员过滤仍由原 owner 执行，终态问题按 D4 作为 warning 输出，不借 warning 隐式恢复这些重试。

这属于用户批准的 policy 删除，允许旧补救路径曾产生的结果不再被选中，不声称行为完全等价。用户关于半区时长的说明作为其删除理由记录；不将其泛化为所有不等长输入下每个具名队伍的累计时长恒等。各队过滤仍读取已有实际工作时长。

菲亚 N/A/B 专用候选比较、正常搜索的组合枚举、菲亚目标回池以及缺少专用能力时的已确认普通降级，不因名称中有“尝试”就一并删除。中枢 required/Plan/绑定规则不因删除重试而放宽。前置逐人试算不取代最终组合和周期检查；检查不合格记录问题。

当前执行单元限于上述三类路径删除、必要的心情诊断接线和验证；排班草稿/定稿结果的整体重构尚未启动。前文仅调查/讨论的授权在此被明确的“删掉”更新为该局部代码修改授权。

### 已确认裁决 D4：排班不失败，现有 error 全部改为 warning

用户针对“排班中途失败时，下游是否使用局部收益”的提问明确纠正（2026-10-30）：

> 排班不可能失败，现有的error都应该改成warning，这条记下来

这是本轮重新设计的明确产品要求：**排班不以失败结束，现有排班 error 全部改为 warning，保留排班结果与问题诊断。** 不再把“允许排班失败后只返回部分结果”作为正常产品设计的既定前提。该条是目标裁决，完整报告的周期诊断在 §8 删除单元中迁移；构造早退仍有 error 出口，整体要求尚未完成。

本裁决覆盖此前对 Control required/requirement-group 周期问题、`ControlRotationMoodRetriesExhausted` 等保留排班拒绝错误的要求；不能自行把这些旧出口列成 warning 规则的例外。D1 的高峰优先与 D2 的只读终态检查继续有效。三类心情补救重试按 D3 删除；不将最终排班问题变回失败出口。

**对设计的直接影响：**不能只改日志级别、仍在原处提前返回未完成报告；需要在重设计中处理原 error 提前退出后尚未完成的组班、动作和结算，使最终名单、动作与评分符合 D2 的同版本要求。问题的真实内容继续保留，warning 不代表已满足约束，也不能用默认零分伪装已完成结算。具体恢复方式尚未设计，不以此自行新增重试或扩大搜索。

原 D4 的两个选项均未被用户接受，撤回该问题，不再等待用户选择“完整收益”或“局部收益”。本条记录排班模块的产品输出要求；外围输入协议、资源读写、进程故障与显式验收工具的处理不在这里擅自扩展为一律报成功。实施前需在具体调用边界识别这些来源，不能据此自行恢复排班域的 error 例外。

### 3.2 选人顺序如何约束整个周期

后继 `schedule_abc_rotation_once:7720` 先用合成的较长工作窗口求 peak；`:7870` 把生产房按绑定组件切成两个半区，`:7908` 从 peak 得到 α/β；`:7940` 起从余池为两半分别构造 γ。之后才建立中枢/辅助岗位的队伍归属和实际班次。这是“先选高峰编制，再构造轮休”的阶段策略，不是三个班次各自独立求最高效率，更不是完整周期最优搜索。

普通主备 `schedule_main_backup_profile:9890` 先得到主班，再由 `solve_policy_disjoint_backup:9201` 从主班占用之外求替班；主班上游选择已经限制替班可选空间。24/24 菲亚目标回池有明确例外，不能当普通任意成员复用。自动建议“第一次主力绝不改”是独立明确裁决，不因讨论普通定时策略被撤销。

**调查后的裁决 D1：**用户选择保留高峰优先及已有专用候选比较，见 §1。当前实现只在若干具名情形完整重试，N/A/B 的完整周期比较也是专用层，不能据此声称普通主备/ABC 已普遍按周期联合择优。后续围绕这个已选方向确定候选状态、冻结边界和失败重建职责。

```text
  → 冻结实际岗位与动作
  → 结算各班及完整周期
  → 只读检查，返回问题
  → 模式编排按既有策略重建，或选择结果附 warning
  → CLI / profile / MAA 投影
```

箭头表示责任先后；候选阶段仍有必要的准入和比较试算。图中只读检查可要求构造重做，不能直接修改冻结状态。ABC 仍为跨周期共同构造，不改成三次互不相关的单班最高效率搜索。

| 责任 | 改写后的输入/输出和唯一职责 | 对应现有路径 |
|---|---|---|
| 模式构造 | 持有本次请求的 Plan、owner、组队、实际岗位与已完成阶段；主备和 ABC 各自实现，遇到问题保留已经形成的状态 | `team_rotation.rs` 中各 `schedule_*` 构造；按职责拆出，最终文件名不先固化 |
| 重试编排 | 接收结构化问题及候选状态，决定是否执行既有换向、cohort 或局部回退；保留触发、顺序、范围和局部上限；管理有限的可返回候选 | 现有递归、wrapper、N/A/B 候选层；全候选有问题时的选择见 §7.5 |
| 候选完成 | 统一提交普通补位、特殊床位/普通宿舍、菲亚动作及对应 transition/无人机变化；一次名单变化同步其队伍归属和关联班次 | `complete_timed_rotation`、`fill_rotation_vacancies`、现有宿舍与动作 helper |
| 最终结算 | 只对定稿名单/动作计分；各班和周期聚合属于同一版本。候选比较需要的试算继续存在，纯报告初算/旧汇总重复删除 | `base_rotation.rs`、普通与菲亚续班结算、daily 汇总；公式复用原 owner |
| 检查与诊断 | 对实际 assignment、Plan、队伍归属、动作和数值只读检查；返回问题集合，普通产品渲染 warning；显式验收独立复算所需规则 | `cycle_mood.rs`、`shift_bind.rs`、终态 invariant 与报告诊断 |
| 输出投影 | 从定稿结果生成文本/JSON/profile/MAA；宿舍 autofill、动作接受等有结构化事实来源，warning 文字只用于呈现 | `rotation_types.rs`、`plan_compute.rs`、`serve.rs`、`export/maa.rs` |

Team 在构造中仍控制候选归属。建议只保留一处归属写入责任，输出花名册由它投影，并核对实际各班岗位；不能直接把所有班次成员取并集反推唯一所属队伍，因为菲亚跨班复用有独立归属规则。

内部类型至少区分“可修改草稿”与“已定稿结果”；未结算草稿不预填最终零收益。是否进一步拆分类型由实现需要决定，不引入通用工作流框架、全局事件系统或另一套搜索器。

### 7.3 error 改 warning 的具体处理

1. **已有完整候选：**检查返回“候选 + 问题”；旧 Control 裸错误改为结构化问题。既有重试继续消费问题原因，避免改成 `Ok` 后直接跳过重试。重试结束仍能拿到报告。
2. **构造中已有部分成果：**把主班/替班、peak/半区/γ、当前班次放进有明确阶段的草稿；问题交给本阶段 owner。可继续的质量问题记录后继续；需要已有重试的保留状态交回编排。局部试放在提交前验证，失败不会把半次更新混进下一阶段。
3. **下层已丢状态：**在 `layout/assign` 的 Plan/pipeline 出口保留可用的 Plan、已承诺岗位和未完成工作，让排班继续完成；构造仍经过 `build_plan → execute_plan → fill → resolve`。不在 CLI 或终态检验里绕过 admission。涉及这个接口的修改是排班保证的必要依赖，不顺势重写单房间公式或全局选人策略。
4. **动作不可用：**沿已有政策在构造阶段去掉不成立动作、调整执行方式，再按最终状态结算；不靠导出阶段临时删动作，也不让“候选本想用菲亚”成为最终收益依据。
5. **诊断传递：**问题有类别、来源阶段、班次/房间/成员和上下文；问题本身不决定重试，模式政策决定。旧错误文字可用于人读，不能继续承担候选退出、重试或 MAA 的程序分派。最终状态诊断与历史尝试记录分开，避免被替换候选的问题误挂到最终名单。

这里不承诺用一段通用 catch-all 处理所有状态。原本没有可用 Plan/合法结构的出口需要在最早 owner 补齐可表达的普通结果；每处转换都要证明后续阶段有真实输入。相应细节是实施单元的必要工作，不能靠空报告或默认评分达成“永不失败”。

### 7.4 实施顺序与验收

建议按责任依赖串行完成，再对整个功能验收：

1. 建立草稿、定稿结果与结构化问题边界，接上单班状态返回；保证新旧行为对照时不会提前丢结果。
2. 先迁普通主备，覆盖“主班成功但替班未完成”与“主/备都完成但质量有问题”；再迁 ABC，覆盖半区/γ/中枢/逐班状态及 N/A/B。共用链路改变时同步适配四班调用，不重议其专用策略；自动建议只校对共享接口，独立策略另行讨论。
3. 收拢补位、宿舍与动作写入，统一最终结算和只读检查，接通 warning 到所有输出；删除被替代的旧最终化、错误降级和文本分派路径。哪些中间评分能删，按是否仍为候选比较/准入提供信息逐项判定。
4. 完整功能后一次执行 release 验证包和独立意图复审。正常排班输出与显式 gate 分开核对：产品带 warning 返回，不等于约束全部通过；不得为追求批量全绿删除真实质量诊断或断言。

验证至少覆盖：

| 边界案例 | 要证明的行为 |
|---|---|
| 主班成功、替班候选耗尽 | 保持已确认重试范围，主班不被错误传播丢失，最终两班时序与诊断齐全 |
| ABC 有完整报告但 Control 周期问题 | 按原次数/顺序尝试，耗尽仍返回可核对排班并 warning |
| ABC 只完成部分 γ 或班次 | 不以 report 壳冒充结果；完成后各班、Plan、队伍和实际岗位对应 |
| 菲亚动作被取消 | 最终岗位、执行方式、收益和 MAA 对取消后的同一状态达成一致 |
| 普通短员、绑定/心情问题 | 产品保留真实问题，构造不为消除告警擅自突破已确认准入；显式 gate 如实报告 |
| 宿舍 warning 文案变化 | 已确认的 MAA autofill 行为不随文字前缀变化 |
| 队伍归属与实际岗位不一致 | 覆盖上轮普通 12/12 花名册反例，不能只依赖现有 gate 通过；自动 12F 反例留在自动模块范围 |
| 代表性与 high-owned Box | 用 release 入口跑真实普通模式及受共用改动影响的专用模式，比较原候选策略/动作/收益及 D4 的预期输出变化 |

原有可正常输出的路径做行为对照；原 error 转 warning 的路径是 D4 授权的产品变化，不能混称全部等价。现有固定有限候选与近似保持原保证类别，不宣称全局最优或天然提速。按 `arknights-invariant-gate` 验证最终 assignment，再按 `arknights-intent-review` 复审整个功能；本轮只有文档和静态证据，没有执行这些代码变更门禁。

实施在用户当前工作树串行完成，不创建分支/worktree，不整支合并历史实验。冻结后继代码用于核对已确认行为；需要引入的版本差异按模块单独审查，不因来自更新分支就整包接收。

### 7.5 已撤回的问题：全候选都有问题时保留哪份

原问题建立在“新设计保留错误驱动的重试及一批待择优报告”这一前提上，给出沿原收益比较或基础方案固定优先两个选项。用户未选择，而是问“这个既有重试又是什么？在我的模型设计里没有”。因此问题撤回，两个选项都未获批准，不继续追问耗尽后的排序。

随后用户已裁决删除 ABC 换半区、Control 心情问题后换组合、主备候选耗尽后撤去过滤重求，见 D3。这些是旧代码的补救路径，不是必须存在的领域模块。D1 已确认的菲亚 N/A/B 比较属于具名方案比较，应与它们分开。

不能由此声称用户已要求删除全部候选搜索，也不能拿早先“保留现有策略”的点击限制其重新澄清模型。最新局部代码删除与验证见 §8。
