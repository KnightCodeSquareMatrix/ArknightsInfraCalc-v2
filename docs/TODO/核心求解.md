## 定位

从“为什么没有选中、为什么选中了错误的人、为什么跨房间状态没有成立”进入。单房公式问题先读机制 canonical；跨设施、候选集合和 Plan 边界再从这里选择活动项。状态表示工作是否已具备实施条件，不代表优先级或当前任务授权。

## 使用边界

- tracker 只提供工作流入口；目标、非目标、证据和关闭条件由详情页维护。
- `proposal` 尚需领域裁决；`ready-on-request` 可在用户选择后实施；`in-progress` 仅限当前 writer；`blocked` 必须写清阻塞条件。
- 活动项完成后，先把稳定事实吸收到 current owner，再把详情移入 ARCHIVE；不得让 tracker 成为第二份机制规范。
