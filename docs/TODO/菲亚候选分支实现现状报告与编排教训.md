## 1. 任务背景

菲亚梅塔在定时换班中的职责是"阶段间的固定策略分支选择器"：

```text
同一 Box → 前置资格判断 → 固定枚举 N / A / B 三候选
→ 每候选各自完整走一遍现有排班 pipeline
→ 比较完整周期收益 → winner → 由 winner 生成菲亚动作与交接
```

- N：不使用菲亚梅塔的完整基线（兜底，参与比较）；
- A：但书 / 可露希尔单核心，提前钉岗后完整 pipeline；
- B：巫恋 + 龙舌兰 + 合法裁缝完整站，先冻结整站后完整 pipeline。

用户裁决的硬约束：

- 每候选从同一初始 Box 独立完整求解，状态隔离；
- 只固定策略组约束，不固定房间和槽位；
- 分支前先判断用户是否拥有角色并达到练度；
- 复用既有龙巫组合判定（`match_witch_group_shortcut`），不手搓规则；
- 完整周期收益比较，沿用 profile 既有目标，平局保留 N；
- `fiammetta_8_8_4_4`（8844）不收编。

完整设计见 [ADR 0010（proposal，实现未完成）](ADR/0010-fiammetta-fixed-branches-full-recompute.md)。

## 2. 已完成的实现（可保留的事实）

### 2.1 `execute_plan` 支持"从中间态构造"

`crates/infra-core/src/layout/orchestrate/execute.rs` 新增 `seeded_anchor_satisfied`：
当 `execution_seed` 已含某成员且其所在房间满足 anchor 的设施/产品语义时，跳过该
anchor 的重复落位（原本直接报错 "occupied before execute"）。普通路径 seed 为空，
此分支不触发。这是"预排表作为中间态进入 pipeline"的最小机制，方向被验证正确。

### 2.2 候选层骨架与预排 seed

`schedule_abc_rotation_candidates`（`team_rotation.rs`）已实现：

- 前置资格判断 `fiammetta_candidate_eligibility`（A/B 分别判拥有+练度+布局条件）；
- B 候选 `build_fiammetta_b_seed`：复用 `match_witch_group_shortcut` 挑合法第三人，
  预排完整巫恋站作 `execution_seed`；
- B 候选通过 `assign_shift_with_preclaimed_plan` 从中间态构造，且带
  `shift_bind`（巫恋+龙舌兰 上2休1），实测该分支完整跑通且不变量通过；
- 收益比较 `fiammetta_candidate_score` 沿用 trade/manufacture 加权，不混入 power。

### 2.3 A 分支的两次尝试（均未达终态）

- 第一次（已提交 `126c2a9`，后修正于 `050ec79`）：A 只跑普通排班后"事后找班次写
  动作"，但书本来就在岗，收益与 N 完全相同——用户判定为"假 A"；
- 第二次（`050ec79`）：A 候选预排但书站作 seed + 复用
  `apply_profile_fiammetta_rotation` 做跨班 refill 延续，但书收益与 N 分离（3.928
  vs 3.946），但触发新的编排冲突（见下节），最终未达终态。

## 3. 本次失败的核心问题

### 3.1 预排 seed 锁房与 γ 搜索抢房（已复现，有日志证据）

A 分支 seed 把但书钉在"首个金单站"（trade_1）。但 γ（替补）搜索看到的共存
assignment 中 trade_1 是空的——seed 只影响 peak 阶段，未传播到 γ 搜索。结果：

```text
γ 搜索先填 trade_1 → 命中巫恋+龙舌兰+卡夫卡（2.482，最优）
γ 再填 trade_2 → 巫恋组已 used → 只能选能天使+蕾缪安+空弦（2.293）
随后但书 refill 覆盖 trade_1 → 巫恋组被踢出，但 used 已标记，无法回到 trade_2
```

现象：A 分支完整排班出现"能天使+蕾缪安+空弦"这一非预期组合，trade_2 效率
2.293 明显低于巫恋站应有的 2.482；巫恋/龙舌兰/裁缝角色齐全却未组成完整站。

根因：**seed 预排的房间与 γ 搜索的自然选站互不知晓**，预排只约束 peak，不约束
γ 的 coexist context；事后 refill 与 γ 结果冲突时只能覆盖，造成浪费。

### 3.2 A 分支"钉岗"与既有 refill 逻辑的二次耦合

方案 A（不锁房）改为不传 seed、由正式搜索自然进站后，但书动作未生成（targets
为空），且收益退回与 N 完全相同（3.946）——"假 A"复现。追查显示
`apply_profile_fiammetta_rotation` 在 required_target=但书 时，目标循环中
但书未通过既有 `has_multi_member_shift_bind` / room 解析等前置条件，动作未写入。
该函数是为旧局部 refill 场景编写的，直接复用到候选分支语义上存在隐形前置条件
（continuous_roles、shift_binds 的来源与候选语义不一致），排查成本高。

### 3.3 结构性判断：现有编排承载不了候选分支

`schedule_abc_rotation` 是约 1.3 万行的单体编排：peak 求解 → resolve → 建池 →
切半 → γ 替补 → 中枢三班 → 组装评分 → 菲亚后处理 → 终验。候选分支需要"在
pipeline 前决定策略组、在 pipeline 内保持钉岗、在结果上写动作"三种能力，而这三
种能力分别散落在 seed 机制、γ 搜索、菲亚后处理三个互不感知的阶段。任何单点修复
都会在另一阶段产生连锁回归：

| 阶段 | 承担职责 | 实际缺陷 |
|---|---|---|
| seed 预排（peak） | 提前钉策略组 | 不传播到 γ 共存上下文，锁房与 γ 抢房 |
| γ 搜索 | 替补填充剩余槽位 | 不知道预排站，把最优组合填进将被覆盖的房间 |
| 菲亚后处理 | 写动作 + 跨班延续 | 依赖 continuous_roles/shift_binds 的旧前置条件，与候选语义不一致 |

这不是某个 bug，而是接入方式本身与现有编排的耦合结构不匹配。

## 5. 教训与下一步输入

### 5.1 教训

1. **候选分支需要独立的候选上下文，不能靠"预排 seed + 事后覆盖"表达**。策略组
   的钉岗语义必须让后续所有阶段（含 γ 搜索）可见，或候选层自身拥有独立的完整
   pipeline 调用边界。
2. **预排中间态与现有编排的传播边界必须显式**：seed 进入 peak 后，哪些阶段感知、
   哪些不感知，需要有明确契约；否则必然出现"预排站被搜索重复占用"或"最优组合
   填入将被覆盖的房间"。
3. **既有菲亚后处理函数（refill 系列）是旧局部模型的历史产物**，其前置条件
   （continuous_roles、shift_binds、fiammetta_return_priority）与候选分支语义不
   一致，不能直接复用为候选动作生成；候选动作应在候选自己的完整结果上独立结算。
4. **每波改动应可独立验证终态**：本次 A 分支连续两波都"能编译、能跑、候选层输出
   了数字"，但都未达到用户要求的语义终态（真实钉岗 + 不浪费组合），验证标准应
   以语义为准，不以"候选层存在"为准。

### 5.2 下一步设计输入（用户将重新设计 pipeline）

- 候选分支的"策略组约束"应作为 pipeline 的显式输入契约，而非 seed 副作用；
- 需要明确：候选完整求解是复用现有 `schedule_abc_rotation` 入口（外层隔离），
  还是要求编排内新增候选阶段；前者改动小但需证明状态隔离，后者改动大但语义清晰；
- B 分支已验证可行的部分（`match_witch_group_shortcut` 复用、预排巫恋站、
  `execute_plan` 中间态跳过）可保留为事实基础；
- A 分支的"钉岗"语义需在候选完整结果上独立结算，不依赖旧 refill 前置条件。
