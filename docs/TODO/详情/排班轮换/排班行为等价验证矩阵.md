## 1. 比较对象

每个迁移单元固定保存：

- old source：迁移前 dirty baseline 的 source fingerprint；
- new source：只包含本迁移单元的 source fingerprint；
- identical input：相同 Box、Layout、runtime data、options、profile 和 initial mood；
- release binary：同一 release profile，不能用 debug 端到端结果替代；
- report JSON、MAA JSON、stderr/stage log 和 invariant 输出。

当前 dirty baseline 指纹见 `target/codex-runs/rotation-unification-20261018/fingerprints.txt`。既有 dirty 改动不能被 old/new 差分误算成新改动。

## 2. 必须逐层相等的字段

| 层 | 比较内容 | 允许差异 |
|---|---|---|
| profile | profile wire 名、班次数、时长、顺序 | 无；排序只可在明确无序字段中规范化 |
| assignment | 每班每房间的实际干员、岗位、容量、required anchor | 无 |
| continuation | 续班关系、局部 transition、菲亚动作目标和房间 | 用户已授权统一 ready-only：未 ready 的动作不再写入；影响到的动作缺席/无候选结果须单独记录为预期行为变化；其他续班关系无差异 |
| recycle | 每班成员、技能档位、容量、效率 room line | 无；未导出字段也必须比对 Report |
| mood | 每班实际 drain、恢复边界、首尾连续预算和失败位置 | 无；ETA 与最终 gate 不能互相替代 |
| settlement | room lines、trade/manufacture/power、weighted daily、production | 仅允许明确的浮点容差 |
| diagnostics | warnings 文本、顺序、错误前缀、partial rotation stage | 无 |
| export | MAA plans、rooms、operators、autofill、Fiammetta、drone、recycle | 既有字段无差异；本轮新增 `rooms.recycle[].operators` 必须与最终 assignment 一致，MAA 不得重新选人；旧回收站 A/B 草案已过期 |
| contract | CLI/Worker schema、版本、字段是否存在 | 既有合同无差异；回收站明确纳入的输出字段按本轮接口合同验证，其他未决字段不自动扩展 |

## 4. 24/24 ETA 特别证明

24/24 的统一候选策略允许使用现有 ETA 试算提前拒绝明显不可行候选，但必须区分：

- ETA：候选准入/排序前的 safe rejection，只能使用已确认的窗口、room context 和 Plan claims；
- final gate：从最终 assignment 独立重算，证明实际 24h 工作、跨设施连续预算、制造 mood-gap 和 profile topology；
- 静态高消耗姓名名单：不再是最终资格 owner；必须记录 ETA 替换前后的候选可见集合、winner 和失败原因差异。

不能用“最终结果仍能求解”证明候选策略等价；必须比较 rejected candidates、winner value 和失败原因。

## 5. 暂停条件

以下未被用户明确授权的差异出现时，只停止相关实现单元并询问，不停下其他独立工作：

- old/new 的最终 assignment 不同，且不能由未排序 JSON 或等价房间顺序解释；
- 菲亚动作数量、目标、slot 或连续目标变化，若并非源自已授权的 ready-only 校正则暂停相关单元；ready 校正按 profile 记录动作取消、候选拒绝和无可接受目标边界；
- 任何普通房间的成员、容量、轮休、空站行为或缺员状态变化；回收站与其他房间一样，若变化来自统一 admission 的修正，必须记录责任路径而不是把它伪装成等价差异；
- 24/24 的候选可见集合、ETA 失败原因、winner 或错误等级变化；
- warning 文案、MAA autofill 或 Worker summary 改变；
- finalizer 需要新增领域规则而不是移动已有规则；
- 文档描述要求改变 canonical 语义或当前公共接口。

暂停时必须记录：输入 fingerprint、old/new report、首次差异字段、责任函数、是否需要用户裁决和未完成的证据。

## 6. 最低验证集

在真实 high-owned batch 之前，至少完成：

- 六个当前 profile 各一组代表性 Box/Layout；
- ABC 两个朝向和菲亚 N/A/B 可行/不可行候选；
- 旧龙巫 CLI/Worker/core 请求分别失败，且不映射主备；普通 ABC 巫恋同站候选不回归；
- 8/8/4/4 的局部事件与普通完整换班对照；
- 24/24 高消耗候选拒绝、ETA 可行边界和制造 mood-gap 边界；
- 回收站 Lv1/Lv2/Lv3、空站、技能候选和普通填充；
- MAA/Worker 在当前支持版本内的字段一致性，尤其是 `rooms.recycle[].operators`；训练室 A/B 另按其角色契约验证，不与回收站混用；
- final-state invariant gate 与首尾周期心情。

当前没有运行这些新重构验证；本页是验证计划，不是通过报告。
