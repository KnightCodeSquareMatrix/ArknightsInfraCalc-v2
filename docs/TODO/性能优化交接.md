### 4.5 心情与暖机影响效率的技能（子代理扫描 `skill_table.json`，原文报告 `/tmp/v2-mood-ramp/report.md`）

用户裁决（2026-10-28）：除铅踝外，心情不影响真正效率；暖机技能额外写函数计算效率。扫描结果与裁决一致：

- **贸易站**：没有任何效率随心情变化的原子。19 个心情原子全是 `mood_drain_delta` / `mood_drain_per_state_step`，只算心情消耗。
- **制造站，心情改变效率的只有两条**，都是铅踝：`manu_prod_spd_reduce[000]` 模糊视线（`owner_mood_gap` selector，每 4 点落差 -5%）和 `manu_prod_spd_addition&cost[000]` 窗外雪啸（落差 >12 时 +10% 效率、+6 仓库）。其余制造站心情原子都是 `mood_drain_delta`。
- **暖机（`add_eff_ramp`）共 5 条，全在制造站**：急性子 `[030]`、“等不及” `[031]`、慢性子 `[040]`、延时摄影 `[041]`、例行清扫 `[100]`。解释器对 ramp 取 20 小时算术平均（`manufacture/interpreter.rs:565-570`，`eff_ramp.rs`）。发电站另有两条硬编码 ramp（`power/solver.rs:112`、`:120`，技术交流 α/β，skill_table 里 atoms 为空）。
- **控制中枢有 3 个心情条件技能**（山河远阔、不以物喜、不以己悲），不在单房间 Bake 范围内。
- **两处按 `mood <= 0` 把基础效率归零**（`trade/interpreter.rs:140`、`manufacture/interpreter.rs:135`），只在心情耗尽时触发。Bake 设计要确认这条边界如何处理。
- **shift_hours 的作用与字段口径**：贸易 `TradeResult.daily_at_shift` 按 `shift_hours/24` 缩放；搜索命中中的日产字段仍按24小时恢复，不得在 Bake 命中后再次乘该比例，纸面效率不变；制造站在房间含心情落差效果时才按心情阈值切段重解（`manufacture/solver.rs:59-173`），否则退回静态结算。也就是说制造站的分段重解只为铅踝存在。
- 分派键应当是 `buff_id`（AGENTS.md 的分层边界：L1 interpreter 只认 `buff_id`，不认干员名）。

### 4.6 冻结版本阶段测量（2026-10-28，仅 b-008-411 三班）

原始证据 `/tmp/perf-stage-20261028/report.md`、`stage.stdout/stderr`、`no-perf.stdout/stderr` 和 `summaries.json`。冻结二进制 SHA256 为 `168a12ac16bdc1c74ec54f7c5a8a9be34aaf42ca02503a71779aa58a345adc01`；同一 `high-owned/b-008-411.json`，默认汇总和 `--no-perf` 各顺序运行3次。仅提供性能归因证据，不作为逐单元正确性验收；该测量不代表最终 U2～U6 收益。

| 观测 | 结果 | 可支持的判断 |
|---|---:|---|
| 默认汇总平均总耗时 | 1821.150ms（1765.820～1894.129） | 单box、3次均成功 |
| `--no-perf` 平均总耗时 | 1909.393ms（1725.506～2084.414） | 顺序运行存在噪声，不能得出日志负开销 |
| 制造搜索累计 inclusive 耗时 | 989.698ms，约总耗时54%；每次38次搜索 | 此样本的主要可见热区是制造搜索 |
| 贸易搜索累计 inclusive 耗时 | 111.165ms，约6%；每次39次搜索 | 重复贸易调用多，但此样本耗时占比较低 |
| 搜索归属 `actual_trade_solves` | 每次15297 | 全局 profile `trade_solves=15379`，两边界差82，具体来源尚未归因 |
| N / A / B 候选实际贸易结算 | 2612 / 6650 / 3191 | A 的结算数最多；次数不能直接换算成本 |
| 中枢重建 | 每次只有 `attempt_0`，3候选均未重建 | 不能把“最多4次重建”当作此样本真实乘数 |
| peak / γ H1 / γ H2 实际贸易结算 | 5119 / 4200 / 3134 | 排班内重复计算的具体归属已可见 |

stage 与 operation 都是 inclusive，父子阶段与计数可以覆盖同一操作，**不可相加**；N/A/B 与 peak/γ 属于不同归因切面。15297是搜索 batch 归属次数，15379是全局入口累计，不能互相替换。日志计时结束于汇总格式化前，`--no-perf` 也未去掉所有既有计时/计数；3次均值不足以证明真实日志开销方向或幅度。只测一个box和三班，不能推广到其他盒、轮换或生产请求。
