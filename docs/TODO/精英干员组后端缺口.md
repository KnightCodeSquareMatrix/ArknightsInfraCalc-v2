# 精英干员组后端缺口

> 文档角色：active-change
> 生命周期状态：ready-on-request
> 当前真源：docs/练卡推荐相关/组合知识库.md
> 摘要：后端按实际编制统计精英设施数并结算凯尔希·思衡托「泰拉的方舟」；推荐可先展示、不得宣称求解已支持

## 1. 推荐侧定义

规范名称：**精英干员组**。

组合含义：罗德岛精英干员实际进入不同设施后，为凯尔希·思衡托提供设施数量；设施数量用于提高凯尔希·思衡托在人力办公室的联络效率。

练卡推荐可以按组合知识展示持有与练度情况，但在本 TODO 完成前必须注明：**当前后端尚不能完整计算凯尔希·思衡托的该项收益。**

## 2. 当前已实现部分

后端已经具备可复用的设施计数基础：

- `layout/workforce.rs` 能从实际 `BaseAssignment` 统计有精英干员进驻的不同设施；
- 当前精英干员名单/标签包含迷迭香、煌、逻各斯、烛煌、电弧、真言；
- 计数排除会客室，且中枢只读取首领位；
- `resolve_base` 会把实际计数写入 `LayoutContext.elite_facility_count`；
- 贸易站真言「精英小队」已经消费该计数：基础 25%，每个设施额外 2%，最多额外 20%。

这些事实只证明“设施计数”和“真言消费”存在，不证明凯尔希·思衡托已经实现。

## 3. 当前缺失部分

凯尔希·思衡托「泰拉的方舟」原文口径：

```text
进驻人力办公室时，联络速度 +30%；
基建内（不包含副手及活动室）每有一间进驻精英干员的设施，额外 +4%；
最多计算 5 间设施。
```

当前缺口（2026-08-06 更新：办公室轮换候选已改用 `support_skill_registry` 评分，见下）：

- `support_skill_registry.json` 已含凯尔希·思衡托「泰拉的方舟」办公室条目（基础 30%、每精英设施 4%、cap 5）；
- `office_candidates` 已改用 registry 静态求值，候选池不再因 instances 缺失而过滤凯尔希·思衡托（`crates/infra-core/src/schedule/team_rotation.rs`）；
- `operator_instances.json` 仍没有凯尔希·思衡托的运行时条目——不影响办公室轮换候选评分，但跨设施 atom / 其他设施归属仍以其为 owner；
- `skill_table.json` 没有「泰拉的方舟」办公室技能定义（registry 路径不依赖它）；
- 当前编排和排班不会为该收益识别或保证精英干员分布；
- 没有凯尔希·思衡托随实际设施计数变化的单元、布局和排班验证；
- `MODELLED_OPERATORS.md` 当前把凯尔希/思衡托写成人间烟火、感知链，和「泰拉的方舟」原文冲突，实施前必须先统一 current 文档。

## 5. 验收口径

- 凯尔希·思衡托精二进入办公室时，0 间精英设施为 30%。
- 1 间为 34%，5 间为 50%，超过 5 间仍为 50%。
- 计数必须来自实际 assignment；蓝图手填值只能作为显式测试或兼容输入，不能冒充实际进编证明。
- 真言已经存在的精英设施计数行为不得回归。
- 推荐报告和求解结果必须分别声明数据来源，不能因推荐知识库已收录就宣称后端已经支持。
