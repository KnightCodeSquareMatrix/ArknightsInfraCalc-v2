## 当前实现与代码入口

- 菲亚目标连续性：`crates/infra-core/src/schedule/team_rotation.rs` 的目标刷新、连续性校验和最终 rotation gate。
- 中枢效果：`crates/infra-core/src/control/ledger.rs`、`crates/infra-core/src/search/control.rs`、`crates/infra-core/src/layout/assign/control_fill.rs`。
- 排班主路径：`layout/assign/pipeline.rs` → `schedule/team_rotation.rs` → MAA export；入口和责任边界见 [项目地图](../PROJECT_MAP.md)。

现有最终状态断言覆盖菲亚目标在岗、目标房存在和绑定连续性，但尚缺“非 `EffectKey` 中枢资源唯一准入”的稳定断言。断言名称和判定集合必须在政策裁决后确定，不能先按干员姓名添加。

## 需要的证据

1. 对每个待复现条目冻结 layout、operbox、站点/宿舍等级、订单、班次、最终 assignment、`rule_id`、候选池和 `used` 集合。
2. 对确认修复项在 Rust 最终 assignment 上注册 assertion；Python 只批量调用 Rust gate 和报告输入错误、无解或超时。
3. 菲亚条目要区分 schedule 输出契约与执行侧回宿舍责任；不把 MAA 未执行动作归因于 solver。
4. 中枢条目要证明激活、拒绝、跨班和最终可行性；不能只凭单个 top hit 或历史工作簿勾选关闭。

## 非目标

- 不把目标房重搜扩展为全局排班重算。
- 不放宽菲亚跨周期目标条件，不模拟完整实时心情曲线或宿舍槽位。
- 不处理跨体系挂件、能力影子候选或 08-212 龙巫候选；这些由独立案件跟踪。
- 不按布局编号、房间编号、班次下标或干员姓名添加补偿特判。
