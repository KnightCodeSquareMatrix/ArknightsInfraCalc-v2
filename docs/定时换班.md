# 定时换班

> 文档角色：canonical
> 生命周期状态：current
> 领域键：schedule.timed
> 当前真源：self
> 摘要：定义固定时刻定时轮换的求解器行为和输出边界
> 代码范围：crates/infra-core/src/schedule/team_rotation.rs、crates/infra-cli/src/commands/plan*.rs
> 知识库桥接：docs/知识库引用.md（机制正文与版本由隔壁知识库裁决）
> 代码锚点：TimedRotationProfile、schedule_timed_rotation_request、TeamShiftResult
> 关联链路：docs/调用链/定时轮换.md、docs/菲亚梅塔使用规则.md
> 核验基线：六个当前产品 profile 与最终 invariant

定时换班服务 MAA 和人工固定时刻执行，输出完整班次表；不负责 Mower、游戏内置自动轮换或跨周期永续优化。

> **当前提交边界：**普通二/三班泛型时长和 Worker v7 随本次 WIP 提交，但未完成 fresh release 验收或部署；规则记录已裁决行为不代表所有部署版本已支持，消费者以实际 Worker wire 为准。

`TimedRotationRequest` 在本次 WIP 中承载 named timings 与普通二/三班 topology timing。CLI `--rotation main-backup@H1/H2`、`--rotation abc@H1/H2/H3` 和 Worker `plan.compute` v7 的 `{topology, shift_hours}` 对象进入同一时长驱动的周期与终态流程；班次顺序保持调用方输入。前端负责拒绝不合法组合，本轮没有增加后端时长业务约束。旧 named timings 的求解语义不变：abc_12_6_6、abc_12_12_12、main_backup_12_12、main_backup_24_24、fiammetta_8_8_4_4、abyssal_7_5_7_5。Worker v1–v6 schema 与 wire 含义不变，v6 继续是闭集。独立龙巫二班已删除；旧 `fiammetta_witch_12_12`、`fiammetta-witch-1212` 和 `witch-1212` 请求明确失败，不映射或降级成普通主备。

**时长数值安全与业务组合分开：**generic CLI 解析与共享 core 请求入口在搜索前拒绝非有限、非正、按现有分钟权重舍入后不足一分钟、或超过整数权重算术安全域的时长。每班舍入分钟数、这些分钟数之和与实际周期小时换算的舍入分钟数均不得超过 `i64::MAX / (i32::MAX + 2)`（4,294,967,294 分钟）。这为 `Efficiency::scale_ratio` 的乘法和正负舍入保留余量，不是新增总周期或时长组合政策；例如 `10/15` 不因总计 25h 被后端拒绝。非法数值走 `rotation_duration_input:` 输入错误，不降为质量 warning。共同 finalizer 与显式 gate 也从实际 `shifts[].duration_hours` 重查，gate 使用稳定前缀 `assert-invariants rotation_duration_input:`。合法数值不保证心情可行，后续质量 warning 与显式心情 gate 仍独立生效。

共享工作区 WIP 的普通主备 topology 保持两个完整 owner 状态与工作成员互斥；ABC topology 保持三队、每班两队工作一队休息。普通泛型请求的周期由调用方限制为 24h、36h 或 48h；班次仍按输入顺序承载实际时长。α 映射到最长班；ABC 并列最长时把休班相位放在较短班，尽量覆盖全部可覆盖的并列最长班，完全等长时保留旧相位。泛型班次超过 12h 时该班最多生成一次菲亚动作，动作仍受 ready、目标去重和最终 assignment 核对；旧 named timing 的动作槽位不变。v7 WIP 的 generic 24/24 与 named 24/24 目标均由实际班长 ETA/心情准入决定，不再使用姓名黑名单；泛型超过 24h 使用输入的实际班长。四班菲亚 `8/8/4/4` 与深海 `7/5/7/5` 继续走原专用路径。完整决策见 [ADR 0011](ADR/0011-generic-two-three-shift-rotation.md)；求解保证仍是既定 facility policy 下的求解，不宣称全局最优。

用户于 2026-10-23 明确普通泛型 ABC 同样使用菲亚 N/A/B 候选层。每个候选共享调用方实际班时，分别完整重求解；generic ABC 先按 α 相位排序构造，候选完成后将含 `duration_hours`、assignment 和动作的整个班次恢复为输入顺序，再完成最终化与收益比较。候选 winner 仍按[菲亚候选策略](菲亚梅塔候选分支适配层设计.md)的 `daily.production` value 选择，平局保留 N；源石 pair 和 ABC 轮休不是候选变量。普通泛型主备与四班专用 profile 不进入该候选层。

生成顺序为：timing/topology 解析 → owner/peak assignment → 依 topology 建立周期班次状态 → Plan dependency/shift_bind → 中枢、办公室、会客室补位 → 菲亚/无人机/dorm_rest → 一个公共完整周期 finalizer → 最终 bind/required/工作休息与 invariant/warnings → CLI/MAA 输出。周期结算统一读取每个最终班次的实际 `duration_hours` 和 `assignment`；MAA 不重新选人，宿舍不算工作。普通二/三班的构造分别保留主备互斥或 ABC 轮休策略，四班特殊路径不进入新泛型分派。

共享工作区 WIP 中所有 profile 最终状态都按下节统一周期预算核验，专用 profile 原有连续工作/恢复和安全余量校验继续独立生效。`main_backup_24_24` 的每个状态是一个完整 24h 计划：生产搜索使用 24h 长班口径，带 12h 后心情衰减的制造成员不进入该长班；WIP 候选阶段按真实 24h ETA 过滤，不再按姓名预先排除。受限主班候选耗尽时，普通产品仍按 24/24 形状走 warning fallback；若主班已在预算内求解成功、仅备班候选耗尽，则保留原主班 assignment 与 Plan，只对仍受完整主班名单互斥的备班撤去候选阶段的 control ETA 限制并重求。只有候选前缀明确耗尽才触发该恢复；资源、输入和其他计算错误继续传播。正常结果携带 `rotation_final_invariant:` warning，显式 gate 仍按最终实际 24h assignment 独立失败。泛型主备给每个 owner 的 control ETA 使用其实际班长，包括超过 24h 的输入；若只有备班候选耗尽，同样保留已成功主班、仅重求备班并 warning。均不把长班拆成多个 MAA 状态。ABC 保留 peak_mood_eta 作参考，中枢、办公室、会客室候选用实际班时与组合净消耗提前检查；已归入其他岗位的成员不得作为普通办公室补位，绑定办公室成员按其 Plan 角色落位。`12/12/12` 实际休班按回满近似，`12/6/6` 原有逐班准入不凭空计入宿舍恢复。`12/12/12` 峰值选体系前，registry 体系若钉死了中枢成员，按“五人满编、不计外部回复”估算这些成员连续工作整班所需心情；撑不满峰值班时长（`12/12/12` 为 24h）的体系整体不入选，`12/6/6`（18h）不受影响。该准入只看体系自己钉死的成员，不替代下节的统一周期心情预算，也不猜测落位后才知道的减免。可选中枢锚点使组合 ETA 不可行时，允许退回其可选角色并重编完整 Plan；required anchor 和已形成的 shift_bind 不在轮换中拆除。机制公式引用知识库，本页只写预算、近似和错误传播。

ABC 当前先尝试生产半区的默认朝向；明确的非生产岗位 ETA 失败后，完整重算另一朝向，让两块既有完整半区交换 α/β 的工作与休息位置。泡泡/火神启用时，其冻结房必须留在 α 半区，朝向重试不得把该组件换派给 β；这可能收窄该源石路径可尝试的朝向。绑定闭包、required anchor 和 reserve 不拆分、不删除，γ 替补、辅助岗位与心情状态重新构建。两朝向均未找到时，才按已确认的可选中枢角色来源重编 Plan；其他错误原样传播。每朝向每次中枢选位仍最多尝试 64 个拒绝名单分支，属于有界近似，预算耗尽不能证明领域无解。两个 ABC profile 均须核查 S3 与下一 S1 同人在岗的预算，不能以 `12/12/12` 休班回满近似豁免首尾连续工作。普通二/三班泛型时序按实际时长把最长班交给 α；ABC 并列最长时休班相位优先落在较短班，确保 α 尽可能覆盖并列最长班。其余班次按输入顺序由 topology 建立轮休状态。`12/6/6` 的 S2/S3 为 6h，不能把“最长班”误写成任一工作班均 12h。

## 泡泡火神源石预占

用户裁决与完整边界见[泡泡火神源石优先](泡泡火神源石优先.md)。当 Box 资格与首个合法三级源石制造房同时满足时，所有本次范围内普通二/三班都建立同房 hard anchors；两人固定属于 α，主备按 1 上 1 休、ABC 按 2 上 1 休消费该绑定。冻结 `RoomId` 随 Plan、切半、普通补位、终态 gate 和 MAA 投影传播；通用 assignment pipeline 只消费显式冻结房 claim，不判断干员身份或拥有产品策略。第三席继续普通制造候选，预占房仅在该显式 claim 下可按合法填充人数短员；短员 warning 不触发 gate 失败。目标房 pair 本身无法完成或后续 pipeline 位移时，schedule owner 保留普通排班并 warning；显式 gate 从最终 assignment 与 Plan anchors 重查并失败。选房同时检查 `level == 3` 与 `capacity >= 3`；容量条件不能替代明确的三级条件。

## 全模式周期心情预算

用户已裁决所有轮换方式、班次数和周期采用同一连续工作检查。检查对象是每班最终 `assignment` 的实际岗位、实际时长和实际中枢组合；最后一班与下一周期第一班相邻，周期结束、换房、换设施或换队伍标签都不恢复心情。中枢、制造、贸易、发电、会客、办公室的净消耗统一由现有 MoodModel 结算，按同一个干员跨设施累计。最终门禁须覆盖每个班次起点的环形连续工作段，并检查初始心情至首个恢复边界的前缀。

中枢心情预算分为两个阶段，不能混用：roster 建立时以初始给定心情、满员中枢 `-0.25/h` 和候选自身已建模中枢技能逐人准入一次；不构造临时完整五人 assignment，也不把班次当前 mood 带回候选筛选。ABC 的自由控制候选在团队归属与非控制岗位预留完成后、建立冻结 `ControlRotationClosure` 前筛选，按其实际归属队伍的完整工作窗口计算：α=`H1+H3`、β=`H1+H2`、γ=`H2+H3`，其中 H1/H2/H3 是本次 ABC 拓扑实际班时；registry 固定成员沿既有 claim roster admission 逐人处理，required 和 `min_count` 成员不会被静默删除。主备等路径在各自 owner 建立 roster 时使用其既有明确时长。排班完成后，公共终态 owner 再以每班实际 assignment、实际班时和真实中枢组合执行一次完整周期预算检查；显式 `--assert-invariants` 仍独立重算该 gate。逐班办公室/会客室 ETA 是各自岗位准入，不属于中枢 roster 筛选。

若最终周期核验发现 Control required 成员或任一 Control requirement group 成员无法支撑目标工作窗口，必须拒绝整份排班候选，并由该路径既有的 roster 重建 owner 从新 roster 重建；不得只删除失败成员、改写 required/`pinned`/`min_count`，或把这份失败候选当成功结果。ABC 仍分别完成 N/A/B 候选层比较；某个候选内的 Control 失败只重建该候选的完整排班，不跳过候选层，也不改变候选顺序、`TOPK`、拓扑或输入班时。逐人 roster 试算是近似准入，不等同于组合级证明或最终周期保证。这里的 requirement group 成员指 Plan/registry 声明的组合 slot 成员，不把普通中枢 filler 的任意周期失败擅自升级成 Control 组合失败。所有替代 roster 耗尽后不得由本节的普通 warning 规则推导出可返回 Control 失败候选；当前 ABC 实现返回独立的 `ControlRotationMoodRetriesExhausted` 错误，不返回被拒候选或 partial success。是否为产品/API 另加可序列化的报告字段属于后续局部设计，不改变本轮的拒绝边界。当前实现进度见[排班模块事实](模块/排班与轮换.md)及[定时轮换调用链](调用链/定时轮换.md)。

离岗一班作为既有连续工作预算的满休边界近似，不证明实际宿舍已入住或回满；ABC `12/6/6` 的休息班按最低等级宿舍基础速率恢复（不叠加技能加成、不假设床位），封顶心情上限；仅 `12/12/12` 的离岗班按满休处理。最终写入的菲亚 `pre` 动作在对应班次消费前重置目标预算，候选或预定动作不算恢复。整轮没有离岗或恢复动作且周期净消耗为正的成员必须拒绝；零净消耗仍可通过心情门禁，并按现有规则保留休班质量诊断。required、bind 或共享角色不豁免心情预算，也不能为通过而静默拆除。

所有耗心情活动必须显式覆盖或明确拒绝未知活动。训练教官是否工作及额外消耗需要训练任务上下文，当前班次没有该活动输入时不得宣称已验证，独立训练副手占用返回不支持活动错误。训练室内没有训练任务的占位（例如莱茵挂件，2026-10-13 用户裁决）不产生小时消耗，加工站同理；二者都不能充当休息回满边界。加工站按加工事件瞬时扣心情，现有定时班次没有加工事件。若增加加工事件，须先接入活动成本 owner 后才能纳入保证。

该检查是 hard constraint，不是排序分数。所有候选在比较收益前均须通过；无菲亚候选被预算拒绝不等于独立的菲亚候选也不合法。Control required/requirement-group 成员的失败按上段整份候选重建，不属于普通 warning fallback；普通 filler 不因仅有 Control pool 身份而获得同一重建出口。非-Control 周期心情失败保持既有边界：候选阶段仍筛选，合法候选优先；若普通候选耗尽，保留完整排班并带 `rotation_final_invariant: rotation_cycle_mood failed: …`（可定位到干员、班次和岗位）warning 返回，交给人工修正，也不声称已证明账号全局无解。没有可保留的排班时，输入非法、无候选等错误仍返回错误。

## 主备 24/24

用户确认的 `main_backup_24_24` 是主班 24h、备班 24h，总周期 48h。CLI 使用 `--rotation 24/24` 或 `main-backup-2424`，Worker v5 使用 `main_backup_24_24`。两个 owner 分别完整求解，通常由主 assignment 已占成员之外生成备班；菲亚开启时，主班最终 Trade 目标会单独回到备班候选池参与正常搜索，不是 required anchor。只有正常 Trade 搜索实际选择并最终落位、且整轮心情/ready/bind 均通过时才接受这种回池结果，否则使用普通互斥备班。两次动作目标不同，各自必须在自己的动作班 TradePost 最终 assignment 内；菲亚上限为两次，不要求必须填满。任何通过门禁的跨班工作仍只可能由实际动作目标触发例外，其他成员按主/备归属互斥。若只有一个动作通过最终检查，warning 报告最终目标、班次、TradePost 与搜索路径；如果宿舍、普通空座或最终 ready finalizer 移除动作，warning 明确报告最终没有动作保留。该警告在共享最终化后读取实际 `TeamRotationReport`，CLI 单列各班目标，回池目标在主备花名册只归入动作班 owner，但逐班工位仍展示真实 assignment。两班各有自己的 Plan、中枢和生产房；daily 用 48h 分母，表示 24h 平均产出。

中枢候选不以完整五人组合做心情筛查。普通单班/主备 owner 在建立候选 roster 时按逐人固定中枢预算筛选；ABC 在建立冻结控制候选目录前，按上述实际队伍归属与整队窗口逐人筛选一次，不按 S1/S2/S3 当前心情重复筛选。required 成员及 `min_count` 候选保持原策略约束，不因预算被静默移除；组合 policy、top-K、顺序不由此改变。Control required/组合成员的最终周期失败按前述整份候选重建；非-Control warning/fallback 继续保持原行为。实际中枢组合的联动、完整周期耗心仅在最终真实 assignment 上由公共周期预算 owner 检查，不能把逐人准入解释为组合级证明或全局无解保证。固定版本知识库《心情与宿舍》“预设换班频次反推”将两班 24/24 与三组连续 48h 区分；运行时继续由现有 `MoodModel` 与实际 assignment 计算，不新增心情公式。

主备与深海 owner 的 Peak Plan registry admission 按当前 owner roster 时长逐人检查固定中枢 claim：named 主备 12/12、24/24 分别使用 12h、24h，generic 主备逐 owner 使用其输入时长，深海主班/替班分别使用 7h/5h。只对 claim 中新增的固定成员逐人采用满员中枢固定减免及其自身已建模中枢技能；不构造完整临时五人组合、不做 contextual combo ETA。含未解析 Search 或无法在 roster 阶段确定的组合联动留待最终真实 assignment 周期检查。ABC 自由控制候选在归属 α/β/γ 后、建立冻结候选目录前，按 α=`H1+H3`、β=`H1+H2`、γ=`H2+H3` 的实际累计工作时长逐人准入一次；之后 `ControlShiftAdmission` 只执行班次 team scope、required、`min_count` 与容量身份约束，不按当前心情二次筛选。普通结果在最终真实 assignment 上执行一次完整周期心情检查；显式 invariant gate 独立复算。Control required/requirement-group 成员周期失败后的整份候选重建不改变候选顺序、top-K、拓扑与班时；普通 filler 不进入这条 Control 组合失败出口，非-Control warning/fallback 保持原边界。当前 ABC 实现的重试耗尽出口是独立 `ControlRotationMoodRetriesExhausted` 错误；产品/API 报告字段是否扩展另行裁决。

普通宿舍仍由相邻班次实际工作差集生成，已有住员优先保留；床位不足产生 warning 并投影 MAA autofill。`DormRestPlan` 专用于固定恢复组，菲亚动作班回宿舍的事实写在最终 assignment，不要求该字段非空。24h 离岗和 autofill 不能证明全部休班成员实际已获得恢复；本模式不声明跨周期宿舍永续保证。菲亚每个状态边界最多一次，24h 内部不增加隐式换班或多动作。MAA 输出两个计划并说明下一计划间隔 24h，动作目标只按最终班次投影，不在导出时重新选人；触发由执行侧配置。

Rust 最终状态门禁的 `main_backup_24_24_topology`、`plan_anchor`、`work_disjoint`、`bind`、`capacity`、`work_budget` 与 `manufacture_work` 核对实际两班、owning Plan 和工作成员；周期权重、菲亚动作/目标/宿舍及休班诊断继续由统一门禁核对。菲亚检查目标必须不同、在各自动作班的 TradePost 实际在岗、对应 Plan 无多成员绑定，并重放菲亚 ready 与目标的完整周期心情；若目标回池后跨班工作，只有实际动作与周期预算共同证明可行才保留。该 profile 也必须通过全模式周期预算；训练室/训练副手缺活动输入明确拒绝，加工站只有占位时按上节边界处理，不声明加工事件或训练任务心情保证。

## 每周期休班底线（目标规则）

任意一个完整定时轮换周期内，实际在工作岗位出勤的每名干员，至少有一班不在工作岗位工作；二班、三班及四班 profile 均按各自完整周期判断。工作状态取每班最终 `assignment` 的实际岗位与状态，涵盖中枢、贸易、制造、发电、会客室、办公室、加工站、训练室普通成员及独立的 `training_assist` 训练副手。宿舍成员不计工作。离岗或进入宿舍可以是不工作，但未在岗不等于已经获得宿舍恢复。队伍标签、候选名单、`shift_bind`、required、pinned 或被称为“挂件”均不能替代实际出勤判断，也不自动获得豁免。

仅有两项具名豁免：实际被选入自动化组合的 Lancet-2，可按该体系的 0 心情发电与加工站去向安排；以及本周期某一班最终确实写入菲亚梅塔心情交换动作的 `target`。只列为菲亚候选、预定目标或体系所需成员不算实际动作目标；其他自动化成员、普通支持位和莱茵挂件没有豁免。详见[自动化组体系](公孙长乐的体系分析文档/AUTOMATION_GROUP_CHAIN.md)和[菲亚梅塔使用规则](菲亚梅塔使用规则.md)。

约束必须对所有 profile 的完整班次最终状态统一核对，包括 Plan 硬锚、shared 成员、后续补位与特殊动作；发现不休班时应能指出干员、各班工作房间及豁免判定，不能靠局部候选过滤或静默改排掩盖。本条休班诊断本身不使求解失败；独立的周期心情预算在候选阶段仍是硬筛选；仅当所有候选都被它拒绝时才降级为 warning 输出，正消耗无恢复因此会被明确标出而不是静默通过。

当前实现由 `finalize_timed_rotation` 在全部班次与宿舍最终落位后统一生成 `rotation_cycle_rest:` 质量诊断，写入 `TeamRotationReport.warnings`。诊断按干员名排序，逐班列出实际工作房间/岗位及无豁免判定。Lancet-2 豁免在每个实际工作班次核对 `plan_index` 对应的自动化入选成员、发电锚点及实际发电/加工站岗位，并要求周期中至少一班在对应发电岗位；其他 owner 的普通 Lancet-2 岗位不能借用该豁免，不凭拥有量、其他分支或仅有 0 心情判定。`--assert-invariants` 的 `rotation_cycle_rest_diagnostics` 从终态重算并核对诊断：漏报、误报、重复或陈旧诊断才是断言失败；整周期工作本身允许带诊断成功返回。这证明诊断与终态一致，不表示排班已经为每个人安排休班或自动修复违规。本条诊断口径不替代现有容量、绑定、恢复和连续工作校验各自的错误传播。

菲亚次数、时机、目标去重由菲亚梅塔使用规则唯一裁决；无人机由 schedule 选择实际赤金制造房；MAA 只投影动作。成功返回 TeamRotationReport。2026-10-19 用户再次明确：不能把质量问题升级成求解错误而拒绝输出。缺员、专用组合未成立、恢复不足、绑定或连续工作违规，以及后置不变量检查，都应保留已生成的排班并给出可定位的 warnings；完整排班尚未生成时应先尝试保留该 profile 班数和时长的普通排班，不静默改成另一个 profile，不伪造缺失的专用组合或菲亚动作。候选阶段仍优先选择满足约束的方案，尽力输出不等于宣布质量合格或证明无解。非法输入、资源损坏/加载失败、未知执行故障和调用者显式启用的 `--assert-invariants` 验收失败须与这类质量诊断区分，不能将验收门禁误当正常产品的拒绝策略。当前迁移状态见活动重构计划。泡泡/火神预占的局部制造完成失败也遵守该输出边界：正常报告保留普通 peak 和 warning，显式 gate 才核对最终预占是否真的成立。

普通工作房间短员是质量诊断，不是结构违规：候选确实耗尽后，最终报告保留缺员 warning，不能再额外标记成“必须满员”的结构错误；`--assert-invariants` 也允许人数低于容量。仍检查不得超容量、重复或非法人员、required/`min_count` 和房间组合约束，并通过 `ordinary_fallback_complete` 确认同一准入策略已无可新增候选。三级制造房未满员本身不再使显式门禁失败。

最终绑定统计与支持 presence 分开：工作成员从最终 assignment 的实际工作岗位重算，宿舍不算工作；Plan 显式 `rest_facility` 只用于判断对应绑定成员是否已离开其绑定工作角色，不改变每周期休班的实际岗位口径。来自同一 Plan 的单向 `active_dependencies` 支持者不因宿舍 presence 被算作绑定工作成员；consumer 实际工作时仍须有 required 支持者实际进驻。普通最终化把真实违规保留为 `rotation_final_invariant: rotation_bind:` warning，不改排；显式 gate 重新核对最终岗位、绑定班数及 profile 拓扑，真实违规才失败。ABC 的非零 on/off 字段分别约束班数，0 表示该项未声明；8/8/4/4 不硬套 ABC 的 2/1。此终态消费检查不代表 Plan 已正确表达所有支持关系、支持设施合法性或 required admission，迁移边界见活动计划 §6.6。

莱茵 `rhine_receivers` 的组班按 2026-10-13 用户裁决：缪尔赛思与选中的岗位支持位在三班模式组成两上一休的班次组，不把 required 支持重复钉成全周期 shared；实际是否工作仍只看最终 assignment 的工作岗位，宿舍中的组员计为休息。娜斯提按效率单独或组合，不因共用规则 ID 自动跟随缪尔赛思组；两班主备只核对主备互斥。领域规则和当前数据边界见[莱茵生命体系论证](公孙长乐的体系分析文档/RHINE_LAB_CHAIN.md)。

不能从上二休一推出“最终基建名单只出现两班”：普通宿舍 finalizer 会把上一班实际工作、本班离岗的成员作为住宿候选。莱茵加工站支持者因此可能两班在加工站、休班在宿舍，既满足实际工作休息口径又有三班 presence；纯宿舍支持者不因提供阵营人数而变成工作人员。2026-10-19 调查、真实反例及 gate 不能证明的范围由[莱茵生命体系论证](公孙长乐的体系分析文档/RHINE_LAB_CHAIN.md) §7.1 记录，不由本页另定休班禁止住宿政策。

## 普通工作岗位补位

用户确认技能选人后的普通工作空位应从当前已裁剪的合法剩余候选尽量补齐，保留 required、绑定、占用唯一性、班次归属、容量与心情资格。2026-10-19 再次明确：所有路径的 fallback 都接收完整 assignment，统一检查中枢、贸易、制造、发电、会客、办公、回收站的剩余席位；无本设施技能不构成普通补位的拒绝理由。技能选人后尚有空位不是结束条件，只有合法普通候选确实用尽后才保留空位并诊断，不因此拒绝产品输出。不允许在收尾或导出时回读全 roster 绕过准入。宿舍不属于普通工作补位目标；没有显式训练、加工任务的训练室和加工站也不参加普通 fallback，只保留 Plan 明确安排的占位。这是产品要求，公共 admission 的迁移状态见活动重构计划，不表示现有各设施已全部实现。
