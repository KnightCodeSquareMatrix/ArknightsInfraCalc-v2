## 会客室、办公室的班次边界规则（2026-11-06 用户澄清）

用户原话：“会客室、办公室这些场所不是ABC轮换，不会切半，就是每一班开始重算心情决定是否换人的。”本段是这两个辅助设施的当前产品裁决，优先于下文历史的全设施“只保留最初 ETA”描述；不据此改变生产队或中枢的既有规则。

会客室、办公室的普通技能岗位不由生产队的 α/β/γ 切半决定出勤。每班开始，应沿用前班工作消耗与实际恢复后得到的当前心情，根据本班实际时长和生效技能判断是否继续上岗或换人。换班不自动回满，同人累计工作 12+6h 本身不能判错；第二班必须基于第一班后的心情判断。克莱门莎按真实精英阶段及同房人数消费技能，见行者也按实际生效技能计算。生产队的累计 Peak 窗口不能替代这两个设施的逐班判断。Plan 绑定与支持 presence 是独立约束，不因本段澄清自动解除。

**普通 ABC 辅助岗位已接入本段规则。** 办公室普通候选消费当前剩余心情和本班时长；会客室移除普通成员的预分队，按实际同房组合试算。辅助候选仅释放生产 Peak 窗口对会客、办公两设施的初始 ETA，不恢复已裁剪的持有人或其他设施资格。构造通过公共宿舍 owner 预览床位；终态检查独立按最终班次名单顺序重放实际岗位净消耗与宿舍恢复，不重新分配宿舍，也不调用候选准入谓词。未显式入住者不假定回复，宿舍技能仍沿用现有模型。普通收尾补位消费同一准入，最后一班还保留每周期至少离岗一次的既有规则。Plan 绑定、required presence 和实际菲亚目标独立处理。实现及验证范围见[排班与轮换模块](模块/排班与轮换.md#辅助设施逐班换人与当前实现差距)与[本轮反馈记录](ARCHIVE/done/七项质量反馈修复-20261107.md)；不据此承诺跨周期永续或 MAA autofill 的实际恢复。

> **2026-10-30 裁决与当前实现：**构造保留已形成的 Plan、岗位和班次；可计算的候选不足、绑定和容量问题由 owner 记录 warning，继续普通完成与真实结算。主备先主后备、ABC 先 peak，N/A/B 保留既有收益目标与平局保留 N。ABC 换半区、中枢 ETA/周期重建和主备撤保守过滤的重试保持删除。终检与导出只读；非法输入、资源/执行故障和显式验收失败仍返回错误。裁决来源见[排班模块重新设计与调查](TODO/排班模块重新设计与调查.md)。

> **本地验证边界：**本次以 `01f2f6d` 为起点完成排班状态与终检修改；最终 release 验证记录见 `target/codex-runs/schedule-state-final/verification-final-manifest.json`。普通泛型时长只覆盖该矩阵及入口探针，部署版本不在本次范围，消费者以实际 Worker wire 为准。

`TimedRotationRequest` 承载 named timings 与普通二/三班 topology timing。CLI `--rotation main-backup@H1/H2`、`--rotation abc@H1/H2/H3` 和 Worker `plan.compute` v7 的 `{topology, shift_hours}` 对象进入同一时长驱动的周期与终态流程；班次顺序保持调用方输入。前端负责拒绝不合法组合，本轮没有增加后端时长业务约束。旧 named timings 的求解语义不变：abc_12_6_6、abc_12_12_12、main_backup_12_12、main_backup_24_24、fiammetta_8_8_4_4、abyssal_7_5_7_5。Worker v1–v6 schema 与 wire 含义不变，v6 继续是闭集。独立龙巫二班已删除；旧 `fiammetta_witch_12_12`、`fiammetta-witch-1212` 和 `witch-1212` 请求明确失败，不映射或降级成普通主备。

**时长数值安全与业务组合分开：**generic CLI 解析与共享 core 请求入口在搜索前拒绝非有限、非正、按现有分钟权重舍入后不足一分钟、或超过整数权重算术安全域的时长。每班舍入分钟数、这些分钟数之和与实际周期小时换算的舍入分钟数均不得超过 `i64::MAX / (i32::MAX + 2)`（4,294,967,294 分钟）。这为 `Efficiency::scale_ratio` 的乘法和正负舍入保留余量，不是新增总周期或时长组合政策；例如 `10/15` 不因总计 25h 被后端拒绝。非法数值走 `rotation_duration_input:` 输入错误，不降为质量 warning。共同 finalizer 与显式 gate 也从实际 `shifts[].duration_hours` 重查，gate 使用稳定前缀 `assert-invariants rotation_duration_input:`。合法数值不保证心情可行，后续心情不足保留质量warning，显式gate核对提示准确性。

当前普通主备 topology 保持两个完整 owner 状态与工作成员互斥；ABC topology 保持三队、每班两队工作一队休息。普通泛型请求的周期由调用方限制为 24h、36h 或 48h；班次仍按输入顺序承载实际时长。α 映射到最长班；ABC 并列最长时把休班相位放在较短班，尽量覆盖全部可覆盖的并列最长班，完全等长时保留旧相位。泛型班次超过 12h 时该班最多生成一次菲亚动作，动作仍受 ready、目标去重和最终 assignment 核对；旧 named timing 的动作槽位不变。v7的generic与named 24/24均保留实际班长的最初中枢ETA筛选，不再使用姓名黑名单；泛型超过 24h 使用输入的实际班长。四班菲亚 `8/8/4/4` 与深海 `7/5/7/5` 继续走原专用路径。完整决策见 [ADR 0011](ADR/0011-generic-two-three-shift-rotation.md)；求解保证仍是既定 facility policy 下的求解，不宣称全局最优。

**主备与 ABC 的连续工作前提不同：**主备两班除最终实际接受菲亚交换的目标外，工作成员必须严格不重复；宿舍 presence 不算重复工作。普通成员每周期最多上一班，不存在 ABC 式同人连上两班或末班接首班的累计工作情形。菲亚目标复用只按其专用动作、ready与绑定规则接受，完整周期预算只诊断。不得从 ABC 的跨班累计问题推导出主备必须新增替代 roster 或周期失败重试；最初中枢名单时长试算和公共最终诊断继续保留。

用户于 2026-10-23 明确普通泛型 ABC 同样使用菲亚 N/A/B 候选层。每个候选共享调用方实际班时，分别完整重求解；generic ABC 先按 α 相位排序构造，候选完成后将含 `duration_hours`、assignment 和动作的整个班次恢复为输入顺序，再完成最终化与收益比较。候选 winner 仍按[菲亚候选策略](菲亚梅塔候选分支适配层设计.md)的 `daily.production` value 选择，平局保留 N；源石 pair 和 ABC 轮休不是候选变量。普通泛型主备与四班专用 profile 不进入该候选层。

生产 half、cohort 与动作索引仍使用 α 相位；班次组装按调用方输入时间顺序遍历，使办公室、会客室从真实首班的初始心情开始，依次消费工作与显式恢复。构造结束先恢复 phase 排列供动作适配层消费，再由该层恢复完整输入班序。最后一班的普通辅助休班约束也按输入位置判断。

生成顺序为：timing/topology 解析 → owner/peak assignment → 周期班次、Plan dependency/shift_bind → 各设施选人与补位 → 动作候选 → `prepare_rotation_state` 提交岗位、宿舍、transition、无人机和动作 → `finalize_timed_rotation` 读取定稿状态结算 → 同一只读问题集合 → CLI/profile/MAA 输出。普通 ABC 的报告初值评分和 daily 重复汇总已删除；专用候选试算与四班续班评分保留。

生产设施与中枢保留最初 ETA roster 试算，制造/贸易/发电后续工作预算筛选继续删除；办公室、会客室按上文当前裁决逐班准入。主备每个 owner 使用各自实际班长建立中枢名单；ABC 按归属队伍累计窗口首次冻结，不再逐班筛中枢心情。Plan required、绑定、容量、身份与技能排序保留；负心情差制造成员不再因长班被排除，正式积分仍按实际窗口和心情结算。保留 peak_mood_eta 作参考；生产与中枢的最终周期消耗只诊断，不重编 Plan 或撤预算重试。

ABC 保留默认生产半区与 α/β/γ 归属，不因非生产岗位 ETA 或最终周期心情问题换向、重组中枢或重编完整候选。泡泡/火神冻结房仍归 α。正常菲亚 N/A/B 各自构造并完成后按既有收益目标比较；独立的四赤金 required 中枢超容量回退继续保留，不属于本次删除的心情补救。两个 ABC profile 仍核查 S3 与下一 S1 的同人连续工作，`12/12/12` 的休班回满近似不豁免首尾；泛型时长和 α 相位继续按原拓扑计算。

## 泡泡火神源石预占

用户裁决与完整边界见[泡泡火神源石优先](泡泡火神源石优先.md)。当 Box 资格与首个合法三级源石制造房同时满足时，所有本次范围内普通二/三班都建立同房 hard anchors；两人固定属于 α，主备按 1 上 1 休、ABC 按 2 上 1 休消费该绑定。冻结 `RoomId` 随 Plan、切半、普通补位、终态 gate 和 MAA 投影传播；通用 assignment pipeline 只消费显式冻结房 claim，不判断干员身份或拥有产品策略。第三席继续普通制造候选，预占房仅在该显式 claim 下可按合法填充人数短员；短员 warning 不触发 gate 失败。目标房 pair 本身无法完成或后续 pipeline 位移时，schedule owner 保留普通排班并 warning；显式 gate 从最终 assignment 与 Plan anchors 重查并失败。选房同时检查 `level == 3` 与 `capacity >= 3`；容量条件不能替代明确的三级条件。

## 全模式周期心情预算

用户已裁决所有轮换方式、班次数和周期采用同一连续工作检查。检查对象是每班最终 `assignment` 的实际岗位、实际时长和实际中枢组合；最后一班与下一周期第一班相邻，周期结束、换房、换设施或换队伍标签都不恢复心情。中枢、制造、贸易、发电、会客、办公室的净消耗统一由现有 MoodModel 结算，按同一个干员跨设施累计。最终门禁须覆盖每个班次起点的环形连续工作段，并检查初始心情至首个恢复边界的前缀。

中枢初始名单用给定心情、满员中枢-0.25/h与候选自身技能逐人试算。主备等owner建池时使用各自窗口；ABC在归属完成、closure冻结前按α=H1+H3、β=H1+H2、γ=H2+H3筛一次。初始Plan Rule/registry沿既有入口；后续动态producer、组合、逐班、办公室/会客室、普通补位不再做心情准入。终态周期owner以实际assignment和时长结算质量诊断，gate独立核对提示准确性。

最终周期发现心情不足时保留已完成排班与`rotation_final_invariant: rotation_cycle_mood:` warning，包括required、group与绑定成员。心情不足本身不使普通输出或显式gate失败；漏报、误报、重复或陈旧提示使gate失败。最初试算并非真实组合或完整周期的完备证明。

终态周期诊断沿既有离岗满休近似，不证明实际宿舍已回满。最终菲亚pre动作在当班消费前重置目标预算，预定动作不算恢复。整轮无离岗/恢复且有正消耗时明确报告；零消耗仍可保留休班诊断。ABC逐班心情状态仅参与正式数值结算，不再用于准入。

所有耗心情活动必须显式覆盖或明确诊断未知活动。训练教官是否工作及额外消耗需要训练任务上下文，当前班次没有该活动输入时不得宣称已验证，独立训练副手占用产生不支持活动诊断；普通最终报告保留warning，显式gate核对提示准确性。训练室内没有训练任务的占位（例如莱茵挂件，2026-10-13 用户裁决）不产生小时消耗，加工站同理；二者都不能充当休息回满边界。加工站按加工事件瞬时扣心情，现有定时班次没有加工事件。若增加加工事件，须先接入活动成本 owner 后才能纳入保证。

2026-10-31 用户最新裁决：只保留最初 ETA roster 试算；后续搜索、组合、补位、逐班和动作候选不再按工作心情预算筛选或拒绝。心情净消耗、暖机与心情差积分仍按真实状态结算；终态心情不足保留质量 warning。显式 gate 核对该 warning 与实际终态是否一致，结构、Plan、绑定和动作事实仍独立验收。本次删除属于 policy，不是 safe reduction，不证明全局最优。

## 主备 24/24

用户确认的 `main_backup_24_24` 是主班 24h、备班 24h，总周期 48h。CLI 使用 `--rotation 24/24` 或 `main-backup-2424`，Worker v5 使用 `main_backup_24_24`。两个 owner 分别完整求解，通常由主 assignment 已占成员之外生成备班；菲亚开启时，主班最终 Trade 目标会单独回到备班候选池参与正常搜索，不是 required anchor。只有正常 Trade 搜索实际选择并最终落位、且ready/bind均通过时才接受这种回池结果，否则使用普通互斥备班。两次动作目标不同，各自必须在自己的动作班 TradePost 最终 assignment 内；菲亚上限为两次，不要求必须填满。任何通过门禁的跨班工作仍只可能由实际动作目标触发例外，其他成员按主/备归属互斥。若只有一个动作通过最终检查，warning 报告最终目标、班次、TradePost 与搜索路径；回池候选在完整岗位、宿舍和普通补位完成后核对ready与bind；成立后保留同一组动作和构造维护的 Team，不从宿舍住员并集重建队伍，不在终检删动作。未成立使用既有普通互斥备班。该警告在共享最终化后读取实际 `TeamRotationReport`，CLI 单列各班目标，回池目标在构造花名册只归入动作班 owner，CLI 按该归属展示，逐班工位仍展示真实 assignment。两班各有自己的 Plan、中枢和生产房；daily 用 48h 分母，表示 24h 平均产出。

中枢候选不以完整五人组合做心情筛查。普通单班/主备 owner 在建立候选 roster 时按逐人固定中枢预算筛选；ABC 在建立冻结控制候选目录前，按上述实际队伍归属与整队窗口逐人筛选一次，不按 S1/S2/S3 当前心情重复筛选。required 成员及 `min_count` 候选保持原策略约束，不因预算被静默移除；组合 policy、top-K、顺序不由此改变。所有最终周期心情问题保留为 warning，不重建 ABC 中枢或撤掉主备过滤。实际中枢组合的联动、完整周期耗心仅在最终真实 assignment 上由公共周期预算 owner 检查，不能把逐人准入解释为组合级证明或全局无解保证。固定版本知识库《心情与宿舍》“预设换班频次反推”将两班 24/24 与三组连续 48h 区分；运行时继续由现有 `MoodModel` 与实际 assignment 计算，不新增心情公式。

主备与深海的初始Peak Plan中枢Rule/registry入口仍使用所属工作窗；Search可选者在尚未认领时试算并核对min_count。普通中枢建池作首次ETA筛选，ABC归属后冻结一次。动态producer required承诺、满pin快捷路径和后续补位不再复筛预算。深海宿管按实际恢复量排序，不按能否回满筛掉组合；只有身份/占用/床位不足才不形成DormRestPlan。

普通宿舍仍由相邻班次实际工作差集生成，已有住员优先保留；床位不足产生 warning 并投影 MAA autofill。`DormRestPlan` 专用于固定恢复组，菲亚动作班回宿舍的事实写在最终 assignment，不要求该字段非空。24h 离岗和 autofill 不能证明全部休班成员实际已获得恢复；本模式不声明跨周期宿舍永续保证。菲亚每个状态边界最多一次，24h 内部不增加隐式换班或多动作。MAA 输出两个计划并说明下一计划间隔 24h，动作目标只按最终班次投影，不在导出时重新选人；触发由执行侧配置。

## 每周期休班底线（目标规则）

任意一个完整定时轮换周期内，实际在工作岗位出勤的每名干员，至少有一班不在工作岗位工作；二班、三班及四班 profile 均按各自完整周期判断。工作状态取每班最终 `assignment` 的实际岗位与状态，涵盖中枢、贸易、制造、发电、会客室、办公室、加工站、训练室普通成员及独立的 `training_assist` 训练副手。宿舍成员不计工作。离岗或进入宿舍可以是不工作，但未在岗不等于已经获得宿舍恢复。队伍标签、候选名单、`shift_bind`、required、pinned 或被称为“挂件”均不能替代实际出勤判断，也不自动获得豁免。

仅有两项具名豁免：实际被选入自动化组合的 Lancet-2，可按该体系的 0 心情发电与加工站去向安排；以及本周期某一班最终确实写入菲亚梅塔心情交换动作的 `target`。只列为菲亚候选、预定目标或体系所需成员不算实际动作目标；其他自动化成员、普通支持位和莱茵挂件没有豁免。详见[自动化组体系](公孙长乐的体系分析文档/AUTOMATION_GROUP_CHAIN.md)和[菲亚梅塔使用规则](菲亚梅塔使用规则.md)。

约束必须对所有 profile 的完整班次最终状态统一核对，包括 Plan 硬锚、shared 成员、后续补位与特殊动作；发现不休班时应能指出干员、各班工作房间及豁免判定，不能靠局部候选过滤或静默改排掩盖。本条休班诊断本身不使求解失败；周期心情预算不再参与候选筛选。包括 Control required/group 在内的最终周期问题均保留 warning，不丢弃已完成排班。正消耗无恢复因此会被明确标出而不是静默通过。

当前实现由 `finalize_timed_rotation` 在全部班次与宿舍最终落位后统一生成 `rotation_cycle_rest:` 质量诊断，写入 `TeamRotationReport.warnings`。诊断按干员名排序，逐班列出实际工作房间/岗位及无豁免判定。Lancet-2 豁免在每个实际工作班次核对 `plan_index` 对应的自动化入选成员、发电锚点及实际发电/加工站岗位，并要求周期中至少一班在对应发电岗位；其他 owner 的普通 Lancet-2 岗位不能借用该豁免，不凭拥有量、其他分支或仅有 0 心情判定。`--assert-invariants` 的 `rotation_cycle_rest_diagnostics` 从终态重算并核对诊断：漏报、误报、重复或陈旧诊断才是断言失败；整周期工作本身允许带诊断成功返回。这证明诊断与终态一致，不表示排班已经为每个人安排休班或自动修复违规。本条诊断口径不替代现有容量、绑定、恢复和连续工作校验各自的错误传播。

菲亚次数、时机、目标去重由菲亚梅塔使用规则唯一裁决；无人机由 schedule 选择实际赤金制造房；MAA 只投影动作。成功返回 TeamRotationReport。2026-10-19 用户再次明确：一般质量问题不升级成求解错误，缺员、专用组合未成立、恢复不足、绑定或后置不变量问题按既有边界保留诊断；2026-10-30 用户进一步取消 Control 心情失败的例外，所有最终周期问题均保留为 warning。完整排班尚未生成时应先尝试保留该 profile 班数和时长的普通排班，不静默改成另一个 profile，不伪造缺失的专用组合或菲亚动作。候选阶段仍优先选择满足约束的方案，尽力输出不等于宣布质量合格或证明无解。非法输入、资源损坏/加载失败、未知执行故障和调用者显式启用的 `--assert-invariants` 验收失败须与这类质量诊断区分，不能将验收门禁误当正常产品的拒绝策略。构造内部使用私有草稿，公共 `TeamRotationReport` 只在完成和真实结算后返回。泡泡/火神预占的局部制造完成失败也遵守该输出边界：正常报告保留普通 peak 和 warning，显式 gate 才核对最终预占是否真的成立。

普通工作房间短员是质量诊断，不是结构违规：候选确实耗尽后，最终报告保留缺员 warning，不能再额外标记成“必须满员”的结构错误；`--assert-invariants` 也允许人数低于容量。仍检查不得超容量、重复或非法人员、required/`min_count` 和房间组合约束，并通过 `ordinary_fallback_complete` 确认同一准入策略已无可新增候选。三级制造房未满员本身不再使显式门禁失败。

最终绑定统计与支持 presence 分开：工作成员从最终 assignment 的实际工作岗位重算，宿舍不算工作；Plan 显式 `rest_facility` 只用于判断对应绑定成员是否已离开其绑定工作角色，不改变每周期休班的实际岗位口径。来自同一 Plan 的单向 `active_dependencies` 支持者不因宿舍 presence 被算作绑定工作成员；consumer 实际工作时仍须有 required 支持者实际进驻。普通最终化把真实违规保留为 `rotation_final_invariant: rotation_bind:` warning，不改排；显式 gate 重新核对最终岗位、绑定班数及 profile 拓扑，真实违规才失败。ABC 的非零 on/off 字段分别约束班数，0 表示该项未声明；8/8/4/4 不硬套 ABC 的 2/1。此终态消费检查不代表 Plan 已正确表达所有支持关系、支持设施合法性或 required admission，迁移边界见活动计划 §6.6。
