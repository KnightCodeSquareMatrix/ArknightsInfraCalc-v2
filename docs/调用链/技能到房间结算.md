## 主链

```text
CLI/library input
 -> OperBox + blueprint validation
 -> PromotionTier + OperatorInstances binding
 -> SkillTable buff_id -> EffectAtom / L2 marker
 -> facility pool
 -> Plan/assignment + used
 -> resolve_base snapshot
 -> domain interpreter (L1)
 -> domain mechanism (L2)
 -> actual-combination shortcut (L3 trade)
 -> Result/breakdown -> assignment snapshot/profile/rotation/export
```

Plan 先处理 required anchor、claims、dependencies、exclusions；pipeline 每推进一段 assignment 就可重新 resolve。房间 solver 只结算实际进驻组合；CLI/export 只格式化结果。

贸易叶搜索接收整基建resolve快照，构造候选房输入时先投影候选，再对原贸易名单中已存在的候选扣回已计入快照的Global StateProduce。扣回使用resolve的共同实现，随后L1执行该房贡献一次；尚未进驻的候选直接在房内首次产生贡献。最终assignment的房间resolve仍按实际成员执行同一扣回。此输入边界防止预占黑键/乌有的搜索效率高于最终房间结算，详见[贸易求解](../模块/贸易求解.md#搜索与跨站)。

| 症状 | 先读的链路 |
|---|---|
| 有干员没有技能 | input→tier→instances→skill table→pool |
| 池里有但没入房 | Plan/used→fill→search comparator |
| 单房效率错 | snapshot→L1→L2/L3→breakdown |
| 单房对、多房错 | resolve→global manifest→next-stage input |
| MAA 字段错 | 先验证 assignment/rotation，再读 export |

验证：单房用 `trade yield`/bench/layout eval；全链用 `plan` 或 `serve plan.compute`；高风险修改运行最终 invariant gate。机制数字只从知识库桥接读取。
