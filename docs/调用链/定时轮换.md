           ├─ run_user_rotation_probe_with_profile_and_preferences

## ABC 候选链

ABC profile 首先判断菲亚候选资格：

1. 生成不使用菲亚的 N 候选。
2. A（但书/可露希尔）具备资格时，用同一 solver 重新求解 A，并附加目标动作。
3. B（巫恋/龙舌兰/合法裁缝）具备资格时，用同一 solver 重新求解 B。
4. 每个候选都调用 complete_timed_rotation，在完整周期与特殊宿舍保护后统一补普通工作空座，再由 finalize_timed_rotation 落普通宿舍、重算效率并校验绑定、逐班 ETA 和全设施周期预算。N 被明确周期预算拒绝时仍继续独立 A/B，输入或内部错误直接传播；A/B 只允许已识别的候选可行性失败降级。
5. 用固定候选价值比较合法 N/A/B；合法 N 在严格平局时优先。没有合法候选返回错误，不把 N 的预算拒绝理解为 A/B 或账号全局无解。

候选只通过 system_preferences、gamma_relaxed 和动作附着影响同一完整求解流程；不预排 seed、不锁房、不把目标直接塞回已有 assignment。ABC 在已选可选中枢角色无法覆盖实际班次时，可由轮换提出角色来源，Plan 仅跳过该可选候选并完整重编；这是有界候选降级策略，不是穷尽全局组合的最优性证明。

`schedule_abc_rotation` 先按默认半区朝向调用 `schedule_abc_rotation_once`；只有明确的非生产 ETA 失败才尝试另一朝向。后者在 `split_production_facilities` 保持绑定闭包和 reserve 的切分之后交换完整 H1/H2，再重新构建 γ、所有 cohort 和逐班心情。两朝向均 ETA 失败时才按收集的可选中枢角色三元组重编 Plan；普通机制、容量、绑定及后处理错误原样传播。每朝向中枢拒绝名单搜索仍最多 64 分支，未找到不等于 canonical 无解。

## 状态阶段

    owner/peak assignment
      → assignment_plans（Plan owner）
      → H1/H2 或 profile 专用状态
      → shift_bind 对齐与 runtime dependencies
      → ControlRotationClosure 冻结候选身份、cohort、scope、required/group
      → 当班 ControlShiftAdmission → 中枢/办公室/会客室补位
          └─ room_admission.rs：候选试算、ETA/mood budget 公共 helper
      → 菲亚、无人机、特殊 dorm_rest
      → complete_timed_rotation
           ├─ finalize_shift_dorms（保护专用占用）
           └─ fill_rotation_vacancies → layout::fill_workplace_vacancies
                └─ 七类工作设施、完整 assignment、已裁剪候选、归属/心情准入
      → finalize_timed_rotation
           ├─ dorm_finalizer::finalize_dorms（试算后提交）
           ├─ 菲亚 ready 重放 / 筛除，必要时恢复普通 transition 与无人机
           ├─ 每班效率快照与 weighted 值
           ├─ shortfall / dorm / 保留的质量 warnings
           ├─ rotation_cycle_rest_warnings（最终出勤与具名豁免）
           ├─ cycle_mood::validate_cycle_mood（全模式首尾与跨设施连续预算）
           └─ profile/shift-bind/连续工作 invariant

普通补位不回读全 roster，不扩大训练/加工/宿舍范围；回收站不再有独立收尾补位。对最终状态的 `ordinary_fallback_complete` 重放只证明当前补位 policy 的稳定性，不证明任意换队、拆绑定或重排技能组合后的全局最优。

TeamShiftResult 是单班最终状态：index、plan_index、duration_hours、active_teams、resting_team、assignment、可选 fiammetta、可选 dorm_rest、可选 drone、transition、三类效率和加权值。TeamRotationReport 还保留所有独立 assignment_plans，排查时先看 shift.plan_index，再追相应 Plan owner。

## 快照、轮休与写入

- ABC：生产房切 H1/H2；α 跑 H1、β 跑 H2，γ 为替补。S1=α+β、S2=β+γ、S3=γ+α；γ/α/β 分别在 S1/S2/S3 休息。
- ABC 的中枢、办公室、会客室在当班组装时使用同一逐班心情状态；中枢五人组合失败时尝试已冻结 admission 内的替换。普通办公室候选排除已预留给生产、中枢及轮换会客等角色的成员，绑定办公室成员仍由 Plan 角色落位。两个 ABC profile 均在 S3 预留下一周期 S1 消耗；当前代码只对 `12/12/12` 的离岗班使用满休近似，`12/6/6` 逐班准入按最低等级宿舍基础速率估算恢复。用户已裁决的统一目标是每班结束更新心情、在岗扣消耗、不在岗近似回满，因此 `12/6/6` 当前逐班准入与该目标尚未一致；实现差距不能由本页的代码描述替代裁决。最终 Rust gate 先核对菲亚动作策略，再重算所有六类持续工作岗位的首尾与跨设施预算；原有非生产逐班 ETA 保留更严格准入，不能代替统一周期 owner。
- main_backup_12_12：主、替各自完整求解；主 assignment 工作成员进入替班禁用集合；中枢分别求解，不使用 ABC 半区。
- main_backup_24_24：主、替各自完整求解；主 assignment 全部已占成员进入替班禁用集合。`schedule_main_backup_24_24` 设置 `control_work_hours=Some(24)`；`prepare_peak_control_candidate` 试放完整中枢组合，使用现有 contextual ETA 在 top-K 前过滤，满五人路径同样检查。两个状态各运行 24h，办公室和会客室使用 24h ETA，生产搜索使用同一工作窗口；最终门禁重新检查 actual assignment，不拆成班内 MAA 状态。required 组合找不到可行填充时返回策略内求解失败，不删除必选锚点。

  当前实现仍在进入该 profile 时调用 `filter_operbox_for_24_24`，按姓名预先移除一组干员；这与“ETA、连续工作和制造 mood-gap 作为统一资格 owner”的 active-change 目标不是同一事实。`prepare_peak_control_candidate` 的 ETA 只覆盖它试放的中枢组合，制造候选已有 `manufacture_combo_allowed_for_shift`，最终 assignment 还有 `main_backup_24_24` 终态检查；三者尚未收敛为一个候选策略。该差异已记录在 `docs/TODO/排班行为等价验证矩阵.md`，本页不把目标写成已完成。
- 独立龙巫二班已从产品支持中删除；普通菲亚候选分支仍按原 ABC 规则运行，不能视为该独立双 owner profile 的映射。
- fiammetta_8_8_4_4：前段两个 8h，菲亚边界动作单独标记；FiammettaOnly 对完整编制分别结算 8h/16h，目标房保留前段值，其他房间按差值结算续段，不等同于只重放目标房。
- abyssal_7_5_7_5：7h 主班、5h 恢复、7h 替班、5h 恢复；DormRestPlan 固定同一宿舍的目标、单回宿管、群回宿管。

dorm_finalizer::finalize_dorms 以相邻班次实际非宿舍工作差集 previous_work - current_work 得到普通休息成员。已有宿舍住员和特殊 DormRestPlan 先保护，再按容量写入；床位不足返回 warning，不偷偷改岗位。特殊组重复、房间不是宿舍、超容量或成员不存在时，finalizer 保留试算前的 assignment 并记录结构诊断，不丢弃整份排班。普通宿舍写入在最终 ready 与评分前完成，评分消费最后提交的 assignment。

宿舍最终落位后，rotation_cycle_rest_warnings 只读取最终非宿舍岗位和训练副手，跨完整周期统计出勤；只有本周期实际自动化 Lancet-2 和最终菲亚动作目标豁免。结果追加到 report.warnings，`rotation_cycle_rest_diagnostics` 重算并检查同前缀诊断是否完全一致；不休班本身不阻断正常结果或 MAA。

所有 profile 最终化后统一调用 `schedule/cycle_mood.rs`，以现有 contextual ETA 按人累计。实际加工站和训练室占位保留工作连续性但无小时成本；独立训练副手缺活动输入明确拒绝。每个起点循环扫描覆盖末班到首班，整轮无恢复正消耗拒绝，初始前缀只使用调用者心情。此处的离岗满休是连续预算近似，不是宿舍恢复证明；制造技能心情落差的连续制造限制由原专用 owner 独立核验。

## 错误与输出

- 普通工作设施候选不足不回退到全 roster；无 anchor 制造 fallback 保留当前池合法的 0..N 人而非直接报错。TeamRotationReport.warnings 从终态生成班次、设施、房间和缺额；训练室、加工站及宿舍不在该普通补位诊断内。
- 逐班中枢 admission 在周期构造阶段允许少于容量，但仍验证唯一身份、活跃队伍准入、真实练度、required 与 `min_count`；整周期普通补位再为中枢尝试补空位。容量超过上限或违反身份/required 仍拒绝该候选。最终公开 invariant 核验中枢不超容量，并由 `ordinary_fallback_complete` 证明同一合法候选策略已耗尽；仍有可加入成员才是断言失败，短员本身保留 warning，不使 gate 失败。贸易、制造、发电及三级制造房采用相同的短员边界，同时继续检查超容量与制造同房兼容。
- 整周期无休班以 `rotation_cycle_rest:` warning 列出干员、逐班工作岗位及豁免判定；CLI 和 Worker 沿现有 warnings 输出，MAA 保留最终岗位与菲亚指令。
- 真实 shift_bind 成员 ETA 不足时不能在轮换中拆成普通候选；只有 Plan 自身确认的 `min_count=0` 中枢角色可作为候选降级，随完整 Plan 重编重新解析绑定。其他无替代的必选成员继续报错。
- 所有菲亚入口通过 `schedule/fiammetta_events.rs` 在完整事件时间线上试放，不同目标共用菲亚预算。普通目标和 ABC 分支只提交 ready 动作；固定龙巫提议路径已删除。普通最终化在宿舍和工作岗位落定后筛除失去 ready 的动作；无动作的 FiammettaOnly 转普通班次，恢复普通无人机动作并按终态重新评分，而不是拒绝整份排班。显式 Rust gate 以 `fiammetta_ready` 从最终 assignment 重放。无动作不产生 ready 违规。目标顺序、绑定和保留动作的 8/8/4/4 专用评分不变。
- 深海专用组合不足在构造处用具名 `ProfileOwnerCandidate::Unavailable` 与执行错误分离，走保留 7/5/7/5 的普通 owner；专用宿舍恢复不足不写未经证明的恢复组。profile 结构和制造连续工作等后置质量检查追加 `rotation_final_invariant:` warning。`schedule_timed_rotation` 最外层仍只恢复已识别预算拒绝且携带完整 partial rotation 的错误，保留 ABC 合法候选优先的原筛选；资源、计算、不支持活动等错误不被统一吞掉。公共终态 gate 的正常产品错误仍降为诊断；CLI/Worker 显式验收再次检查真实终态，失败返回错误，不能将其统计为正常产品拒绝。派生 shortfall/dorm/rest warning 完整性比较不包含自由文本的 `rotation_final_invariant:`，实际容量、绑定、ETA 和 ready 检查不因此跳过。
- plan_compute 保留失败阶段和 partial rotation；MAA 只有轮换完成后才生成。

## 排查顺序

先确认入口解析出的 profile；再看 TeamRotationReport.profile、shifts[].plan_index、transition、assignment、runtime_shift_binds、dorm_rest 和 warnings；最后用 --assert-invariants 检查最终状态。若只错 MAA，沿 MAA 导出调用链排查，不反查 solver 规则。

## 绑定闭包与跨半区交换

shift_binds_from_plan 读取每个 AssignmentPlan 的 exact-presence dependency 和显式 shift_binds，排序去重后合并重叠集合。它不会从 roster 或 buff 名称猜 bind。align_shift_binds_in_halves 选一个已在 half 的 anchor，把同组 wanderer 的 trade/manu/power room 与另一 half 的同类 room 交换；没有可交换房间时不伪造对齐，后续 invariant 会报告 bind 不属于完整 team。

最终 `validate_final_bind_cycle` 从 `assignment_plans` 重建绑定，合入 runtime-only bind，并冻结各组来源 Plan。它按 `work_position_operator_names` 重算工作向量，宿舍不算工作；Plan anchor 或 registry slot 声明的宿舍支持与工作核心分开，核心实际工作时支持须实际进入任意宿舍。另有同 Plan 的单向依赖 required support 不进入 exact 工作向量，receiver 实际工作时用真实房间 presence 检查支持缺席。显式 `rest_facility` 只区分该绑定角色的休息去向，训练/加工普通占位与 training_assist 的独立实际出勤口径不变。两个及以上工作成员的组在 ABC 核对非零 on/off，其他 profile 使用既有 active_teams 拓扑，8/8/4/4 不复用 2/1 班数。无工作核心的纯宿舍组不伪造班数；分类后只剩单个 receiver 的单向支持关系不套 exact 工作组班数，本单元不宣称完整覆盖所有绑定。普通 finalizer 将错误追加为 `rotation_final_invariant: rotation_bind:`，显式 gate 从最终报告重算并返回错误，不消费 warning 作为证据。

候选试放仍使用原 `validate_final_rotation_invariants`，本轮未改候选筛选或排序；旧公开 helper `verify_shift_binds` 目前不在产品主终验路径，不能用于声称终态工作统计已统一到所有 helper。办公室的 bound_operator_names 仍用原闭包排除普通补位，避免绑定成员被 office fallback 拆开。Plan exact 闭包夹带单向支持、支持设施合法性与所有 required admission 的完整证明仍待后续 owner 迁移，不能从本次 gate 推导已完成。

## 支持角色到最终评分的状态流

主动挂件组合关闭时不会生成 `rhine_support` role；显式开启后，规则编译器按 role 的候选顺序解析实际成员与可用设施。每个已选 role 成员在候选 Plan 形成时就写入候选 assignment、`used` 与 anchor；所有声明 role 落位后才执行该 alternative 的 domain completion / competitive 比较。因此当前观察到的是**先承诺并占位、再比较**，不是通用延迟绑定池。

`score_completed_manufacture`、`score_completed_power` 分别消费比较分支的候选 assignment 和已占人员集合，也重算未添加该 alternative 的 baseline。已承诺支持者若在对应 assignment 中，会像其他已占位成员一样影响后续可选人和完整房间评分；这不证明存在 receiver/support claim 的通用候选遍历。支持位的产品设计仍未授权改变。

菲亚候选试放读取各班当前 assignment 生成 ETA，复制 shift 列表并只增试放的 action；验证成功后写回 action 字段，不替换 receiver、支持位或房间 assignment。公共 finalizer 先让普通宿舍落位并筛除不 ready 的 action，然后从最终 assignment 重算普通班效率、8/8/4/4 续段和周期权重。最终宿舍中的普通休息者不回填成 Plan 支持 claim。

样例观察留证：`target/codex-runs/rotation-support-investigation-20261019/observations/support-trace-summary.json`。它来自 243 + `b-073-415`、ABC 12/6/6、主动挂件开启、显式 gate 的隔离日志插桩 release；在 44 条观测中记录了 Plan 已选支持者、比较输入、菲亚试放及 finalizer 前后的 assignment。它只证明该输入下的阶段状态，不证明所有 profile 或所有候选都一致。

另有未裁决的 Plan bind 冲突：莱茵 current canonical 规定支持位不进 exact `ShiftBind`，而 `rhine_receivers` 的三个 alternative 都配置 `bind_all:true`，通用编译器对所有入选 anchors 构造 bind。当前终态 bind gate 会把 `active_dependencies.required` 从工作核心统计剔除，但跨房团队归属和 anchor 轮换仍消费整个 bind。未获用户裁决前不改 Plan 生成或 rotation 归属。
