当前普通二班/三班使用有序时长进入 topology-specific 周期构造；四班菲亚/深海保持专用路径；适用的泡泡/火神 pair 在所有普通二/三班预占到 α。普通泛型菲亚每个超过 12h 的班次最多一次动作；ABC 并列最长时休班相位放在较短班；自定义 >24h 按实际 ETA/心情准入。周期由前端限制为 24h、36h 或 48h。本次本地验收覆盖固定矩阵中的具名模式与两种泛型时长、Worker v7 及输入错误边界；不证明所有自定义时长组合。

## 入口与分派

    infra-cli plan
      ├─ timed_rotation_request_from_args / current Worker v1–v7 schema decode (v7 WIP)
      ├─ 资源加载：BaseBlueprint / OperBox / OperatorInstances / SkillTable
      └─ compute_plan
           ├─ run_user_rotation_probe_with_request_and_preferences

           ├─ （可选）assert_final_rotation_invariants_for_request（消费请求的 fiammetta_enable）

           └─ （可选）build_from_team_rotation → MaaSchedule

serve 的 `plan.compute` 使用相同 `compute_plan`。本次 WIP 的 v1–v6 接受各自原 named rotation wire，v7 新增 `main_backup` / `abc` topology 对象及有序 `shift_hours`。CLI 的 generic `main-backup@H1/H2` 或 `abc@H1/H2/H3` 也由本次 WIP 承载。未给 rotation 时仍为旧默认 ABC `12/6/6`。

generic CLI 的 `FromStr` 与共享 `schedule_timed_rotation_request` 在 named 归一化/分派前调用同一 `rotation_types::validate_rotation_duration_hours`；后者覆盖 Worker 直接反序列化和 core 调用者。只做[时长数值安全](../定时换班.md)，不新增周期组合业务校验。共同 finalizer 在 dorm/评分之前检查实际 shifts；公共显式 gate 第一项重新读取最终时长，失败带 `assert-invariants rotation_duration_input:`，不把错误变成候选无解。`plan_index` 仍是 assignment Plan owner；恢复输入顺序移动的是完整 `TeamShiftResult`（包含时长、assignment 与菲亚动作），不是把 owner 索引改成输入班次索引。

普通二/三班 generic request 的数组长度由 topology 结构限定，时长组合业务合法性由调用方前端校验；这不扩展四班专用路径。显式 named profile 不静默降级到另一 profile；能力不足时保留原请求标识与时间形状，并明确普通降级不表示专用组成立。

独立龙巫二班不在六项闭集中。历史 CLI 别名、Worker v3–v5 wire 和重放 bundle 在排班开始前明确失败；`infra-core` 的公共轮换入口也拒绝其旧 wire 标记，不存在旧专用双 owner 构造或普通主备映射。

## ABC 候选链

named ABC 和普通泛型 ABC 均先判断菲亚候选资格。泛型 ABC 在候选内部使用按 α 相位重排后的同一组实际输入班时；每个候选完成构造后，将完整 `TeamShiftResult`（时长、assignment、菲亚动作及索引）恢复到调用方输入顺序，再做共同 finalization 和价值比较。这样 α 相位不会变成固定 Shift 编号，也不会把 `plan_index` 改成输入班次索引。泛型动作槽按实际 `duration_hours > 12` 逐班生成，A/B 目标仍须在 ABC 每个生产班持续在岗；普通泛型主备不进入该适配层。

ABC profile 首先判断菲亚候选资格：

1. 生成不使用菲亚的 N 候选。
2. A（但书/可露希尔）具备资格时，用同一 solver 重新求解 A，并附加目标动作。
3. B（巫恋/龙舌兰/合法裁缝）具备资格时，用同一 solver 重新求解 B。
4. N 完成普通状态；A/B 在附动作后准备全部岗位、宿舍和普通补位，并核对被 relaxed 放行的跨班目标确有动作且满足周期预算。finalizer 只读取已定稿状态结算和诊断；质量 warning 不参与收益排序。
5. 保留固定候选价值与平局优先 N；A/B 动作依赖未兑现按原具名候选退出，其余输入、资源和执行故障继续传播。

当请求显式关闭菲亚时，只求 N，不生成 A/B 动作。CLI 的 `--assert-invariants` 将请求开关传入 request-aware final gate；若最终 assignment 报告仍含动作，即使动作 ready、目标合法，也以 `assert-invariants fiammetta_disabled` 失败。

菲亚 N/A/B 只通过 system_preferences、gamma_relaxed 和动作影响同一完整构造；不预排或硬锚菲亚目标，不按完整周期改选 peak。泡泡/火神预占仍在 peak 前写入 room anchors。ABC 不按中枢 ETA/周期失败退出角色、换半区或重建；既有四赤金容量和可选预占的具名退出保留。

普通二/三班 owner 在 peak 前都解析泡泡/火神资格和首个合法三级源石制造房，再调用 `assign_originium_pair_peak`。planning seed 让 Plan 看见两名同房 `rotation_originium_pair` anchors，execution assignment 仍由 Plan 与普通 pipeline 产生；第三席继续普通制造准入。在冻结房显式 claim 下，若第三席无法合法落位就保留 pair 短员并生成普通缺员 warning；pair 本身无法完成或 pipeline 位移则映射为可选预占失败，重跑普通 peak 并留下质量 warning。资格不足或没有合法房时静态不启用、静默运行普通路径。

当前 `schedule_abc_rotation` 按默认半区构造，不再做 ETA 换向、cohort 重建或可选中枢角色退出；四赤金 required 中枢超容量的独立回退仍保留。`freeze_abc_control_roster` 在冻结目录前按实际工作窗过滤自由候选。N/A/B 各自构造并最终化一次，保留既有比较；最终心情问题写 warning，不按 Control required/group 身份拒绝候选。主备也不再撤去 `control_work_hours` 重求。

## 状态阶段

    timing request → topology/profile resolution
      → owner/peak assignment（可选 preclaimed pair anchors）
      → assignment_plans（Plan owner）
      → H1/H2 或 profile 专用状态
      → shift_bind 对齐与 runtime dependencies
      → ControlRotationClosure 冻结候选身份、cohort、scope、required/group
      → 当班 ControlShiftAdmission → 中枢/办公室/会客室补位
          └─ room_admission.rs：候选试算、ETA/mood budget 公共 helper
      → 菲亚、无人机、特殊 dorm_rest
      → complete_timed_rotation
           ├─ prepare_rotation_state（唯一构造完成 owner）
           │    ├─ 普通提案确认 / 专用动作依赖核对
           │    ├─ 特殊床位和必要 presence
           │    ├─ fill_rotation_vacancies → layout::fill_workplace_vacancies
           │    └─ 进驻顺序、普通宿舍和 autofill 提交
           └─ finalize_timed_rotation（只读岗位和动作）
                ├─ 真实每班评分、周期加权和 notes
                ├─ shortfall/dorm/rest 与构造诊断
                └─ collect_final_rotation_issues（普通 warning / 显式 gate）


普通补位不回读全 roster，不扩大训练/加工/宿舍范围；回收站不再有独立收尾补位。对最终状态的 `ordinary_fallback_complete` 重放只证明当前补位 policy 的稳定性，不证明任意换队、拆绑定或重排技能组合后的全局最优。

TeamShiftResult 是单班最终状态：index、plan_index、duration_hours、active_teams、resting_team、assignment、可选 fiammetta、可选 dorm_rest、可选 drone、transition、三类效率和加权值。TeamRotationReport 还保留所有独立 assignment_plans，排查时先看 shift.plan_index，再追相应 Plan owner。

中枢心情计算只有 roster 准入与终态周期检查两个阶段。roster 阶段按候选逐人使用初始心情、满员中枢固定 `-0.25/h` 和该候选自身已建模中枢技能；不复制临时完整五人 assignment，不求组合级 contextual ETA。ABC 在团队归属完成、建立 `ControlRotationClosure` 之前冻结候选：候选所属 α 的准入窗口为 H1+H3，β 为 H1+H2，γ 为 H2+H3（H1/H2/H3 为实际班时）；此后逐班 `ControlShiftAdmission` 仅执行活跃队伍 scope、required、`min_count` 和容量/身份校验，不读取当前 mood 重新筛中枢。Plan 的固定 required 成员继续由原有准入 owner 约束。主备等路径在各自 roster 建立时按其 owner 的实际时长逐人准入。完成排班后，公共 `cycle_mood` 以实际各班 assignment、实际班时和真实中枢组合做一次完整周期复核；普通 finalizer 的结构性 rotation replay 排除 Control 的逐班重复检查，显式 `--assert-invariants` 仍独立执行完整 gate。终态周期问题统一留 warning，不触发重建。办公室、会客室逐班 ETA 不受此调整影响。

当前 Rule 固定/分组候选与 registry claim 在认领前完成工作窗准入，registry Search 可选者逐人筛选后仍须满足 min_count。动态 producer mask 在 required 承诺前执行同一现有单人预算；protected 仅保留已承诺的 pin。ABC 自由候选在团队归属后、closure 冻结前按实际累计工作窗筛选。依赖宿舍上下文的深海技能仍由原专用 owner 和终态真实组合保证。普通结果保留终态问题，显式 gate 独立核对；未提供预算的 public selector 保持原语义。

## 快照、轮休与写入

- 普通 ABC：生产房切 H1/H2；α 跑 H1、β 跑 H2，γ 为替补。S1=α+β、S2=β+γ、S3=γ+α；α/β/γ 各休一班。泛型时长按最长班把 α 状态映射到输入周期，再恢复输入顺序；同一 source pair 始终属于 α。ABC 并列最长时休班相位优先落在较短班，完全等长保留旧相位。
- ABC 的中枢候选不再在当班组装时读取逐班 mood：冻结时按实际队伍累计窗口逐人准入一次，S1/S2/S3 只从冻结 roster 与当前 team scope 选人。办公室、会客室仍在当班组装时执行各自逐班 ETA；普通办公室候选排除已预留给生产、中枢及轮换会客等角色的成员，绑定办公室成员仍由 Plan 角色落位。S3 对下一周期 S1 的连续消耗由最终完整周期预算检查覆盖；该检查使用真实最终 assignment 与当前真实中枢组合，不用 `12/12/12` 满休假设替代，也不额外运行 Control 逐班 replay。显式 Rust gate 独立重算完整周期预算及其他最终不变量。
- 主备普通 topology：两个完整 owner assignment 互斥，输入时长按两状态顺序结算；α 是主队、β 是替班。适用源石 pair 固定归 α，按 1 上 1 休绑定，不套用 ABC 的 2 上 1 休计数。`main_backup_12_12` 与 `main_backup_24_24` 仍保留旧 profile policy。
- main_backup_24_24：主、替各自完整求解；通常主 assignment 全部已占成员进入替班禁用集合。菲亚开启时，主班最终 Trade 动作目标逐个回到备班候选池，由正常 Plan/Trade 搜索决定是否实际选入，不直接加 anchor。只有各动作班最终 TradePost 落位、目标互异且完整周期心情/ready/bind 检查通过才接受；不通过则保留普通主备互斥备班并以自身最终 Trade 结果寻找不同目标。`schedule_main_backup_24_24` 设置 `control_work_hours=Some(24)`；`prepare_peak_control_candidate` 在动态 required 承诺前按已有单人预算筛选，满 pin 路径消费已完成的准入。两个状态各运行 24h，办公室和会客室使用 24h ETA，生产搜索使用同一工作窗口；最终门禁重新检查 actual assignment，不拆成班内 MAA 状态。required 组合不成立仍按原 mask 枚举；普通候选耗尽时保留已执行 Plan 状态和真实空位，不静默拆除必选承诺。

  当前 named `main_backup_24_24` 保留 `control_work_hours=Some(24)`；named 与泛型 `main-backup@H1/H2` 均按实际 ETA/心情准入，不再有 `filter_operbox_for_24_24` 姓名名单。自定义班次超过 24h 直接使用实际 H1/H2 ETA。
- 独立龙巫二班已从产品支持中删除；普通菲亚候选分支仍按原 ABC 规则运行，不能视为该独立双 owner profile 的映射。
- fiammetta_8_8_4_4：前段两个 8h，菲亚边界动作单独标记；FiammettaOnly 对完整编制分别结算 8h/16h，目标房保留前段值，其他房间按差值结算续段，不等同于只重放目标房。
- abyssal_7_5_7_5：7h 主班、5h 恢复、7h 替班、5h 恢复；DormRestPlan 固定同一宿舍的目标、单回宿管、群回宿管。

dorm_finalizer::finalize_dorms 以相邻班次实际非宿舍工作差集 previous_work - current_work 得到普通休息成员。已有宿舍住员和特殊 DormRestPlan 先保护，再按容量写入；床位不足返回 warning，不偷偷改岗位。特殊组重复、房间不是宿舍、超容量或成员不存在时，finalizer 保留试算前的 assignment 并记录结构诊断，不丢弃整份排班。普通宿舍和动作在 preparation 内完成，评分与终检读取最后提交的 assignment。

宿舍最终落位后，rotation_cycle_rest_warnings 只读取最终非宿舍岗位和训练副手，跨完整周期统计出勤；只有本周期实际自动化 Lancet-2 和最终菲亚动作目标豁免。结果追加到 report.warnings，`rotation_cycle_rest_diagnostics` 重算并检查同前缀诊断是否完全一致；不休班本身不阻断正常结果或 MAA。最终 Trade gate 独立从最终 assignment 清快照后直接求解：普通班按实际小时，`FiammettaOnly` 先求 8h/16h，目标房取 8h，其余房按整数续段差分；它不负责跨域 policy 或完整 Plan 比较。

所有 profile 最终化后统一调用 `schedule/cycle_mood.rs`，以现有 contextual ETA 按人累计。实际加工站和训练室占位保留工作连续性但无小时成本；独立训练副手缺活动输入产生未支持活动诊断。每个起点循环扫描覆盖末班到首班，整轮无恢复正消耗产生预算诊断，初始前缀只使用调用者心情。完整报告中的周期心情问题直接追加 warning；不再触发 Control 候选拒绝或重建。此处的离岗满休是连续预算近似，不是宿舍恢复证明；制造技能心情落差的连续制造限制由原专用 owner 独立核验。

魔王同房配对恢复在共同净消耗 owner 内接入，候选试放与最终周期 ETA 都消费实际同房成员及来源练度，不在轮换层再扣一次。最终 `control_pair_recovery` 检查精确两档委托/实例映射，并从 `shifts[].assignment` 比较启用与移除配对数据后的 contextual ETA，独立核对两人受益、第三人/其他设施不变及共同下限。它不要求两人一定入选，也不把模型支持扩成强制绑定或跨类别互斥。

## 错误与输出

- 普通工作设施候选不足不回退到全 roster；无 anchor 制造 fallback 保留当前池合法的 0..N 人而非直接报错。TeamRotationReport.warnings 从终态生成班次、设施、房间和缺额；训练室、加工站及宿舍不在该普通补位诊断内。
- 逐班中枢 admission 在周期构造阶段允许少于容量，但仍验证唯一身份、活跃队伍准入、真实练度、required 与 `min_count`；整周期普通补位再为中枢尝试补空位。容量超过上限或违反身份/required 仍拒绝该候选。最终公开 invariant 核验中枢不超容量，并由 `ordinary_fallback_complete` 证明同一合法候选策略已耗尽；仍有可加入成员才是断言失败，短员本身保留 warning，不使 gate 失败。贸易、制造、发电及三级制造房采用相同的短员边界，同时继续检查超容量与制造同房兼容。
- 整周期无休班以 `rotation_cycle_rest:` warning 列出干员、逐班工作岗位及豁免判定；CLI 和 Worker 沿现有 warnings 输出，MAA 保留最终岗位与菲亚指令。
- 真实 shift_bind 成员 ETA 不足不能拆成普通候选；构造记录具体诊断并继续其他岗位，终检只核对实际状态，不退出角色或重编 Plan。
- 所有菲亚入口共用 ready 时间线。无依赖普通提案在补位前确认；ABC A/B、24/24 回池、8/8/4/4 的动作与依赖工作整体提交。终检只读重放，取消依赖动作的坏状态仍被显式 gate 拦截。
- main_backup_24_24 单动作 warning 在完整 preparation 和结算后读取实际目标、动作班、TradePost 和搜索路径，不读取试放前快照；CLI/profile/MAA/Worker 同源。
- 泡泡/火神预占的局部失败与条件不成立分开：资格不足或没有合法三级源石房时不生成 anchors，普通排班静默成功；已有目标房但双 anchor 制造完成失败时，保留普通 peak、rotation 和 MAA，并写入 `rotation_final_invariant: originium pair preclaim failed: …; ordinary peak retained`。显式 `--assert-invariants` 从最终 assignment 重查，若合法房和资格仍成立但 peak Plan 丢失 anchors、pair 不在两班工作或休息班残留，则失败；CLI 的显式 gate 在写 MAA 之前返回失败，因此该验收路径不承诺同时产出文件。普通工作房第三席候选耗尽只产生短员 warning，不触发该硬错误，显式 gate 仍允许两人短员。
- 深海专用组合不足仍按具名 ProfileOwnerCandidate::Unavailable 使用普通 owner 保留 7/5/7/5，恢复不足不虚构 DormRestPlan。普通终检和显式验收消费同一问题集合；普通保留 warning，显式 gate 返回错误。已删除预算文本识别和 partial 质量降级包装。
- 主备各 owner 始终传递实际工作窗的保守过滤，不恢复撤过滤重试；候选耗尽保留已执行 Plan 并完成普通补位。菲亚目标回池、深海能力缺失的普通 owner 降级保留原 policy。
- plan_compute 仍保留真实故障阶段；只有完整结果进入 profile、MAA 和练卡建议。排班内部不再用 PartialRotation 传播未结算草稿。

## 排查顺序

先确认入口解析出的 profile；再看 TeamRotationReport.profile、shifts[].plan_index、transition、assignment、runtime_shift_binds、dorm_rest 和 warnings；最后用 --assert-invariants 检查最终状态。若只错 MAA，沿 MAA 导出调用链排查，不反查 solver 规则。

## 绑定闭包与跨半区交换

shift_binds_from_plan 读取每个 AssignmentPlan 的 exact-presence dependency 和显式 shift_binds，排序去重后合并重叠集合。它不会从 roster 或 buff 名称猜 bind。align_shift_binds_in_halves 选一个已在 half 的 anchor，把同组 wanderer 的 trade/manu/power room 与另一 half 的同类 room 交换；没有可交换房间时不伪造对齐，后续 invariant 会报告 bind 不属于完整 team。

最终 `validate_final_bind_cycle` 从 `assignment_plans` 重建绑定，合入 runtime-only bind，并冻结各组来源 Plan。它按 `work_position_operator_names` 重算工作向量，宿舍不算工作；Plan anchor 或 registry slot 声明的宿舍支持与工作核心分开，核心实际工作时支持须实际进入任意宿舍。另有同 Plan 的单向依赖 required support 不进入 exact 工作向量，receiver 实际工作时用真实房间 presence 检查支持缺席。显式 `rest_facility` 只区分该绑定角色的休息去向，训练/加工普通占位与 training_assist 的独立实际出勤口径不变。两个及以上工作成员的组在 ABC 核对非零 on/off，其他 profile 使用既有 active_teams 拓扑，8/8/4/4 不复用 2/1 班数。无工作核心的纯宿舍组不伪造班数；分类后只剩单个 receiver 的单向支持关系不套 exact 工作组班数，本单元不宣称完整覆盖所有绑定。普通 finalizer 将错误追加为 `rotation_final_invariant: rotation_bind:`，显式 gate 从最终报告重算并返回错误，不消费 warning 作为证据。

候选试放仍使用原 `validate_final_rotation_invariants`，本轮未改候选筛选或排序；旧公开 helper `verify_shift_binds` 目前不在产品主终验路径，不能用于声称终态工作统计已统一到所有 helper。办公室的 bound_operator_names 仍用原闭包排除普通补位，避免绑定成员被 office fallback 拆开。莱茵支持位进入所选 alternative 的 exact bind 是 2026-10-13 用户裁决，终态工作统计另将单向 required support 从工作核心剔除并检查 receiver-active 时的 presence；支持设施合法性与所有 required admission 的完整证明仍待后续 owner 迁移，不能从本次 gate 推导已完成。

## 支持角色到最终评分的状态流

主动挂件组合关闭时不会生成 `rhine_support` role；显式开启后，规则编译器按 role 的候选顺序解析实际成员与可用设施。每个已选 role 成员在候选 Plan 形成时就写入候选 assignment、`used` 与 anchor；所有声明 role 落位后才执行该 alternative 的 domain completion / competitive 比较。因此当前观察到的是**先承诺并占位、再比较**，不是通用延迟绑定池。

`score_completed_manufacture`、`score_completed_power` 分别消费比较分支的候选 assignment 和已占人员集合，也重算未添加该 alternative 的 baseline。已承诺支持者若在对应 assignment 中，会像其他已占位成员一样影响后续可选人和完整房间评分；这不证明存在 receiver/support claim 的通用候选遍历。支持位的产品设计仍未授权改变。

菲亚候选试放读取各班当前 assignment 生成 ETA，复制 shift 列表并只增试放的 action；验证成功后写回 action 字段，不替换 receiver、支持位或房间 assignment。preparation 提交普通宿舍和实际动作后，公共 finalizer 读取定稿 assignment 结算普通班、8/8/4/4 续段和周期权重，不筛除动作。最终宿舍中的普通休息者不回填成 Plan 支持 claim。

样例观察留证：`target/codex-runs/rotation-support-investigation-20261019/observations/support-trace-summary.json`。它来自 243 + `b-073-415`、ABC 12/6/6、主动挂件开启、显式 gate 的隔离日志插桩 release；在 44 条观测中记录了 Plan 已选支持者、比较输入、菲亚试放及 finalizer 前后的 assignment。它只证明该输入下的阶段状态，不证明所有 profile 或所有候选都一致。Astra 只读设计思考记录在 `target/codex-runs/rotation-support-investigation-20261019/observations/astra-design-thought-20261019.md`，经 DeepSeek 阶段复核后仅作为待讨论方案；没有改变当前 eager placement，也没有批准 receiver/support 语义或实现。

莱茵 `bind_all:true` 承载 2026-10-13 用户裁决后的组班策略，不能仅凭该字段判偏差或宣称完整合规。所选双端 alternative 会把娜斯提、缪尔赛思、支持位及制造补齐成员编入同一 bind；单端 alternative 不因规则 ID 自动并入另一个 receiver。`active_dependencies` 另外核对 receiver 实际工作时 support 是否在最终 assignment 中；被 exact bind 覆盖的 required support 不再被钉成全周期 shared。终态工作统计按实际岗位计算，宿舍只算休息。较早的 `RHINE_LAB_CHAIN.md` 文字已按用户裁决对齐；来源与当前覆盖见[莱茵生命体系论证](../公孙长乐的体系分析文档/RHINE_LAB_CHAIN.md) §5.3、§7。

2026-10-19 的五份隔离纯日志观测直接比较公共宿舍 finalizer 前后，且与正式 release 的 profile/rotation/MAA 除 elapsed 外完全相同：`b-174-382` / ABC 12/6/6 的缪尔赛思和加工站支持赫默在休班 S2 原先不在 assignment，经 `previous_work - current_work` 普通休息候选进入宿舍，最终是两班工作、一班住宿，三班均有 presence。原 `b-073-415` / 12/6/6 的整组第三班缺席是床位溢出时普通休息者被 omitted 的结果；同盒 12/12/12 会重新住宿。因而组班、工作和阵营 presence 不能共用一个次数。两种 ABC 各 38 盒显式开启挂件的 release gate 均通过，只证明已注册检查；228 班 MAA 显式名单与终态一致，不证明 autofill 的游戏内动态选择。详细逐人状态与保证边界由莱茵 canonical §7.1 持有。

| 失败/症状 | 结果字段或 stage | 调查顺序 |
|---|---|---|
