1. CLI解析`auto@H1/H2`；公共分派进入独立建议owner，不进入定时恢复/profile/MAA。
2. 主中枢建池时按H1做初始单人ETA筛选，再定主中枢；完整可用盒走公共Peak和普通补位，第一次完成主力冻结。备中枢从剩余工作成员建池并按H2初始筛选，不复筛固定主力。
3. Plan在角色递归前限制alternatives；自动整体跳过兼容registry。宿舍1＋1临时环境由原设施搜索选人，赢家包含受益者才保留anchor/dependency；不补排全基建比较收益。
4. execute原样落实Plan及used。`claim_support_rooms`登记显式挂件的唯一工作房；同房主备允许共享，跨工作房拒绝双认领。
5. 自动直接一次公共发电→贸易→制造填充，跳过动态producer前缀、上界、排序和比较分数。搜索保留原技能排序、同房兼容和机制公式，不做逐组合心情筛选。
6. 办公室、会客室和空岗沿普通补位，只消费Plan、身份、占用、容量、Team/Shift和设施策略，不做心情复筛。
7. 从最终实际两态结算效率、ETA、首人红脸、缺额与显式挂件。`auto_work_duration_issues`重算两名单×两实际中枢及外站深海人数最大混搭，心情不足追加质量提示，不影响名单与正常输出。
8. 显式Rust gate从真实状态核对身份、Plan、快照、缺额、挂件和心情提示完整性。心情不足本身不失败；没有任意混搭协同完备保证。

2026-10-31 用户最新裁决：只保留最初 ETA roster 试算；后续搜索、组合、补位、逐班和动作候选不再按工作心情预算筛选或拒绝。心情净消耗、暖机与心情差积分仍按真实状态结算；终态心情不足保留质量 warning。显式 gate 核对该 warning 与实际终态是否一致，结构、Plan、绑定和动作事实仍独立验收。本次删除属于 policy，不是 safe reduction，不证明全局最优。

此前已删除全站协同证明与混搭穷举的approximation保持；本轮不恢复动态producer搜索、重试或全响应缓存。搜索memo只消费收益layout、模式与H，不携带后续心情预算状态。真实资源与效率仍由普通resolve及设施solver结算。
