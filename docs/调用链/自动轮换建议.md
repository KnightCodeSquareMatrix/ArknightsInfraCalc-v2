# 自动轮换建议调用链

> 文档角色：call-chain
> 生命周期状态：current
> 领域键：schedule.auto_rotation
> 当前真源：docs/自动轮换.md
> 摘要：每站主备建议的八步复用、准入与输出
> 代码范围：crates/infra-core/src/schedule/auto_rotation.rs、crates/infra-core/src/layout/admission.rs、crates/infra-core/src/layout/assign.rs、crates/infra-core/src/mood/drain.rs、crates/infra-cli/src/commands/plan.rs
> 代码锚点：schedule_auto_rotation、assert_auto_rotation_invariants、complete_standalone_assignment、CandidateAdmission、room_workable_hours_with_control
> 关联链路：docs/模块/排班与轮换.md、docs/模块/候选搜索与Bake.md、docs/接口/CLI与Worker.md
> 核验基线：09655db至当前变更；挂件修正证据见docs/ARCHIVE/done/自动轮换挂件选人修正-20261029.md，入口/时长见docs/ARCHIVE/done/排班入口与时长统一-20261029.md

1. CLI解析 `auto@H1/H2` 并校验有限正时长，加载蓝图、盒、instances、skill table；公共 `schedule_rotation` 分派独立建议入口。裸 `auto` 明确要求补时长。
2. 中枢公共owner先选主中枢；主力使用完整可用盒由公共Peak seed形成，完成空座后冻结工作名单。替补排除全部主力工作成员、继承宿舍挂件，再从剩余成员选择备中枢并走同一Peak owner。备中枢候选检查固定主力H1，实际选择结果（含候选耗尽留下的空中枢）再次复核；不兼容则明确固定主力下未找到方案，不回选主力。
3. `build_plan`限制可用规则和registry。宿舍1＋1沿既有角色递归建立临时环境；对应房清除预选受益者，取消必选条件，由原设施搜索直接选完整组合。赢家包含受益者才提交挂件、anchor及dependency provenance；否则整个临时alternative回退。制造/发电不为此补排全基建比较总收益。贸易保留有序role；普通组合搜索使用已有full_pool保留受益者资格。普通定时竞争政策保留。
4. `execute_plan`按同一Plan建立真实岗位与设施池，继承的宿舍角色不重复入住。
5. 贸易、制造、发电、中枢及支援设施的候选沿原搜索；mode准入复核实际外部成员来源。`resolve`供给真实资源；公式不由准入计算。
6. 公共办公室选择与vacancy补位完成空座，保留required/禁配。共享挂件在两态固定；单独效率刷新不再次补人。
7. Rust auto gate检查两个最终assignment及Plan，重算各房ETA与效率，核对互斥、来源、能力、共享宿舍、房全集、缺额和说明；不运行周期恢复门禁。
8. 独立报告逐站显示两态；缺人且满足预算与协同时保留建议并标不完整。替补选人、补位与最终混搭检查失败返回固定主力policy错误，不伪装为全空间无解。只有CLI文本/JSON消费，不投影profile、MAA或Worker。

禁令属于hard constraint；Peak与有序竞争/Top-K属于heuristic；输入收益窗口属于policy，撑满输入时长属于hard constraint。自动模式使用live搜索，memo区分模式、真实站点和另一态的真实成员。批量通过只证明样本满足已列终态断言。

独立切换准入：替补候选在搜索/Plan/普通补位入口与其他房两态可共存成员检查；同房主备不共存。发电同轮选入更新快照。建议返回前与最终gate均精确枚举所有工作房的主备混合配置。候选投影通过candidate_room实际房身份，避免把本房未入选成员残留成外站。固定站点以借用视图参与准入，只物化候选本房；制造、贸易和中枢每次搜索、发电每个实际目标房建立 `CandidateAdmission`，按需缓存与候选无关的另一态＋共享宿舍准入结果。宿舍本身变化时按实际新宿舍重查。完整当前态及所有既有可共存房对仍按原条件检查。

资源来源由中枢trace、发电虚拟产出、跨设施global执行器写入和全局转换实际执行边提供；同成员净零不登记，房内转换不发布。蓝图初始pool保留，实际转换同时记录在岗provider/converter，因此预置碎片经一级絮雨转换仍会构成外站成员依赖。站点真实等级与静态蓝图输入用于同一解释器求值，平台条件保留阈值。来源同一次准入按需读取，实际资源消费者才触发原解释器。

时长由请求进入主/备options，经过planning/execution seed、RuleCompileContext与resolve快照传递，候选与普通基线都用同一H。`room_workable_hours_with_control`只复用ETA净耗公式检查完整成员的预算，不决定收益窗口。未完成前缀仅检查已确定协同，完整组合再检查预算；制造缺员兜底也使用域组合枚举，按候选最终名单检查而非逐人前缀拒绝；主中枢先于主力生产，主力完成后才选备中枢，备中枢完整候选消费固定主力预算；备工作候选检查自身及另一个中枢。无必需成员的中枢候选耗尽留缺位，有钉选/必需角色仍拒绝；缺位中枢若导致固定主力预算失败，在备生产之前明确报错。最终精确枚举的每房主备来源携带自身H，宿舍固定共享。

办公室排序与普通试放共用 `office::rank_candidates`、`office::fill_vacancies`；自动从满心情检查当前及另一个中枢下的H。发电无技能补位保留完整assignment上下文。自动制造取消≥12小时负心情差排除，既有分段心情/连续暖机负责收益。

终态gate另从实际assignment独立重建两种中枢下的ETA，按各房输入H比较预算数值。

站位快照在LayoutContext内使用共享只读所有权，复制搜索上下文不深复制两态成员；发电提交下一房前以写时复制更新本轮站位。序列化、相等比较和memo键仍按成员内容；prepared对象不进入memo。房间预算通过mood的显式中枢名单及必要外站深海人数接口结算；已删除无消费者的旧layout预算入口。终态仍从最终assignment重建实际状态；空、非普通工作房、成员与依赖及其他属性完全相同而仅H不同的主备状态合并一次，属于safe reduction，其余混搭分支保留。同一次终态调用中，预算按不可变房态、实际中枢态和中枢所需外站深海人数复用；非中枢预算不依赖深海人数。每个枚举叶的协同检查仍独立执行，缓存随调用销毁，不从生产阶段带入。
