> 代码范围：crates/infra-core/src/schedule/auto_rotation.rs、crates/infra-core/src/layout/assign.rs、crates/infra-core/src/mood/drain.rs、crates/infra-cli/src/commands/plan.rs

1. CLI解析`auto@H1/H2`；公共分派进入独立排班owner，不进入定时恢复/profile/MAA。
2. 先按H1/H2冻结各工作设施正常技能候选的单人ETA资格；主中枢建池时按H1做初始单人ETA筛选，再定主中枢；完整可用盒走公共Peak和普通补位，第一次完成主力冻结。备中枢从剩余工作成员建池并按H2初始筛选，不复筛固定主力。
3. Plan在角色递归前限制alternatives；自动整体跳过兼容registry。宿舍1＋1临时环境由原设施搜索选人，赢家包含受益者才保留anchor/dependency；不补排全基建比较收益。
4. execute原样落实Plan及used。`claim_support_rooms`登记显式挂件的唯一工作房；同房主备允许共享，跨工作房拒绝双认领。
5. 自动直接一次公共发电→贸易→制造填充，跳过动态producer前缀、上界、排序和比较分数。搜索保留原技能排序、同房兼容和机制公式，不做逐组合心情筛选。
6. 主力完成后按布局优先级确认菲亚续班目标；菲亚入住有临时交换席的宿舍，继承常驻支持。`solve_policy_backup_with_continuous_targets`只将这些目标从主力工作排除集移除，通过`assign_shift_with_preclaimed_plan`把同房锚点交给build→execute→fill；队友由原设施搜索选择。目标与菲亚的依赖记录在两份Plan。新增目标不能满足共享恢复预算、初始资格或同房续班时放弃该目标，主力工作名单不回选。没有可确认目标时走原互斥替补。办公室、会客室和空岗沿普通补位；Fallback仍直接随机补剩余持有人，不查心情、技能或组合。
7. 从最终实际两态结算效率、ETA、首人红脸、缺额与显式挂件；回收复用`recycle::evaluate_recycle`。确认的菲亚目标不再作为普通红脸换班瓶颈，其心情由共享服务周期证明；其他人的ETA质量提示保持。`fiammetta`输出实际续班目标、宿舍和重复交换记录，双方心情交换和菲亚恢复共用定时的`fiammetta_events::Timeline`。保守服务policy与边界见[菲亚梅塔使用规则](../菲亚梅塔使用规则.md)。Fallback仍追加原样warning。
8. Rust gate从真实状态核对身份、Plan、快照、缺额、Fallback来源、初始ETA、挂件和心情提示；实际主备工作交集必须恰好等于确认的菲亚目标，目标必须同房且有Plan锚点/依赖、实际宿舍及交换临时席。重新计算共享预算和交换记录。关闭/未持有不允许续班目标。普通心情不足本身不失败；不证明任意混搭协同完备。

2026-10-31 用户最新裁决：只保留最初 ETA roster 试算；后续搜索、组合、补位、逐班和动作候选不再按工作心情预算筛选或拒绝。心情净消耗、暖机与心情差积分仍按真实状态结算；终态心情不足保留质量 warning。显式 gate 核对该 warning 与实际终态是否一致，结构、Plan、绑定和动作事实仍独立验收。本次删除属于 policy，不是 safe reduction，不证明全局最优。

此前已删除全站协同证明与混搭穷举的approximation保持；本轮不恢复动态producer搜索、重试或全响应缓存。搜索memo只消费收益layout、模式与H，不携带后续心情预算状态。真实资源与效率仍由普通resolve及设施solver结算。
