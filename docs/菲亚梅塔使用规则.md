# 菲亚梅塔使用规则

> 文档角色：canonical
> 生命周期状态：current
> 领域键：schedule.fiammetta
> 当前真源：self
> 摘要：裁决定时换班中菲亚梅塔的使用次数、时机和目标去重规则

## 1. 适用范围

本文是定时换班排班中菲亚梅塔使用规则的唯一 canonical owner。排班模式、CLI、前端和 MAA 文档只引用本文，不重复维护次数或目标选择规则。

## 2. 使用次数与时机

菲亚梅塔动作发生在对应班次开始。以下是当前简化换班模式的最大使用次数和固定时机：

| profile | 班次 | 最大次数 | 使用时机 |
|---|---|---:|---|
| `main_backup_12_12` | `12/12` | 2 | 第 1、2 班开始 |
| `abc_12_12_12` | `12/12/12` | 3 | 第 1、2、3 班开始 |
| `abc_12_6_6` | `12/6/6` | 2 | 第 1、2 班开始；第 3 班菲亚休息 |
| `fiammetta_8_8_4_4` | `8/8/4/4` | 3 | 第 1、2、3 班开始；第 4 班不使用 |

这里的“最大次数”同时是当前模式允许生成的动作上限。没有合法的新目标时，可以少于上限，但不得为了填满次数重复服务已经使用过的目标。

## 3. 目标规则

- 菲亚梅塔可以在同一周期服务多个合法目标。
- 每个目标在一个周期内最多接受一次菲亚梅塔服务。
- 一个目标接受一次服务后，排班器将其视为获得该周期的持续工作资格，不再为该目标生成第二次动作。
- 后续动作应优先分配给尚未服务、且满足当前排班和设施约束的其他目标。
- 没有合法的新目标时，动作保持关闭；不得重复输出同一目标。
- 目标优先级只用于从当前合法候选中选取目标，不得突破次数、班次位置、容量、绑定或持续工作约束。

## 4. 当前目标候选

常规目标优先级按布局选择：

```text
153：可露希尔 > 巫恋 + 龙舌兰 > 但书
243 / 252：但书 > 可露希尔 > 巫恋 + 龙舌兰 > 清流
333 / 342：但书 > 可露希尔 > 清流 > 巫恋 + 龙舌兰
```

巫恋 + 龙舌兰属于成组候选时，必须同时满足其既有裁缝和同房约束。上述顺序不能把已经服务过的目标重新选回。

## 5. 开关与输出责任

`fiammetta_enable`（CLI 的 `--no-fiammetta` 对应关闭值）是全局开关，不是逐班输入。排班层依据本文生成 `TeamShiftResult.fiammetta`；MAA export 只把该动作忠实映射为 `Fiammetta.enable`、`target` 和 `order`，不自行选人或补动作。

关闭菲亚梅塔时不生成任何动作。显式菲亚事件 profile 仍遵守其自身的硬前提。

## 6. 非目标内容

本文不扩展为完整实时心情曲线、跨多个周期的永续排班、Mower 动态换班或宿舍槽位模拟。`fiammetta_ready_events` 只能作为已有动作候选的心情可执行性判断，不能增加 profile 次数、改变固定时机或重复选择目标。
