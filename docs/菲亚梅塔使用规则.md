# 菲亚梅塔使用规则

> 领域键：schedule.fiammetta

> 摘要：定义菲亚梅塔动作数量、目标去重和输出责任
> 代码范围：crates/infra-core/src/schedule/team_rotation.rs
> 知识库桥接：docs/知识库引用.md（机制正文与版本由隔壁知识库裁决）
> 代码锚点：fiammetta_action_slots、attach_fiammetta_target_actions、validate_fiammetta_action_policy

本页裁决动作数量、时机和目标去重；游戏机制正文引用隔壁知识库。

| profile | 动作位置 | 上限 |
|---|---|---:|
| abc_12_6_6 | S1、S2 | 2 |
| abc_12_12_12 | S1、S2、S3 | 3 |
| main_backup_12_12 | 两个 12h 状态 | 2 |
| main_backup_24_24 | 两个 24h 状态 | 2 |
| fiammetta_8_8_4_4 | 前三个状态 | 3 |
| abyssal_7_5_7_5 | profile 专用动作位 | 由 profile 校验 |

上限是允许生成的动作数，不是必须填满。目标必须在当前合法生产房、未被本周期动作使用，并满足 action slot、绑定、容量和连续工作约束；目标服务一次后本周期不再重复。优先级只在合法候选中排序。

普通泛型二/三班不继承旧 named profile 的固定槽位：调用方只接受 24h、36h 或 48h 周期；每个实际超过 12h 的班次提供一个动作槽，且该槽最多写入一次动作。动作仍须通过同一 ready 事件、目标去重、绑定/容量和最终 assignment 核对；没有合法目标时保留普通排班并按既有 warning 边界输出。四班专用 profile 的槽位和动作数量不受本条影响。

`main_backup_24_24` 的两个动作若都生成，必须指向不同干员，且各自在自己的动作班由普通 Trade 搜索选中并最终实际进入对应 TradePost；该 profile 的目标限定贸易站，不沿用其他 profile 的制造/发电候选范围。主班动作目标会回到备班 Trade 候选池参与正常搜索，但不会作为 required anchor 强制落位。若备班搜索选回该目标，只有完整 48h 心情、菲亚 ready 与对应 bind 检查均通过才接受；否则重新使用普通主备互斥备班。若最终只有一个不同目标通过，允许只输出一个动作并告警；零个候选时保留普通排班与定位 warning。候选名单和 target 字段本身不构成落位证明，显式门禁从对应动作班的最终 assignment 核对 TradePost 与完整周期心情。

24/24 单动作诊断必须基于共享最终化后的 `TeamRotationReport`：宿舍落位、普通空座补位和最终 ready 筛除完成后，warning 才写明最终保留的目标、动作班次、TradePost 和搜索路径；若共享最终化移除了已试放动作，应说明没有动作保留，而不能报告试放前的目标为已接受。CLI 文本在逐班工位表前单列各自动作班的最终目标和 TradePost；若目标因正常回池而出现在两个 owner assignment，主备花名册只将其计入动作班所属队伍，逐班工位表仍反映实际 assignment。MAA JSON 不新增字段，继续只投影最终 `TeamShiftResult.fiammetta`。

动作 ready 判定（`fiammetta_ready_events`）：候选班次开始时菲亚心情已按宿舍自律速率（`mood_model.json` 中 `no_external` 条目，不吃外部回复）逐班累积攒满，且目标在该班 `shift_eta` 在岗明细内。动作把目标心情重置为满，菲亚接手目标原心情后继续累积。目标休班期间不计回复（保守），仅为动作 ready 判定，不是实时心情曲线。

执行动作的菲亚本人按该班宿舍休息成员处理，不属于主备工作队；终态队伍归属检查不得把这项必需的宿舍 presence 当成“无队伍在岗人员”。

所有 profile 的动作均受 ready 约束，不存在普通目标、已删除专用 profile 或插班例外。不同目标共享同一名菲亚的连续预算，不能为每个目标重新从满心情开始试算；各目标的在岗消耗则分别累计。候选动作须在保留既有事件的完整时间线上试放，不能使已接受的后续动作失去 ready。最终岗位落位后仍须重新核对，候选阶段通过不替代终态证明。

动作不 ready 不等于整份排班必须失败。最终岗位确定后，沿实际时间线排除不 ready 的动作并给出诊断，保留工作 assignment；原动作专用班次转为普通班次，重新生成无人机动作、效率和周期权重。缺菲亚或没有接受动作的 8/8/4/4 仍保留原班数和时长，不伪造动作。独立龙巫二班已从产品 profile 删除，旧入口不再触发专用组合或普通主备降级。显式 `--assert-invariants` 仍独立核查终态，不把已输出警告的结果当作质量通过。

对[每周期休班底线](定时换班.md#每周期休班底线目标规则)而言，只有本周期某班最终 `TeamShiftResult.fiammetta.target` 所指的干员获得例外；列入候选、预定使用或留在 Plan 中均不等于动作已写入。例外依据是已生成的排班指令，不要求证明游戏内已执行交换；MAA 沿用现有 `target` 与 `order=pre` 投影。

fiammetta_enable=false（CLI --no-fiammetta）关闭常规动作；fiammetta_8_8_4_4 要求开启，冲突直接失败。schedule 写入 TeamShiftResult.fiammetta，MAA 使用 target 和 order=pre，不重新选人。本文不定义 Mower、实时心情曲线、宿舍完整槽位或全周期最优。
