# 练卡推荐自然语言输出层设计

> 文档角色：current-reference
> 生命周期状态：current
> 当前真源：docs/练卡推荐相关/README.md
> 摘要：说明练卡推荐自然语言输出层的当前设计和待接入边界

## 1. 目标

将后端已经确定的练卡事实整理成面向玩家的自然语言报告，让玩家可以快速理解：

- 账号整体情况；
- 已经达到成型可用状态的组合；
- 尚未完成的组合；
- 当前最值得执行的练卡或收集行动；
- 高效率散件和后续排班建议。

LLM 只负责组织语言，不负责计算、裁决或补充领域事实。

## 2. 总体架构

```text
OperBox / 布局 / 求解结果
        ↓
Rust training_advice
        ↓
PlayerTrainingAdviceReport v2
        ↓
NarrativeInput 投影
        ↓
BFF / Python narrator adapter
        ↓
LLM 或确定性 fallback
        ↓
事实校验、placeholder 替换
        ↓
training_advice.narrative
        ↓
前端自然语言展示 + 结构化详情
```

### 2.1 责任边界

| 层 | 责任 | 不负责 |
|---|---|---|
| Rust core | 生成 `PlayerTrainingAdviceReport v2`、完成度、成员状态、目标练度、推荐顺序和事实输入 | 调用外部 LLM、管理 API key、生成异步任务 |
| Python narrator adapter | 加载 mapping、调用 OpenAI-compatible API、校验结构化文案、替换 canonical 名称、生成 fallback | 重新计算组合完成度、重新排序、补充机制事实 |
| BFF | HTTP 路由、鉴权、限流、配额、Redis、任务状态和 adapter 编排 | 改写已校验文案、修改 Rust 事实 |
| 前端 | 展示自然语言报告和结构化详情 | 直接调用 LLM、替换名称、解析自然语言决定练卡建议 |

当前仓库没有 BFF、Redis 或 Python narrator 服务。本仓库本阶段负责 narrator 核心契约、投影规则、校验/fallback、adapter 包和测试；BFF 与前端在外部仓库按本设计接入。

## 3. 服务接口

保留原有 `plan.compute` 契约及 `result.training_advice` 结构化输出，新增独立接口：

```text
training_advice.narrative
```

建议的异步协议：

```text
POST /training_advice.narrative
→ 200 { status: "ready", narrative, structured_report }
→ 202 { status: "processing", request_id, retry_after_ms }
→ 200 { status: "fallback", narrative, structured_report, fallback_reason }

GET /training_advice.narrative/{request_id}
→ 200 { status: "ready" | "fallback", narrative, structured_report }
→ 202 { status: "processing", retry_after_ms }
```

缓存命中时直接返回 `ready`。未命中时先尝试获得任务锁；未抢到锁的并发请求返回同一内容哈希对应的 `processing`，不等待、不重复入队。

Narrative 请求必须消费已经成功生成的 `PlayerTrainingAdviceReport v2`，不得为了自然语言输出重新触发或阻塞 `plan.compute`。POST 请求如果已经携带可验证的结构化报告，在 Redis 不可用时可以直接生成确定性 fallback；GET 请求只有任务 ID 时无法重建报告，应返回明确的 degraded/503 状态，而不是调用 LLM。

## 4. 报告内容

LLM 和 fallback 共用同一个 `NarrativeOutput` 协议，固定六个章节：

1. 账号概况
2. 已成型组合摘要
3. 基础必练、必收集
4. 待完成组合摘要
5. 练卡建议与高效率散件
6. 再次使用排班工具的提示

### 4.1 组合选择规则

组合筛选必须在 Rust 或确定性的 NarrativeInput builder 中完成，LLM 不参与选择。

- 已成型组合：只选择确定状态为已成型的组合，最多 6 组；按 `completion_percent` 原始字段从高到低排序；不足 6 组不扩充。
- 未完成组合：只选择确定状态为未完成且非 `needs_review` 的组合，最多 6 组；按 `completion_percent` 原始字段从高到低排序；不足 6 组不扩充。
- 缺核心但不满足 C2 的组合可以出现在结构化完成度中，但不因此生成收集行动建议。
- 同完成率使用 Rust 当前固定组合顺序作为稳定顺序。
- `completion_percent` 直接复用 Rust 字段。当前口径是向下取整，Narrator 不重新计算、不四舍五入。
- 已成型组合整体用一句话陈述，例如“龙舌兰组、叙拉古、自动化组等组合已经达到成型可用状态”。
- 未完成组合整体用一句话陈述，并带真实整数完成率，例如“红云组（66%）、红松林骑士组（50%）等组合尚未完成”。
- 组合概况不等于行动催收；行动建议只消费 Rust 已经生成的最多 10 名确定性推荐。

### 4.2 练卡建议和散件

- 每条练卡建议 1～2 句。
- 每条必须回答建议对象、目标练度，以及练成后的组合或设施用途。
- 建议目标、当前状态、组合身份、设施和效率必须由后端事实填充。
- 高效率散件最多 4 个，按结构化结果的确定性顺序选择；不足 4 个不扩充。
- LLM 不得从未完成组合自行增加干员或行动建议。

## 5. NarrativeInput 与事实约束

NarrativeInput 只包含已经确认的玩家事实和本次报告允许引用的白名单，不直接暴露原始技能表、solver 中间状态或内部 priority。

每个请求建立不可变的引用白名单：

```json
{
  "combinations": {
    "vermeil": { "name": "红云组" },
    "siracusa": { "name": "叙拉古" }
  },
  "operators": {
    "operator-canonical-key": { "name": "红云" }
  }
}
```

LLM 输出必须使用引用占位符，不直接决定最终名称：

```text
{{combination:vermeil}}、{{combination:siracusa}}已经达到成型可用状态。
```

Python narrator adapter 在服务端完成以下步骤：

1. 校验引用 ID 属于本次请求白名单；
2. 校验引用没有超出后端已选择的组合数量；
3. 依据本次请求中的 canonical 映射替换 placeholder；
4. 扫描未知内部字段、未知名称和不允许的自由事实；
5. 只缓存校验通过且已经完成替换的结果。

System Prompt 必须明确禁止：

- 自行计算或改写完成率、效率、目标练度和成员状态；
- 重新排序组合或推荐；
- 推断缺失数据；
- 补充输入中不存在的组合、干员、设施或获取方式；
- 将“应该存在”的组合写入报告；
- 暴露 `priority`、`Plan`、`anchor`、内部 system id 等实现词汇。

事实字段不由模型自由填写。数字、设施、精英阶段、获取方式和组合名称均由后端引用并填充；mapping 不得覆盖 Rust 报告事实。

## 6. Python narrator adapter

adapter 使用 OpenAI-compatible API，配置仅读取环境变量：

```text
TRAINING_ADVICE_LLM_PROVIDER=openai
TRAINING_ADVICE_LLM_BASE_URL=https://api.openai.com/v1
TRAINING_ADVICE_LLM_MODEL=<部署环境配置>
TRAINING_ADVICE_LLM_API_KEY=<Secret 注入>
TRAINING_ADVICE_LLM_REQUEST_TIMEOUT_MS=12000
TRAINING_ADVICE_NARRATIVE_TASK_DEADLINE_MS=20000
TRAINING_ADVICE_NARRATIVE_LOCK_TTL_SECONDS=30
TRAINING_ADVICE_LLM_MAX_OUTPUT_TOKENS=2200
TRAINING_ADVICE_NARRATIVE_MAX_CHARS=6000
```

缺少 key、model 或 provider 配置时，立即使用确定性 fallback，不调用公共模型。

时间控制使用单一 monotonic deadline：每次调用、重试、退避和 JSON 修复只能使用剩余时间。可恢复错误（429、连接暂时失败、502、503、504）最多重试一次；JSON 校验失败最多进行一次修复请求；总预算到期立即 fallback。生产实现还应设置 provider/model 维度的有界并发和队列长度，队列满时直接 fallback。

## 7. canonical mapping

mapping 不写入 Python 业务代码，使用外置 `canonical_mapping.json`，至少包含：

- `mapping_version`；
- `locale`，第一版只支持 `zh-CN`；
- 干员和组合的 canonical 名称、别名及 ID 映射。

mapping 只负责名称、别名和多语言预留，不负责完成度、成员关系、目标练度或推荐排序。

加载策略：

- adapter 启动时加载并完整校验；
- 通过受保护的内部 reload 接口热更新，不使用常驻文件 watcher；
- 新文件校验成功后原子切换，不成功则保留上一份有效配置；
- 首次加载失败时自然语言接口全部 fallback；
- 校验别名唯一性、版本格式和版本单调性；
- mapping 版本/hash 进入缓存键；
- 在途任务固定其开始时的 mapping 快照，完成后仍按该快照校验和替换。

Rust 请求映射是本次报告的事实白名单。mapping 与 Rust 输入不一致时拒绝 LLM 结果并 fallback，不能任选一方，也不能让 mapping 覆盖报告中的事实名称。

## 8. Redis 与高并发

统一使用隔离命名空间，禁止把不同类型数据混在同一 key：

```text
arknights:training_advice:narrative:v1:ready:{content_hmac}
arknights:training_advice:narrative:v1:lock:{content_hmac}
arknights:training_advice:narrative:v1:task:{task_id}
arknights:training_advice:narrative:v1:fallback:{content_hmac}
```

`content_hmac` 由 BFF 使用服务端密钥从规范化后的 report 内容、schema 版本、locale、skill/prompt 版本、mapping hash、模型策略生成。客户端不得提供或决定 hash。外部查询使用随机 `task_id` 并绑定用户身份，不能用 content hash 探测其他用户状态。

锁要求：

- 使用 `SET NX EX`；
- value 保存随机 owner/fencing token；
- 只有 token 所有者可以续租、写入结果和 compare-delete 释放；
- 任务入队、锁和 task state 应在同一 Redis slot 的 Lua/事务边界内完成；
- 入队失败立即写失败态并释放自己的锁；
- worker 崩溃后锁自动过期，旧 worker 不得覆盖新 worker 结果。

高并发预案：

- 100 个相同 hash 的请求只允许一个任务调用 LLM，其余返回 `202 processing`；
- 100 个不同 hash 的请求受 provider/model 有界 semaphore 和队列长度限制；
- 队列满、熔断开启或超出任务 deadline 时直接 fallback；
- Redis Connection Refused/Timeout 时 BFF 立即跳过异步任务和 LLM，POST 若携带可验证 report 则直接返回 fallback，否则返回明确 degraded 状态；
- 该路径不调用、不阻塞、不重试 `plan.compute`。

缓存按状态设置不同 TTL：

- `ready`：较长 TTL；
- `fallback`：较短 TTL，避免长期复用暂时性故障；
- `processing`/task state：短 TTL，防止僵尸任务永久存在。

只缓存校验通过的最终结果。日志使用脱敏字段，只记录状态、耗时、模型、版本、请求 HMAC、fallback 原因和错误类别，不记录完整 OperBox、prompt 或模型原文。

## 9. 降级与前端体验

降级优先级：

1. 已校验 `ready` 缓存；
2. LLM 生成并通过事实校验的报告；
3. 确定性 fallback 报告；
4. 结构化 `PlayerTrainingAdviceReport v2`。

结构化结果必须先可用。前端展示自然语言报告时需要支持：

- `processing` 加载态；
- `ready` 自然语言报告；
- `fallback` 明确标记为自动整理结果；
- 任务过期或 Redis 故障时保留结构化详情；
- 不向用户展示内部错误细节、API key、prompt 或内部 ID。

## 10. 实现工作项

### 当前仓库

- 定义 `NarrativeInput`、`NarrativeOutput`、placeholder 和引用 schema；
- 增加 Rust 确定性投影 builder；
- 复用 `PlayerTrainingAdviceReport v2` 的向下取整完成率；
- 实现组合/干员引用白名单和 fallback renderer；
- 实现 Python narrator adapter、配置加载和 OpenAI-compatible client；
- 实现 mapping 加载、校验、reload 和不可变快照；
- 实现 JSON 输出校验、事实填充、名称替换和禁止字段扫描；
- 增加超时、重试、修复请求、熔断和高并发测试；
- 增加部署、环境变量和健康检查说明。

### 外部 BFF 与前端

- 暴露 `training_advice.narrative` POST/GET 路由；
- 接入登录态、用户/IP 限流和配额；
- 实现 Redis key、SET NX 锁、fencing token、任务队列和分状态 TTL；
- 处理 Redis 故障、队列过载和任务超时；
- 先展示结构化结果，再异步补充自然语言；
- 保留结构化组合详情和成员练度状态；
- 支持移动端的章节、加载、fallback、过期和重试状态。

## 11. 非目标

- 不修改 `plan.compute` 的结构化契约；
- 不让 LLM 参与 solver、组合完成度计算或推荐排序；
- 不在前端保存或调用 LLM API key；
- 第一版不支持 `zh-CN` 之外的语言；
- 不实现常驻 mapping 文件 watcher；
- 不在当前仓库伪造 BFF、Redis 或生产登录系统；
- 不允许自然语言报告替代组合图鉴中的完整结构化事实。

## 12. 验收重点

- 100 个相同 hash 请求只有一个 LLM 任务；
- 100 个不同 hash 请求不会突破 provider 并发上限；
- 锁过期后旧 worker 不能覆盖新结果；
- provider 超时、429、5xx、配置缺失、Redis refused/timeout 都能确定性降级；
- LLM 不能改变组合顺序、完成率、精几、设施、干员名或推荐数量；
- mapping reload 失败不破坏上一份有效配置；
- `plan.compute` 在 LLM、Redis 和 narrator 服务故障时保持原有行为。
