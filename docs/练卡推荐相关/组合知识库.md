# 练卡推荐组合知识库

> 文档角色：canonical
> 生命周期状态：current
> 领域键：advice.training.combinations
> 当前真源：self
> 摘要：定义练卡组合规范名、产物、设施、玩家角色层级、完成状态和展示约束

## 1. 本知识库与排班求解的关系

练卡推荐和排班求解共享干员技能、设施和组合知识，但不是同一件事：

- 直接访问练卡推荐时，只比对干员盒、目标练度和组合完成情况，不先求解排班；
- 从排班结果进入时，可以额外消费求解器已经给出的布局、产物安排、现有解和人均效率，但推荐层不得自行重算；
- 本文的“核心、重要、次级、挂件”用于解释培养与收集价值，不等同于求解器内部的准入约束或优先级；
- “高效率组合、低效率组合”是当前人工确认的展示层级，不是标准平均效率系数，也不是全局最优证明；
- 将来若传入平均效率系数，只能作为已有求解结果的附加输入，不能反向替代本文的持有与练度比对。

## 2. 统一分类与成员层级

玩家侧固定产物顺序：

```text
贸易 → 赤金 → 经验 → 通用制造 → 搓玉
```

每种产物内部固定展示顺序：

```text
高效率组合 → 低效率组合 → 高效率散件
```

“通用制造”指可用于赤金、经验等多种制造配方的组合。红云组归入经验制造，深海猎人组归入通用制造。搓玉当前只维护干员名单，不建立组合，见《高效率散件与搓玉名单》。

成员层级统一解释如下：

| 层级 | 含义 | 推荐处理 |
|---|---|---|
| 核心 | 决定组合身份或启动主要机制的角色 | 缺少或未达到目标时，优先产生收集或培养建议 |
| 重要 | 提供主要增益、关键分支或把基础形态提升到推荐形态的角色 | 核心齐全后优先补；可包含“多选一、三选二”等分支要求 |
| 次级 | 能继续提高收益或作为常用替换，但不是优先补齐对象 | 与高效率散件同层比较后再推荐 |
| 挂件 | 本身不为目标设施直接提供效率，只为其他角色提供人数、标签、数值或计数 | 最后考虑；不得写成独立高效率角色 |

未在本文明确写出目标精英阶段的角色，**不得**由大模型猜测统一精二。默认目标练度复用现有干员组合/技能数据：`data/operator_instances.json` 的 `tier_0`/`tier_up` 设施绑定，以及与 pool/search 相同的 `PromotionTier` 星级门槛（详见《玩家输出口径》§10 / C7）。知识库仍可在表中显式覆盖个别角色。

## 3. 组合完成状态

系统对每个组合至少计算以下状态：

| 状态 | 判断 | 玩家侧处理 |
|---|---|---|
| 已成型 | 所需核心已拥有并达到目标练度，所选重要分支也达到推荐形态 | 可以在“已成型组合摘要”中打勾或高亮 |
| 持有可启动、练度不足 | 启动所需角色均已拥有，但至少一名核心或所选重要分支未达到目标练度 | 进入“待完成组合建议”，说明练谁、练到什么阶段、练完后如何上班 |
| 缺核心、暂时无法启动 | 至少一名核心未拥有 | 记录为收集缺口；通常不展开所有次级和挂件。是否对缺失核心生成**收集行动建议**见下方 C2 |
（“部分可用”及其 30% 合格形态规则已废弃。组合状态只使用“已成型”“持有可启动、练度不足”“缺核心、暂时无法启动”和必要的 NeedsReview。）

**缺核心时的收集建议（C2，2026-07-29 裁决）：**

- **可生成**收集/培养行动建议，当且仅当：重要角色侧已集齐（无重要角色则视为已满足；分支型重要条件至少一条推荐形态分支所需角色均已拥有），且合计缺少的核心不超过 **2** 名。
- **否则**只保留状态与缺口记录，不把非新手高稀有核心写成催收待办，也不因缺核心而展开次级/挂件收集清单。
- 已在《新手必练与必收集名单》中的核心仍按新手层与《玩家输出口径》截断规则处理，不因本条放宽或收紧新手义务。
- 报告名额与措辞以《玩家输出口径》§5.2 为准。

同一角色可以在知识库中保留多个身份，报告中必须合并成一条建议：

- 可启动组合中的核心身份优先于重要、散件、次级和挂件身份；
- 若组合因其他核心缺失而无法启动，但该角色仍满足高效率散件条件，可以改用散件作为主要理由；
- 不在主要理由后追加“同时也是散件”等较低层理由；
- 每个产物在账号概况中最多提及 2～3 个常用、可用或完成度较高的组合。

**多组合 / 多身份优先（T1 / T2 / T3 / T7，2026-07-29 修订）：**

| 冲突 | 裁决 |
|---|---|
| **T1** 人间烟火组 ↔ 感知信息组（共享琴柳等） | 摘要与待办**优先感知信息组**；人间烟火仍算完成态，同轮不与感知抢同一共享角色的主理由名额 |
| **T2** 能天使：能天使组（原拉特兰）核心 + 企鹅物流重要 | **优先启动能天使组**；企鹅物流可启动时不以能天使为主推理由 |
| **T3** 多身份（含砾等） | **凡与新手名单目标未完成重叠的，一律新手理由优先**；新手已完成后，再按组合核心＞重要＞散件/次级＞挂件 |
| **T7** 乌尔比安 | **深海猎人重要**与**深巡＋乌尔比安挂件**两种身份**同时成立**；完成态两边都算。行动建议仍合并为一条干员记录，主理由可并列两组关系，不强制二选一压掉另一组 |

共享成员默认只占一条 ≤10 名额；T7 允许一条建议内写清双重组合关系。

### 6.2 计算边界

火神的高数值依赖同站角色，不属于高效率散件：

```text
红云组：19 × 2 - 5 = 33%
泡泡组：19 × 3 - 5 = 52%
```

52% 只能作为泡泡组内的火神收益说明，不能对玩家写成“火神单人 52%”。

### 6.3 默认隐藏项

- 怒潮凛冬**经验组**默认不展示（不作为独立组合推荐）。
- **怒潮凛冬身份（C6 修订）：** 日常作**经验高效率散件**使用，目标**精零**即可；见《高效率散件与搓玉名单》。新手名单精零与散件精零同目标，去重为一条。不恢复怒潮经验组对外展示。

## 10. 后续实现约束

- `data/training_recommendations.json` 等旧提案数据不能作为本文的反向真源；新前端运行时知识由 `data/training_advice_knowledge.json` 按本文承载。
- 组合结果至少需要输出规范名、产物、设施范围、完成状态、核心缺口、重要分支缺口、推荐成员和目标练度。
- 分支组合必须保存结构化条件；例如红云组是“两条分支任选一条”，不能展平成所有角色都必需。
- 默认隐藏项可以参与内部知识核对，但不得进入普通玩家报告。
- 任何组合的精确效率、平均效率或练成前后实际提升，必须由机制计算或求解器结果提供；大模型只能解释已确认结果。
- **成员目标练度定稿表**见 [组合成员练度审阅稿](组合成员练度审阅稿.md)（2026-07-29 已批）；与本文冲突时以审阅稿批注 + 用户最新裁决为准并回写本文。
