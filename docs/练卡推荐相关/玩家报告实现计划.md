## 0. 目标与非目标

### 目标

给定 `operbox`（可选布局/效率上下文），先输出符合《玩家输出口径》的三块确定性数据：全量未完成基础名单、17 组组合完成度、去重后最多 10 人的行动建议。未来 AI 只消费这份结构化事实并生成五章自然语言报告，不在当前 builder 中生成文案。

### 非目标

| 禁止 | 原因 |
|---|---|
| 修改 `search/**`、`schedule/**` 或主路径 solver 策略 | 练卡建议只消费既有 operbox、布局和效率事实 |
| 玩家角色写入 Plan hard admission | 产品边界 |
| 用旧 `training_recommendations.json` 当玩家真源 | 已归档 v2 合同 |
| 凯尔希办公室机制 / 五章 AI 渲染 | 另 TODO |

### 成功标准（直接访问）

1. `incomplete_newbie` 保留全量未完成事实，T9 只改变章节状态和行动候选。
2. `combinations` 固定输出 17 组规范名、完成状态与逐成员持有/练度状态。
3. `recommendations` 去重且不超过 10 人，包含目标练度、主理由和稳定优先级。
4. 布局/效率上下文只触发已裁决条件，不从未知事实猜测效率。
5. 旧诊断 JSON 继续兼容，但不决定玩家语义或未来 AI 文案。

## 2. 架构

```text
docs/练卡推荐相关/*  →  training_advice_knowledge.json
                      →  player::build_player_report
                      →  advice --player / plan.compute.training_advice
                      →  未来 AI render 五章（未实现）
旧 evaluate + training_recommendations.json  →  diagnose 兼容
```

可选 `PlayerAdviceContext`：布局可确定的源石线、会客室、宿舍、工程机器人，以及调用方确认的贸易/制造人均效率。`advice` 内不重跑全量 search，也不从总产出猜测人均效率。

## 6. C/E 后仍开放的知识与上下文项

- 水月本人的目标练度尚未单批，保持 `needs_review`。
- 红云组黑角/蛇屠箱等、动态金属工艺成员、动态莱茵科技成员缺少封闭成员表或目标绑定，不猜测枚举。
- T11“部分可用”需要求解器传入组合级实际效率（≥30%）和现有编制；当前不从盒子或布局臆算。
- 吉星、苍苔、槐琥需要实际同站编制事实；知识和条件已保存，但当前布局上下文不能单独证明时不进入行动建议。
- 产物数量加权仍为可选策略；当前最新用户裁决要求同层按 17 组顺序，E 阶段不以布局打乱该顺序。

产品映射与风险详见会话中的完整计划讨论；细节以同目录 canonical 与审阅稿为准。
