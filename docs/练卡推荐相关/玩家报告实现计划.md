## 0. 目标与非目标

### 目标

给定 `operbox`（可选布局/效率上下文），输出符合《玩家输出口径》的五章报告与 ≤10 人约束（C1–C10 / T 系列 / 审阅稿）。

### 非目标

| 禁止 | 原因 |
|---|---|
| `layout/**`、`search/**`、`schedule/**`、主路径 solver | 并行 agent |
| 玩家角色写入 Plan hard admission | 产品边界 |
| 用旧 `training_recommendations.json` 当玩家真源 | 已归档 v2 合同 |
| 凯尔希办公室机制 / 完整 LLM | 另 TODO |

### 成功标准（直接访问）

1. 稀盒 ≤10、C1 六人优先、无 acquire 洪水。  
2. 组合规范名 + 四问句。  
3. 多身份主理由符合 T1–T3/T7。  
4. 旧 `--pretty` JSON 可保留 diagnose，不决定玩家文案。

