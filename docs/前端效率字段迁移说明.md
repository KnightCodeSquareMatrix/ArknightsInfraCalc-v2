# 前端效率字段迁移说明

> 文档角色：current-reference
> 生命周期状态：current
> 当前真源：docs/FRONTEND_CLI.md
> 摘要：说明前端迁移到统一效率字段的读取、展示和验收要求

后端真源：[EFFICIENCY_MODEL.md](EFFICIENCY_MODEL.md)。

## 1. 这次必须改什么

前端不再根据旧的 `*_skill_efficiency`、房间人数、中枢加成或订单类型自行拼出完整效率和产出。

所有房间效率展示、跨班次效率汇总和产出预估，统一消费后端已经结算的：

```text
rotation.shifts[].efficiencies.room_lines[]
```

一次性 CLI 使用 `--profile-out` 时，读取同一份 profile 中的：

```text
rotation.shifts[].efficiencies.room_lines[]
```

常驻 Worker 使用 `method: "plan.compute"` 时，读取响应中的：

```text
result.rotation.shifts[].efficiencies.room_lines[]
```

不要解析 stdout/stderr 的中文文本作为结构化数据。

## 2. 新字段定义

每个生产房间的 `room_lines[]` 使用以下字段。JSON 中值为直接小数，不是百分数；例如 `1.550` 表示 `155%`。

| 字段 | 含义 | 前端显示建议 |
|---|---|---|
| `room_id` | 实际房间 ID | 用于定位房间；不要假设固定房间数量或固定顺序 |
| `operator_count` | 当前房间实际入驻人数 | 人数展示和调试校验 |
| `base_efficiency` | 贸易/制造房间的设施基准 `1.000` 与非红脸（心情大于 0）干员进驻增量之和；发电站行固定为 `0.000`，共享发电基础只在发电域汇总注入一次 | 基础效率 |
| `operator_efficiency` | 干员技能提供的效率；发电站还包含技能驱动的爬升增量 | 干员技能效率 |
| `global_efficiency` | 中枢或其他设施写入的全局效率 | 全局加成 |
| `station_efficiency` | 兼容字段，混合进驻增量与全局加成 | 兼容读取，不用于当前分解或再次求和 |
| `total_efficiency` | 贸易/制造为 `base + operator + global`；发电站为该站岗位增量，不含共享 `1.000` | 总效率 |
| `equivalent_efficiency` | 已结算效率的等效解释值，不额外计入总效率或产出 | 等效效率 |
| `trade_output_per_day` | 贸易单位日产出 × 总效率 | 贸易日产出 |
| `gold_consumption_per_day` | 内部贸易结算字段，公开产物汇总不返回 | 不读取 |
| `trade_equivalent_efficiency` | 贸易特殊单位产出对应的等效技能效率 | 贸易等效效率 |
| `gold_equivalent_efficiency` | 赤金特殊单位产出对应的产能效率，不扣除基础、中枢或贸易消耗 | 赤金等效效率 |
| `combined_output_value` | 按用户裁决的贸易:赤金 `1:1` 归一化单房诊断值；不属于通用效率或日汇总 | 双产出综合值 |
| `final_efficiency` | 已从公开接口移除 | 不读取 |

后端字段可能因值为零而被 JSON 省略。前端读取时将省略的效率字段按 `0.000` 处理；`order_multiplier` 缺失时按 `1.000` 处理。不要把缺失字段当成协议错误。

轮换报告的 `daily.production` 使用最终产物字段：`lmd`（贸易站龙门币订单）、`pure_gold`（制造站赤金）、`battle_records`（制造站作战记录）、`orundum`（贸易站「开采协力」合成玉订单）和 `originium_shards`（制造站源石碎片）。贸易订单交付消耗的赤金、源石碎片不属于最终产物汇总，也不应由前端自行扣减。数值按全部班次的实际时长加权，并归一到 24h 平均值。

会客室效率由以下百分比直接加算：`干员技能效率 + 精英化基础加成 + 稀有度基础加成 + 非红脸进驻加成`。其中非红脸进驻加成为 `5%`，稀有度 1–3/4/5/6 星为 `0/2/4/5%`，精英化 0/1/2 为 `0/8/16%`；0 心情只取消 `5%`，不取消稀有度和精英化加成。

## 3. 统一公式

### 3.1 贸易站与制造站

```text
base_efficiency = 1.000 + nonzero_mood_operator_count × 0.010
total_efficiency = base_efficiency + operator_efficiency + global_efficiency
```

发电站单站 `total_efficiency` 只表示该站岗位增量；发电域总效率为 `1.000 + Σ 发电站 total_efficiency`，没有有效发电站时为 `0.000`。

### 3.2 贸易站

```text
trade_output = trade_unit_output_per_day × total_efficiency × work_time / 24
gold_output = gold_unit_output_per_day × total_efficiency × work_time / 24
```

特殊组合的贸易和赤金产出独立返回。前端不得把单位产出倍率乘回 `total_efficiency`，也不得把任一等效效率再次用于产出。
`combined_output_value` 仅用于同一房间的双产出比较，不用于累计 `daily.production`、跨房总分或反推资源数量。

### 3.3 制造站和发电站

制造站按配方单位日产出计算产出；统一单位日产出为经验 `8000`、赤金 `10000`。源石碎片/合成玉订单单位日产出为 `240`。

```text
output = unit_output_per_day × total_efficiency × work_time / 24
```

发电站如果有额外内部机制，后端已经计入 `operator_efficiency` 或对应最终效率，前端不重新实现公式。

## 4. 跨房间和跨班次汇总

生产域汇总使用后端给出的分域直接效率：

```text
trade_total = Σ trade_room.total_efficiency
manufacture_total = Σ manufacture_room.total_efficiency
power_total = 1.000 + Σ power_room.total_efficiency
```

不要跨域相加，也不要将基础效率中已有的进驻增量或全局加成再次计入总效率。

班次加权值直接使用后端输出的：

```text
weighted_trade
weighted_manufacture
weighted_power
```

日汇总直接使用 rotation summary 中对应的贸易、制造、发电字段。前端只做格式化，不重新按班次时长计算产出。

## 5. 旧字段处理

当前响应中可能仍出现以下旧的解释字段：

```text
trade_skill_efficiency
manufacture_skill_efficiency
power_skill_efficiency
trade_efficiency
manufacture_efficiency
power_efficiency
```

这些字段不能用于推导总效率或产出。迁移规则如下：

1. 房间展示读取 `base_efficiency`、`operator_efficiency`、`global_efficiency`、`total_efficiency`，贸易站另读 `order_multiplier`、`equivalent_efficiency`。
2. 产出直接读取后端的单位产出、weighted 或 daily 字段。
3. 不根据 `operator_count` 补算入驻加成。
4. 不根据旧字段名判断贸易、制造或发电的公式。
5. 不因为旧字段仍存在而在前端保留第二套效率口径。

`domains[].current` 和 `domains[].baseline` 目前主要用于账户画像对比；房间级效率与产出以 `room_lines[]` 为准。

## 6. 最小读取示例

```ts
type RoomEfficiencyLine = {
  room_id: string;
  operator_count: number;
  base_efficiency?: number;
  operator_efficiency?: number;
  global_efficiency?: number;
  station_efficiency?: number;
  total_efficiency?: number;
  order_multiplier?: number;
  equivalent_efficiency?: number;
  trade_output_per_day?: number;
  gold_output_per_day?: number;
  trade_equivalent_efficiency?: number;
  gold_equivalent_efficiency?: number;
  combined_output_value?: number;
  manufacture_unit_output_per_day?: number;
  manufacture_output_per_day?: number;
};

const value = (n: number | undefined, fallback = 0) => n ?? fallback;

function outputEfficiency(line: RoomEfficiencyLine): number {
  return value(line.total_efficiency);
}

function displayBreakdown(line: RoomEfficiencyLine) {
  return {
    base: value(line.base_efficiency),
    skill: value(line.operator_efficiency),
    global: value(line.global_efficiency),
    multiplier: value(line.order_multiplier, 1),
    total: value(line.total_efficiency),
    tradeOutputPerDay: value(line.trade_output_per_day),
    goldOutputPerDay: value(line.gold_output_per_day),
    tradeEquivalent: value(line.trade_equivalent_efficiency),
    goldEquivalent: value(line.gold_equivalent_efficiency),
    combinedOutputValue: value(line.combined_output_value),
  };
}
```

示例中 `outputEfficiency` 只读取后端总效率；实际产出读取后端产出字段，不再读取或计算 `final_efficiency`。

## 7. 验收标准

前端修改完成后，至少验证以下内容：

- 贸易房间显示 `total_efficiency`、订单倍率、单位产出和实际产出；前端不读取 `final_efficiency`。
- 制造、发电房间显示各自的 `total_efficiency` 和后端实际产出字段。
- 等效效率直接读取后端 `equivalent_efficiency`，不从其他字段反推或再次计入总效率。
- 跨房间汇总与后端 `trade_efficiency`、`manufacture_efficiency`、`power_efficiency` 一致。
- 三班排班使用后端 `weighted_trade`、`weighted_manufacture`、`weighted_power`，不重复按时长折算。
- 房间列表按响应中的 `room_id` 渲染，不写死 `trade_1`、`trade_2` 或固定房间顺序。
- `plan.compute` 和一次性 `plan` 的同一输入展示一致。
- 缺失零值字段不会导致页面崩溃或显示 `undefined`。
- 真实 243 Full E2 输入能生成三班结果和 MAA；效率字段不含 CLI 路径、调试对象或内部日志。

## 8. 不在本次前端修改范围内

- 不在前端实现贸易订单机制、制造公式、发电公式或中枢加成规则。
- 不修改 `mechanic_equivalent_efficiency` 的领域含义；它只是贸易机制解释字段，不参与第二次乘法。
- 不删除后端旧兼容字段；前端先停止消费它们，旧入口退役另行跟踪。
- 不把跨域效率合成匿名总分。
