# 前端效率字段迁移说明

> 文档角色：current-reference
> 生命周期状态：current
> 当前真源：docs/FRONTEND_CLI.md
> 摘要：说明前端迁移到统一效率字段的读取、展示和验收要求

后端真源：[EFFICIENCY_MODEL.md](EFFICIENCY_MODEL.md)。

## 1. 这次必须改什么

前端不再根据旧的 `*_skill_efficiency`、房间人数、中枢加成或订单类型自行拼出完整效率和产出。

所有房间效率展示、跨班次效率汇总和产出预估，统一消费后端已经结算的：

```text
rotation.shifts[].efficiencies.room_lines[]
```

一次性 CLI 使用 `--profile-out` 时，读取同一份 profile 中的：

```text
rotation.shifts[].efficiencies.room_lines[]
```

常驻 Worker 使用 `method: "plan.compute"` 时，读取响应中的：

```text
result.rotation.shifts[].efficiencies.room_lines[]
```

不要解析 stdout/stderr 的中文文本作为结构化数据。

## 2. 新字段定义

每个生产房间的 `room_lines[]` 使用以下字段。JSON 中值为直接小数，不是百分数；例如 `1.550` 表示 `155%`。

| 字段 | 含义 | 前端显示建议 |
|---|---|---|
| `room_id` | 实际房间 ID | 用于定位房间；不要假设固定房间数量或固定顺序 |
| `operator_count` | 当前房间实际入驻人数 | 人数展示和调试校验 |
| `operator_efficiency` | 白字：干员本人及直接作用于干员的技能效率 | 白字 |
| `station_efficiency` | 绿字：入驻人数、 中枢和其他设施的全局/工位加成 | 绿字 |
| `total_efficiency` | 倍率前总效率 | 总效率 |
| `order_multiplier` | 订单或产出类型倍率；非贸易房间为 `1.000` | 需要时显示倍率 |
| `final_efficiency` | 倍率后实际效率，唯一产出和排序真源 | 最终效率/产出效率 |
| `equivalent_efficiency` | 蓝字：扣除基础 `1.000` 和绿字后的等效效率 | 蓝字 |

后端字段可能因值为零而被 JSON 省略。前端读取时将省略的效率字段按 `0.000` 处理；`order_multiplier` 缺失时按 `1.000` 处理。不要把缺失字段当成协议错误。

## 3. 统一公式

### 3.1 所有生产房间

```text
total_efficiency = 1.000 + operator_efficiency + station_efficiency
```

### 3.2 贸易站

```text
final_efficiency = total_efficiency × order_multiplier
```

贸易站的 `final_efficiency` 已经包含订单/单位产出倍率。前端不得再次乘订单倍率，也不得把 `equivalent_efficiency` 再乘一次。

### 3.3 制造站和发电站

制造站和发电站没有订单倍率：

```text
order_multiplier = 1.000
final_efficiency = total_efficiency
```

发电站如果有额外内部机制，后端已经计入 `operator_efficiency` 或对应最终效率，前端不重新实现公式。

## 4. 跨房间和跨班次汇总

生产域汇总只累加每个房间的 `final_efficiency`：

```text
trade_total = Σ trade_room.final_efficiency
manufacture_total = Σ manufacture_room.final_efficiency
power_total = Σ power_room.final_efficiency
```

不要跨域相加，也不要把白字、绿字、人数或中枢加成再次累加。

班次加权值直接使用后端输出的：

```text
weighted_trade
weighted_manufacture
weighted_power
```

日汇总直接使用 rotation summary 中对应的贸易、制造、发电字段。前端只做格式化，不重新按班次时长计算产出。

## 5. 旧字段处理

当前响应中可能仍出现以下旧的解释字段：

```text
trade_skill_efficiency
manufacture_skill_efficiency
power_skill_efficiency
trade_efficiency
manufacture_efficiency
power_efficiency
```

这些字段不能用于推导总效率、最终效率或产出。迁移规则如下：

1. 房间展示改读 `operator_efficiency`、`station_efficiency`、`total_efficiency`、`order_multiplier`、`final_efficiency`、`equivalent_efficiency`。
2. 产出计算只读 `final_efficiency`，或直接使用后端的 weighted/daily 字段。
3. 不根据 `operator_count` 补算入驻加成。
4. 不根据旧字段名判断贸易、制造或发电的公式。
5. 不因为旧字段仍存在而在前端保留第二套效率口径。

`domains[].current` 和 `domains[].baseline` 目前主要用于账户画像对比，贸易域的 `final_efficiency` 仍是可直接比较的最终值；房间级白/绿/总/最终/蓝分解以 `room_lines[]` 为准。

## 6. 最小读取示例

```ts
type RoomEfficiencyLine = {
  room_id: string;
  operator_count: number;
  operator_efficiency?: number;
  station_efficiency?: number;
  total_efficiency?: number;
  order_multiplier?: number;
  final_efficiency?: number;
  equivalent_efficiency?: number;
};

const value = (n: number | undefined, fallback = 0) => n ?? fallback;

function outputEfficiency(line: RoomEfficiencyLine): number {
  return value(line.final_efficiency);
}

function displayBreakdown(line: RoomEfficiencyLine) {
  return {
    operator: value(line.operator_efficiency),
    station: value(line.station_efficiency),
    total: value(line.total_efficiency),
    multiplier: value(line.order_multiplier, 1),
    final: value(line.final_efficiency),
    equivalent: value(line.equivalent_efficiency),
  };
}
```

示例中 `outputEfficiency` 不应改成重新计算 `total × multiplier`；该公式只用于测试校验，实际产出直接使用后端的 `final_efficiency`。

## 7. 验收标准

前端修改完成后，至少验证以下内容：

- 贸易房间同时能显示倍率前 `total_efficiency` 和倍率后 `final_efficiency`。
- 制造、发电房间显示 `final_efficiency == total_efficiency`，倍率为 `1.000`。
- 蓝字使用后端 `equivalent_efficiency`，不由前端从旧字段反推。
- 跨房间汇总与后端 `trade_efficiency`、`manufacture_efficiency`、`power_efficiency` 一致。
- 三班排班使用后端 `weighted_trade`、`weighted_manufacture`、`weighted_power`，不重复按时长折算。
- 房间列表按响应中的 `room_id` 渲染，不写死 `trade_1`、`trade_2` 或固定房间顺序。
- `plan.compute` 和一次性 `plan` 的同一输入展示一致。
- 缺失零值字段不会导致页面崩溃或显示 `undefined`。
- 真实 243 Full E2 输入能生成三班结果和 MAA；效率字段不含 CLI 路径、调试对象或内部日志。

## 8. 不在本次前端修改范围内

- 不在前端实现贸易订单机制、制造公式、发电公式或中枢加成规则。
- 不修改 `mechanic_equivalent_efficiency` 的领域含义；它只是贸易机制解释字段，不参与第二次乘法。
- 不删除后端旧兼容字段；前端先停止消费它们，旧入口退役另行跟踪。
- 不把跨域效率合成匿名总分。
