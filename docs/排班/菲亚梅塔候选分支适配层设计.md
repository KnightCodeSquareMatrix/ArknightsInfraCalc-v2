## 1. 一句话结论

菲亚梅塔候选分支适配层是 ABC 三班排班的一个**薄选择层**：同一 Box 独立完整求解
N / A / B 三个候选，用完整周期收益比较选 winner，平局保留 N。该规则适用于 named ABC
和普通泛型 ABC；泛型候选均使用调用方的实际班时，并按同一 α 相位构造，不能借用 named
profile 的固定时长。适配层不拥有进编、
钉岗、房间分配、组合判定或排班最终化责任；候选差异只通过轻量机制表达，其余全部
交给既有自然搜索与编排规则。

## 2. 适配层职责边界

适配层只做三件事：

1. **候选差异 = 求解输入的轻量偏好**：每个候选以不同 options 调用既有完整
   `schedule_abc_rotation` 入口，状态隔离；
2. **菲亚动作 = 只换心情不改 assignment**：在候选完整结果上对固定目标各写一次
   `FiammettaShiftAction`，不 refill、不钉岗、不改房间成员；
3. **收益比较 = 完整周期产物价值**：候选 finalization 后读取 `daily.production`，
   按 `lmd:1 + pure_gold:1 + battle_records:1.25` 计算唯一 value，平局保留 N。

适配层**不是**：

- 预排 seed 锁房 / 中间态构造（已实测产生 γ 抢房连锁回归，放弃）；
- 局部 refill / 事后找班次写动作（旧路径，语义与候选不匹配，放弃）；
- 通用能力影子候选协调器（能力影子候选设计.md 为延期 proposal，不并入）；
- 新的体系选型或组合判定 owner（全部复用既有 shortcut / 规则）。

## 3. 候选定义与降级

| 候选 | 策略 | 菲亚动作目标 | 资格 |
|---|---|---|---|
| N | 不使用菲亚的完整基线 | 无 | 始终参与 |
| A | 但书 / 可露希尔单核心，`system_preferences` 偏好 trade_core 选择 | 但书一次、可露希尔一次（各换一次心情） | 存在金单贸易站，且但书任意练度或可露希尔精二至少其一 |
| B | 巫恋 + 龙舌兰完整站，靠 L1 shortcut 自然选中 | 巫恋一次、龙舌兰一次（各换一次心情） | 存在三级金单贸易站，且 `match_witch_group_shortcut` 能判定合法完整龙巫组 |

降级规则：

- A 按布局降级：单贸易站 153 布局优先可露希尔；其余布局优先但书；以候选干员
  实际拥有情况优先；
- B 完整条件不足（缺角色、未达练度、无合法裁缝、无三级金单站）时直接放弃 B，
  不允许降级为单人；
- 两者都不满足时直接返回 N 的完整结果，不进入分支比较。

## 4. 候选差异机制

### 4.1 A 分支：trade_core 偏好

A 候选通过 `system_preferences` 写入 `trade_core=<alternative_id>` 偏好
（`single_trade_closure` / `single_trade_docus_fallback` / `multi_trade_docus` /
`multi_trade_closure_fallback`）。偏好是**排序不是强制**：但书 alternative 排最前，
gate 不满足时自动降级到可露希尔，不改变候选集合。无偏好时 N 分支保持现状。

### 4.2 B 分支：巫恋优先 + γ 放行

- B 候选跳过 `trade_core` 规则（不抢占但书锚点），并让巫恋组在 peak 的贸易
  自然搜索中优先尝试（首选 role 不可行时回退默认顺序）；
- γ（S2/S3）从 used 集合放行巫恋、龙舌兰，使它们跨班持续在岗；
- 放行仅当目标尚未在 coexist 班次在岗时生效，避免同一目标在另一间贸易房重复
  落位（multiple room slots）。

### 4.3 状态隔离

N/A/B 各自从同一原始 Box 独立完整求解：assignment、used、teams、H1/H2、中枢、
宿舍、轮换状态互不复用；只共享只读静态数据（layout、operbox、skill table、
instances、静态 pool）。

## 5. 菲亚动作语义

- 动作只写入 `TeamShiftResult.fiammetta`，不改 assignment 成员、不做跨班 refill；
- 用 `fiammetta_ready_events` 校验（菲亚 +2/h 攒满 + 目标在岗才 ready）；
- A/B 各目标各换一次心情，动作次数、时机、目标去重遵守
  docs/排班/菲亚梅塔使用规则.md；
- 目标"持续工作资格"（每班在岗）由 L1 shortcut 自然选中 + 既有
  `validate_fiammetta_continuous_targets` 兜底；目标无法每班在岗时该候选 reject，
  回落到 N（不伪造动作）。

## 6. 收益比较

- 候选评价只使用各自完成 finalization 后的完整周期产物，不比较菲亚目标房间的
  局部效率；
- `daily.production` 由现有产物 owner 按全部班次时长归一到 24h 后生成，候选比较
  不重新计算、不读取局部 `combined_output_value`；
- 菲亚候选唯一 value 函数为：

  ```text
  value = daily.production.lmd
        + daily.production.pure_gold
        + daily.production.battle_records × 1.25
  ```

- 该权重是菲亚候选决策专用的用户价值政策，不改变通用效率模型、trade/manufacture
  搜索排序或其他 profile；
- `orundum`、`originium_shards`、`power` 不进入本轮 value；
- 平局时保留基线 N，不为形式上的菲亚动作破坏排班；
- 候选 A/B 可能因自然搜索与 N 的 value 相同（该 box 上策略无优势），这是正确行为；
  候选只在真实 value 更高时胜出；完全相等时保留 N。
- `--fiammetta-candidates-out` 输出的 N/A/B JSON 是自包含审计对象，包含
  `value_policy`、`value`、`daily_production` 和完整 `report`，不会要求调用方从日志
  反推 winner value。

## 7. 贸易组合竞争规则（黑键 / 但书 / 巫恋 / 伺夜）

用户 2026-08-30 校准的贸易组合事实：

1. **黑键不是散件**：黑键与迷迭香是绑定组合，同队同上同下（`bind_roles` 声明），
   黑键效率随感知数变化（`floor(感知/2)`，满配约 48%），不是固定效率，也并非
   全游戏贸易最高；
2. **黑键同站自由**：黑键可以与可露希尔同站，也可以与但书同站，最终由该排班
   实际跑出的效率更高者决定；不存在"黑键必须配可露希尔"的硬约束；
3. **但书站选队友有绝对优先权**：但书作为 trade_core 锚点优先占位，其队友由
   效率搜索决定（可含伺夜+贝洛内叙拉古链、能天使+蕾缪安等）；
4. **黑键 ≠ 巫恋同站**是全布局产品约束（`ROSEMARY_PERCEPTION_CHAIN.md` §2.3），
   包含二发电和感知体系未启动时，由贸易搜索统一过滤并由最终班表断言；
5. **感知链三组合轮换**（`ROSEMARY_PERCEPTION_CHAIN.md` §1）：体系启动且三组合
   可形成时，peak=A+B（但书站 + 黑键可露希尔站）、γ 复用 C（巫恋组），形成
   A+B → B+C → C+A；该规则不固定房号或队伍标签，也不把黑键—可露希尔扩张为
   全局固定组合。

候选分支与上述规则的关系：B 分支的巫恋优先在感知链激活时可能与三组合轮换竞争
（3 体系抢 2 个贸易房），此时目标无法每班在岗 → 候选 reject 回落 N，由感知链
轮换胜出——这是收益最大化的正确行为，不是失败。

## 8. 明确不改

- `fiammetta_8_8_4_4`（8844）、主备二班 `12/12`、深海
  `7/5/7/5` profile 的既有语义与入口；
- 贸易/制造公式、效率模型、无人机、电力、心情结算 owner；
- Mower 动态换班、完整实时心情曲线、跨周期永续排班、宿舍槽位模拟；
- MAA 输出协议与宿舍输出责任；
- 测试代码（验证走 Rust 最终状态 `--assert-invariants` gate + Python 持久化 box
  批量求解 + Sol 复审，不新增/修改源代码内测试）。

## 9. 已知边界与待办

- 候选 A/B 在感知链激活等体系竞争场景下可能 reject，属预期行为；
- γ 放行与 coexist 在岗检查的交互需要批量 box 持续验证；
- 贸易体系组合覆盖（黑键/伺夜/贝洛内/德克萨斯链等）是既有搜索 coverage 问题，
  与适配层正交，作为独立 quality 跟踪。
