## 1. Worker 连接

`infra-cli serve` 是长驻子进程，前端通过 stdin/stdout 传输 NDJSON。每行一个 JSON 对象，stdout 只能输出协议帧，日志在 stderr。

```json
{"id":0,"method":"ping","params":{}}
```

兼容 Worker 的 ping 结果包含：

```json
{
  "protocol_version": 1,
  "plan_schema_version": 1,
  "supported_plan_schema_versions": [1, 2, 3],
  "plan_contract_sha256": "<v1 sha256>",
  "plan_contract_sha256_by_version": {
    "1": "<v1 sha256>",
    "2": "<v2 sha256>",
    "3": "<v3 sha256>"
  },
  "solver_executable_sha256": "<sha256>",
  "solver_git_commit": "<commit or null>",
  "solver_built_at": "<UTC timestamp or null>"
}
```

兼容判断：

- v1 请求：`protocol_version === 1` 且 `plan_schema_version === 1`。
- v2 请求：除上述条件外，`supported_plan_schema_versions` 必须包含 `2`。
- v3 请求（使用 `options.fiammetta_enable`）：`supported_plan_schema_versions` 必须包含 `3`。
- 旧 Worker 没有 `supported_plan_schema_versions` 时，只发送 v1 请求。

同一 Worker 只允许一个 in-flight 请求。请求超时后终止 Worker，当前请求失败，不自动重发。

## 2. 请求版本

普通排班继续用 v1：

```json
{
  "id": 1,
  "method": "plan.compute",
  "params": {
    "schema_version": 1,
    "layout": "完整 BaseBlueprint",
    "operbox": "完整 OperBox 数组",
    "labels": {
      "layout": "243",
      "operbox": "当前干员数据"
    },
    "options": {
      "rotation": "abc_12_6_6",
      "top": 20,
      "system_preferences": {},
      "maa_title": "243 排班"
    }
  }
}
```

`12/12/12` 必须用 v2：

```json
{
  "id": 2,
  "method": "plan.compute",
  "params": {
    "schema_version": 2,
    "layout": "完整 BaseBlueprint",
    "operbox": "完整 OperBox 数组",
    "labels": {
      "layout": "243",
      "operbox": "当前干员数据"
    },
    "options": {
      "rotation": "abc_12_12_12",
      "top": 20,
      "system_preferences": {},
      "maa_title": "243 · 12/12/12 排班"
    }
  }
}
```

需要显式关闭菲亚梅塔回岗时用 v3：

```json
{
  "id": 3,
  "method": "plan.compute",
  "params": {
    "schema_version": 3,
    "layout": "完整 BaseBlueprint",
    "operbox": "完整 OperBox 数组",
    "labels": {
      "layout": "243",
      "operbox": "当前干员数据"
    },
    "options": {
      "rotation": "abc_12_6_6",
      "top": 20,
      "system_preferences": {},
      "maa_title": "243 排班",
      "fiammetta_enable": false
    }
  }
}
```

注意：`fiammetta_enable` 默认 `true`，省略即保持回岗启用；设置为 `false` 且 `rotation` 为 `fiammetta_8_8_4_4` 时请求会失败（该 profile 本身就是菲亚事件班）。

注意：`layout` 和 `operbox` 是内联对象，不是文件路径。未知字段会被 schema 拒绝；真实布局必须包含完整房间，真实干员数据必须是完整数组。

当前支持的 `rotation` wire 值：

| wire 值 | 班次 | 周期 |
|---|---:|---:|
| `abc_12_6_6` | 12/6/6 | 24h |
| `abc_12_12_12` | 12/12/12 | 36h |
| `main_backup_12_12` | 12/12 | 24h |
| `fiammetta_8_8_4_4` | 8/8/4/4 | 24h |
| `abyssal_7_5_7_5` | 7/5/7/5 | 24h |

不支持自由时长数组、普通 `4`、五班及以上。

## 3. 读取响应

成功响应的核心形状：

```json
{
  "id": 2,
  "ok": true,
  "elapsed_ms": 1200,
  "solver": {
    "git_commit": "<commit or null>",
    "built_at": "<UTC timestamp or null>"
  },
  "result": {
    "schema_version": 2,
    "profile": {},
    "rotation": {
      "profile": "abc_12_12_12",
      "daily": {
        "trade": 5.128,
        "manufacture": 9.184,
        "power": 3.656
      },
      "shifts": []
    },
    "maa": {},
    "training_room": {
      "schema_version": 1,
      "shifts": [
        { "trainee": null, "trainer": null }
      ]
    },
    "training_advice": {
      "schema_version": 2,
      "context": {},
      "newbie_section_status": "shown",
      "incomplete_newbie": [],
      "combinations": [],
      "recommendations": []
    }
  }
}
```

前端应检查：

- `result.schema_version` 必须等于本次请求的 schema version。
- `profile.schema_version` 是画像结构版本，目前为 `4`，不要与请求版本混用。
- `rotation.profile` 必须等于请求的 `options.rotation`。
- `abc_12_12_12` 的 `rotation.shifts[].duration_hours` 应为 `[12, 12, 12]`。
- 三个班次的队伍关系是 `alpha+beta`、`beta+gamma`、`gamma+alpha`。
- `rotation.daily` 是周期归一化后的日均值；121212 按 36h 分母计算，不是把 36h 产出直接当成 24h 产出。
- `maa.plans[]` 可以直接用于现有排班展示和 MAA 下载。
- `training_advice` 是本次排班自动附带的练卡结果；字段、枚举和消费规则以 [FRONTEND_CLI.md](FRONTEND_CLI.md#45-training_advice排班附带的练卡建议) §4.5 为准。不要额外调用 legacy `advice --player`。
- `training_room` 是可选响应字段；若存在，`schema_version` 为 `1`，`shifts` 与 `rotation.shifts` 按位置对应。没有训练任务时 `trainee` 为 `null`，没有协助位时 `trainer` 为 `null`。字段缺失不视为错误，且不升级总体 `plan_schema_version: 3`。
- 每个 plan 的 `description` 会包含本班时长和下一次相对间隔。
- `Fiammetta.enable` 最多每个休息班一次；没有合法目标时为 `false`，不能强行补齐三次。
- `rotation.warnings` 必须展示给用户，不能静默丢弃。

失败响应：

```json
{
  "id": 2,
  "ok": false,
  "elapsed_ms": 80,
  "solver": {},
  "error": {
    "code": "PLAN_FAILED",
    "stage": "plan.compute",
    "message": "具体失败原因"
  }
}
```

## 4. 前端修改清单

1. `RotationProfile` 增加 `"abc_12_12_12"`。
2. 请求类型把 `schema_version: 1` 改为 `schema_version: 1 | 2 | 3`。
3. 根据 rotation 选择请求版本：只有 `abc_12_12_12` 发送 v2；只有需要 `fiammetta_enable` 时发送 v3；其余保持 v1。
4. capability 检查支持 `supported_plan_schema_versions`，不能把 ping 的兼容字段直接改成只接受 v2。
5. 响应校验允许 `result.schema_version` 为 1、2 或 3，但必须与请求版本相等。
6. 设置 UI 增加“ABC 三班 12/12/12”，说明“36h 周期、三班各 12h”；如需提供菲亚梅塔开关，发送 v3 并在 `options.fiammetta_enable` 中显式传 `false`。
7. 结果 UI 使用 `rotation.shifts[].duration_hours` 和 `maa.plans[].description`，不要根据 profile 名称硬编码时长。
8. 保存 solver 归因时使用本次 `plan.compute` 响应里的 `solver`，不要使用最近一次 ping 的构建信息。

当前前端对应代码位置：

- `src/types.ts`：请求类型和 `RotationProfile`
- `src/server/plan-protocol.ts`：ping 能力判断和响应版本校验
- `src/server/infra.ts`：`plan.compute` 请求组装
- `src/rotation-result.ts`：rotation 结果归一化
- `src/components/RotationSettings.tsx`：轮换设置 UI

```bash

  --maa-out /tmp/abc121212_maa.json \

```

实际结果应包含：

```text
ABC 三班 12/12/12
Shift 1 · 12h
Shift 2 · 12h
Shift 3 · 12h
```
