# 游戏机制知识库引用合同

> 文档角色：canonical
> 生命周期状态：current
> 领域键：docs.knowledge-bridge
> 当前真源：self
> 摘要：规定求解器文档如何引用外部游戏机制知识库，以及机制事实与本项目实现的边界

## 1. 唯一边界

本仓库记录求解器行为：输入如何映射、候选如何准入、状态如何传播、结果如何输出、哪些机制尚未支持。游戏规则、技能原文、组合知识和玩家策略不在这里复制。

游戏机制知识库是相邻仓库 [`arknights-base-vault`](https://github.com/lejciy/arknights-base-vault)：

```text
本地开发路径：/home/knightcode/Projects/arknights-base-vault
固定引用：977b6ab0cc0430053194f269d7b3ee0242e7be48
远程入口：https://github.com/lejciy/arknights-base-vault/tree/977b6ab0cc0430053194f269d7b3ee0242e7be48
```

本地路径用于快速阅读，远程固定 commit 用于复核和跨机器交接。不要只引用未固定的 `main`，也不要引用知识库的 `meta/mirror/ArknightsInfraCalc/` 旧求解器镜像来证明本项目当前行为。

知识库正文的 `status: draft` 表示存在未解决争议，不能写成已确认机制。发现机制缺口时记录 `knowledge-gap`，不要在 solver 文档里猜一个数值补齐。

## 3. Solver 文档的引用格式

描述一个机制接入时按下面顺序写：

```text
知识库事实：vault 文件#章节（固定 commit，status）
运行时映射：data/... → crates/...::symbol
求解器行为：候选/状态/输出由本仓库哪个 owner 负责
差异与缺口：unsupported | deferred | approximation | policy
验证：命令、输入 fixture 或最终状态检查
```

同一页不要重新抄整张技能数值表；需要数值时引用具体小节并说明本项目保存的单位、舍入或兼容转换。若代码故意采用产品 policy 而非游戏机制，写清 policy 名称，不把它伪装成机制结论。

## 4. 更新与升级

知识库固定 commit 变化时，只更新本文件和真正受影响的引用页，并检查每个引用的 `status`、路径和标题。求解器行为变化不反向修改知识库；应在本仓模块/调用链页更新代码锚点和差异说明。

建议检查命令：

```bash
git -C /home/knightcode/Projects/arknights-base-vault rev-parse HEAD
python3 scripts/codex/check_repository_facts.py
```

## 5. 不可混淆的四种内容

| 内容 | 真源 |
|---|---|
| 游戏规则和技能效果 | 知识库具体 canonical；草稿必须标注 |
| 求解器应该支持什么 | 本仓库 current canonical 与用户裁决 |
| 当前代码实际上怎么做 | 本仓库代码、help、模块页和调用链页 |
| 某次运行得到什么 | fixture、CLI 输出和 evidence；不升级为长期规则 |
