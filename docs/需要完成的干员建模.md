## 判断顺序

“未建模”必须拆成四类：缺 instance binding、缺 skill-table row、atom 已存在但 interpreter 未消费、机制需要 L2/L3 或 global/rotation 闭环。先用 `validate_operator_refs`、pool skip reason 和机制审计定位类别，再决定 owner；不要用 JSON 行数或旧推荐表推断完成度。

```text
registry row
  -> operator_instances facility/tier
  -> skill_table buff_id/atom
  -> domain interpreter or named L2/L3
  -> global/resolve/rotation consumer
  -> regression/invariant evidence
```

## 当前边界

贸易和制造是主求解域；控制中枢、发电、办公室、会客室有界求值；宿舍只对明确 `scope=Global` 的资源 producer 进入跨设施链。连续心情最优换班、活动室/训练室/加工站求解、未建模概率事件不因出现在 registry 就自动纳入。

`docs/INTERNAL/MECHANICS_REGISTRY_AUDIT.md` 是脚本生成的 triage，不是覆盖证明。其 `has_atoms`、`empty_atoms`、`not_found_by_name` 只用于找入口；每个候选需回到代码和知识库章节确认责任与公式。

## 新增/修正清单

- 添加或变更设施技能：先核对知识库版本和 `PromotionTier` 解锁，再改 instance/skill table。
- 同房效率：补对应 domain interpreter 与 breakdown；不要在 CLI 加特判。
- 跨房效果：声明 `scope=Global` 或 producer/inject contract，补 collector、resolve 和 consumer 链。
- 组合/特殊订单：使用 `trade_shortcuts.json`/segment registry，携带来源、精度和回归夹具。
- 交付前运行 refs audit、代表性 solve、最终 invariant gate，并更新本页缺口状态。
