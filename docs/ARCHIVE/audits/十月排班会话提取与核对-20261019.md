## 6. 自动轮换：主体已裁决，尚未成为产品入口

第 2 题原文 `msg_12974b3e6001jf9mjSjvG1WjyK` 明确区分“全部禁止”与“优先单站，必要时允许其他跨站组合”。用户后答“2禁用”，将早期“尽量、尽可能”收敛为禁止其他跨站协同，而非软优先。结合原题而非孤立选项，已决内容是：

- 每站一主一替，各站工作成员和主备之间互不重复；先保留主力，替补用剩余人，配不齐则显示缺员。
- 禁止其他跨站协同，只保留宿舍一挂件＋生产一受益者的 1+1、发电＋制造自动化；常驻宿舍挂件可供主备共用。
- 中枢先全局贸易/制造/人力光环，后心情减免，允许中枢内部组合；中枢主备也互斥。
- 各房收益按首人红脸与 36h 较早者评估；正常输出效率。
- 首版固定关闭菲亚，不安排普通宿舍、不模拟实际换班；网站和 CLI 都在范围内。

不能再把实际异步换班或宿舍永续模拟列为实现该建议模式的必要条件。当前[排班模式](../../排班模式.md)仍无自动轮换入口，定时 profile 闭集也没有它。独立输入/输出与验收仍要落地；具体 1+1 名单和现有挂件开关如何衔接，原问答没有完成对接裁决，但不等于上述主体方法未定，更不能借此重开八题。
