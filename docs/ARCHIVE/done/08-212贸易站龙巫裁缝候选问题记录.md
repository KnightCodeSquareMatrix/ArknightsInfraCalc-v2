## 1. 问题描述

08-212 的贸易站反馈显示，巫恋 + 龙舌兰可能与月见夜、夜刀等普通第三人组成，而没有优先使用裁缝 α。该组合的贸易效果低于巫恋 + 龙舌兰 + 裁缝 α。

本记录只保存调查结果，不授权修改候选策略、数据或求解器代码。

## 2. 用户裁决：龙巫组合专用候选顺序

巫恋会清空同房其他干员的效率，因此“巫恋 + 龙舌兰”是特殊组合，第三人不能按普通贸易候选的总效率自由竞争。

该组合的第三人只允许按以下顺序选择：

```text
裁缝 β >> 裁缝 α > 白板
```

含义：

- 有可用裁缝 β 时，只能选择裁缝 β；不得选择裁缝 α 或白板。
- 无可用裁缝 β、但有可用裁缝 α 时，只能选择裁缝 α；不得选择白板。
- 只有 β、α 均不可用时，才允许选择白板。
- 月见夜、夜刀等普通第三人不属于该组合的自动候选路径；其他路径全部排除。

这条裁决是本问题后续修复的 admission 规则，不是普通候选排序权重，也不是 L2 结算后的软偏好。

## 4. 已定位的责任路径

贸易余站由 `pick_trade_meta_then_plain` 按 `docus → closure → witch → fallback → ...` 尝试，完整龙巫路径在：

- [trade_fill.rs:635](../../../crates/infra-core/src/layout/assign/trade_fill.rs#L635)

`witch` role 要求同房包含巫恋和龙舌兰，并调用 `hit_filter=witch`。当前过滤器同时接受以下结果：

- `gsl_witch_long0_alpha`
- `gsl_witch_long0_blank`

责任代码：[role_pick.rs:234-256](../../../crates/infra-core/src/search/role_pick.rs#L234-L256)。

过滤后，贸易搜索会对所有命中按 `total_efficiency` 排序，不执行“存在裁缝 α 时先排除白板，只有无 α 时才启用白板”的分层 fallback：

- [trade.rs:337-373](../../../crates/infra-core/src/search/trade.rs#L337-L373)

因此，普通第三人可以作为 `gsl_witch_long0_blank` 进入自动 `witch` role，与裁缝 α 成为平级候选。这是目前已确认的策略责任点。
