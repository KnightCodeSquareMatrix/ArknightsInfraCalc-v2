# 办公室逐班择优修复

> 文档角色：archive
> 生命周期状态：completed
> 替代项：docs/排班/定时换班.md；docs/排班/SCHEDULE_ROTATION.md
> 历史原因：办公室已改为当班剩余池逐班效率/ETA 选择，旧 cohort 与跨班累计状态已删除
> 摘要：记录办公室逐班择优修复的裁决、实现边界与验收证据

## 1. 用户裁决

办公室与生产设施的切半、两队合成排班没有业务关系。办公室不因生产队伍、办公室 cohort、上一班
是否办公或下一班是否办公而预先决定成员。

效率优先于减少人员占用。每个新班次都重新选择办公室成员；如果上一班成员在当前班次仍是效率最高且
当前 ETA 足够，就可能自然复用，但复用不是目标，也不是约束。

## 2. 正确过程

```text
当前班生产与其他固定岗位落位
    -> 从当前班未占用干员中形成办公室候选
    -> 按办公室 registry 候选效率从高到低尝试
    -> 当前班 ETA 足够完成本班：选入办公室
    -> 当前班 ETA 不足：跳过，尝试下一名
    -> 候选耗尽：办公室留空并报告缺员
```

下一班重新执行同一过程。上一班的办公室成员、办公室使用时长和办公室队伍归属不进入下一班的普通
办公室择优条件。

## 3. 本次保留

- 办公室候选必须排除当前班已经被生产或其他固定岗位占用的干员。
- 候选按办公室 registry 的当前实现评分从高到低尝试；本轮不为每个候选重跑全局 resolve 或组合搜索。
- 候选只检查当前班的 ETA 是否覆盖当前班时长；不足时继续尝试下一候选。
- 真实的跨设施绑定仍由既有绑定规则负责；绑定成员不能被普通办公室补位逻辑拆开。
- 最终班次检查办公室与贸易、制造、发电岗位不得同班重叠。
- 候选不足时允许办公室缺员，并沿用既有 warning 语义。

## 4. 本次删除或不再消费

- 普通办公室成员进入生产 α/β/γ 队伍花名册。
- 普通办公室成员预先分配办公室 cohort。
- 为办公室成员提前占用生产候选的全局预留。
- 以往办公室使用记录驱动的“已使用优先”或“少换人”排序。
- S2/S3 固定同人、固定房间和合并 12h 办公室段。
- 跨班累计办公室工作时长、跨周期办公室连续段扫描和换人合理性证明。
- 由办公室候选反向改变生产、中枢或其他班次搜索空间的路径。
- 为办公室候选建立跨设施综合评分、全局回溯或未来班次预判。

## 5. 明确不改

- 生产设施切半、γ 替补生产和中枢轮休本身。
- Plan、required anchor、producer dependency 和真实 shift bind。
- 会客室独立候选与心情规则。
- 二班、菲亚梅塔和深海 profile 的既有 owner 语义。
- Mower 动态换班、全基建连续心情最优和自定义班次数组。

## 6. 验收义务

只做轻量运行验证，不运行大批量测试，也不新增复杂全周期断言：

1. 三班分别完成一次独立办公室选择；办公室结果可因当班生产占用而不同，不要求三班必须选不同姓名。
2. 每班办公室成员不与当班生产岗位重叠。
3. 心情足够的高效率候选应被选中；当前班 ETA 不足的候选应被跳过。
4. 至少构造几种高风险 operbox，覆盖生产占用、高效率候选跨班可用、异常心情候选和办公室候选不足。

验证只调用真实 `plan` 入口和轻量 Rust 最终状态检查；Python 或脚本只负责批量调用和分类结果，不重新
实现办公室语义。

增加例外条件维持旧模型。
