## 3. 单元 A：统一 ABC 中枢轮换可用闭包

### 3.1 唯一责任

建议新增内部模块 `schedule/control_rotation.rs`，由它拥有 `ControlRotationClosure`：合法候选来源、技能与 tags、固定队伍、已解析工作范围、每班 required 和候选组要求。名字是设计建议，尚非当前类型。

Plan 仍决定体系和硬关系，mood/ledger 仍结算机制。闭包只消费这些事实并生成当班选位输入；所有中枢提交均通过该 owner，不能重新从账号 roster 激活体系。

最小内部结构：

| 结构 | 必须表达的事实 |
|---|---|
| `ControlCandidateOrigin` | Plan 已解析角色、候选组成员、普通轮换补位、深海分支事实；不能仅记录姓名 |
| `ControlWorkScope` | 固定 cohort 的活跃班、既有 Plan 明确共享的工作范围、已解析分支工作范围 |
| `ResolvedControlRequirement` | 原 Plan/claim/slot 来源、候选组、最低人数、独立于最终选位的适用范围 |
| `ControlShiftAdmission` | 当班合法 entry、required、适用候选组、排除项与实际非中枢占用 |
| `ControlRotationAudit` | 班次生成前冻结的归属/来源/范围；由最终 gate 反查，不由最终成员反填 |

优先在报告中增加 `serde(skip)` 的内部审计证据，公开 CLI/Worker/MAA 字段保持现有契约。最终岗位事实仍唯一来自 `shifts[].assignment`，不另存一份可变的 selected 名单。

### 3.2 工作范围与候选组适用性

`ControlCandidateRequirement` 当前只有名单和人数。Plan 编译时补上内部来源关联：体系 ID 与该 Plan 内的 slot 身份；这是 Plan provenance，不是另造机制 ID。来源仅给轮换消费，不让轮换解释原始 `PickOne` / `OptionalFixed`。

在 peak 实际落位与 dependency/bind 解析完成后，生成以下非循环适用事实：

| 已解析事实 | 当班规则 | 禁止做法 |
|---|---|---|
| required 中枢角色属于实际 exact bind/cohort | 随固定队伍工作；工作班 required，休班不 pin | 把 required 一律改成全周期在岗 |
| Search slot 的实际选中成员属于已解析体系 cohort | 继承该 owner 的工作范围；每个适用班保留原 `min_count` | 用最终是否选了组员决定本班是否适用 |
| Plan 既有共享/RequiresPresence 已明确工作范围 | 消费其已解析范围并保护 required | 为保证轮休删除硬角色，或给予自动休班豁免 |
| 普通轮换 filler | 一个完整周期内队伍固定，只可在活跃队对应班候选 | 每班从全池重新捞人或临时改队 |
| 来源不全、同一 slot 多个范围冲突、无可解析 owner | 返回带来源的 `control_requirement_scope_unresolved` 等解析错误 | 静默略过组、默认全班或按当前结果猜 scope |

例如人间烟火 Search slot 要求重岳/令至少一人，而其实际体系上二休一。组要求在体系两个工作班生效，体系休班时不为满足该组强行恢复在岗；这是保留原工作范围，不是放松工作班的最低人数。

`min_count` 不等于固定选择某一人；但若 peak 实际成员另有 exact bind，该绑定仍独立生效，不能以换一个组员为由拆绑定。

shared 中枢硬角色必须在清空/重建中枢前提取为显式 required，之后与当班 cohort required 一起 materialize。合并后超容量、跨岗位重复或硬范围冲突均拒绝该状态，不删 shared 成员凑五人。其全周期连续在岗仍由单元 D 报诊断，没有第三种豁免。

### 3.3 候选生成、预留与分队

1. 候选来源是完整 runtime control pool 加已解析 Plan/分支角色；按 Plan 排除、自动准入排除和实际能力解析裁剪。未被 peak 选中不自动非法，但进入轮换时必须有明确普通补位来源，不能借全池重选未认领体系。
2. 已确定 production/shared/fixed/bound-office/rotating-meeting 岗位是预留事实。普通办公室与会客室尚未选中的名单不是占用，保持先中枢、后普通辅助岗位的既有时序。
3. hard bind/cohort 先固定归属；普通候选以现有稳定均衡作为首个分队尝试。同房协同偏好可调整尝试顺序，不新建彩六/异格/魔王硬绑定。
4. 对每个活跃两队组合，检查真实可用席位、required、适用 `min_count`、禁配和 ETA。名单人数够五只是必要预检，不能证明满编可行。
5. 具有派系、tag 或当前有效协同响应的无 buff 成员，不并入“全等普通 filler”。只有经上下文等价证明的无响应成员可做安全尾部缩减；否则保留恢复候选入口，并明示受限搜索结果。

普通办公室和会客室选位消费中枢已提交 assignment，并重新排除真实占用。最终检查所有实际房间的唯一占用；不以提前锁住所有辅助候选来避免冲突。

### 3.4 状态传播与写入收敛

```text
Plan + peak actual facts + resolved dependency/bind
  -> production halves / Gamma / shared / fixed reservation
  -> frozen candidate provenance + fixed team + work scope
  -> materialize shift admission from actual occupancy
  -> required placement -> control fill -> auxiliary selection
  -> resolve / contextual mood check -> final assignment gate
```

需要删除或改写的冲突路径：

- 删除每班把未归队 `control_fallback_entries` 追加到 `final_pool` 的路径。
- previous control 成员只能在当前 admission 中恢复；entry 复用真实 progress/buff/tags，不再合成空 tags 条目作为放行手段。
- `ensure_control_inject_coverage` 不再拥有独立的最终 `set_room`。过渡期可提出候选建议，但由统一 fill owner 再验证、提交；顺序选位成熟后移除这个补偿路径。
- extra pin 先解析进 branch admission；pin 函数不能额外扩大资格。
- `assign_control` 的满员快捷返回、普通 fill 和最后补满都使用同一 required/group validator；后置替换完成后仍做最终计数。

### 3.5 深海分支与重试事务

深海 S2 的有/无分支及生产收益比较沿用已有 policy。进入班次循环前冻结潜在 producer 的准入身份与唯一归属，身份冻结不表示预占岗位或强选分支；分支只 materialize 已准入者，不临时更换既有队伍。

若深海 producer 已归其他队、被实际岗位占用或不满足本班范围，该分支失败。需要改变归属时只能生成新的整周期尝试。S2 胜出后追加 Gamma 标签的路径改为提交该尝试原本就有的归属事实，不新增跨班 producer bind。

两种重试明确分开：

- 固定分队内换人：恢复本班 assignment/used、办公室/会客室落位和本班暂存状态；成功后才推进心情、会客累计工时和暖机状态。
- 改变分队：从班次循环入口重算三班，重新初始化 `rotation_mood`、`meeting_worked_hours`、warmup/sticky 状态和报告；不可保留旧 S1 再给 S2 换队。peak Plan、生产 split 和已解析硬关系只读复用。

重分队是具名搜索启发式，不证明全局最优。保留可恢复的候选目录；尝试次序稳定、分支失败不污染其他尝试。需要预算时统一登记预算及消耗，避免把分队预算与班内预算相乘成无界重试。

### 3.6 保证与失败结果

容量、唯一性、Plan required、适用 `min_count`、明确 bind、准入排除是 hard constraint。普通候选分队/协同集中是 heuristic；固定名单限制是 policy restriction；未证明等价的 tail/top-K/ETA 截断是 approximation。

本单元不新增无证明的固定前 N 名截取。当前 skillless tail、top-K 和 64 次 ETA 重试均纳入保证审查；源池完整不能代表最终搜索完整。策略未找到报告 `NO_CANDIDATE_UNDER_POLICY`，预算停止报告搜索未完成，只有完整证明才能报告 canonical `INFEASIBLE`。这些是 core 诊断分类，不要求本次新增公开状态枚举。

## 4. 单元 B：校正心情来源映射

独立写入 `data/mood_model.json` 与必要的 mood 数据读取逻辑：

- 彩六提供者保留四人，计数成员按固定知识库八人修正；医生等只增加人数，不伪造成技能提供者。
- 分开核对中枢全员回复资格、玛恩纳允许扩散的技能来源、宿舍回复和自身/条件回复。三角初华的宿舍效果不能因数值同为 0.05 被标成中枢全员笑脸。
- 异格成员和技能档位只在有明确来源时校正；记录已核对范围和未支持条件，不能从标签或名称补猜公式。

机制出处经[知识库引用合同](../../知识库引用.md)进入固定版本的 `docs/2-干员技能/技能-控制中枢.md`、`docs/2-干员技能/类别.md` 和 `docs/3-组合库/单站组合/彩虹小队.md`。本页只定义映射修复责任，数值和成员语义仍由原文裁决。

候选分类、统一心情效果与最终 gate 必须读取同一份来源映射；实际 ETA 继续由 mood owner 结算。修正后用固定真实组合隔离 provider/member、作用设施、技能档位和附带增耗的反例，不宣称未审计的心情机制全部正确。

## 5. 单元 C：心情补位选择

前序席位由 Plan 和既定效果区按顺序确定并锁定；心情只消费剩余容量。严格遵守“当前已选 + 当前候选”，不提前计算未来队友、不为激活前序条件额外找 witness，不回溯替换前序已选成员。

类别顺序消费已有政策：已有维什戴尔优先魔王、已有玛恩纳优先合法扩散提供者、无全局 owner 时比较派系/人数或笑脸来源；其他合法来源与普通补位按已声明层级处理。无 buff 成员若对当前已选组合有有效贡献，也可成为心情候选。

**用户已裁决：心情减免按统一效果结算，不按候选的个人耗损比较。** “统一”表示同一效果按固定作用范围对符合条件的工作状态统一减免，不存在“优先照顾当前最累干员”的排序目标。不同来源如果确实提供不同的统一效果，仍按既有中枢顺序和 `ControlEffectLedger` 的结构化 `EffectKey`/aggregation 处理；本方案不新增总净消耗、边际节省或最短可工作时长目标。

心情阶段只做三件事：

1. 前序席位锁定后，按单元 A 已解析的准入、required、候选组和容量规则生成剩余合法候选。
2. 当前已选成员加当前候选只用于判断该候选的 canonical 效果是否激活，以及它的目标范围、计数和聚合方式；不构造每个干员的耗损比较分数。
3. 对最终实际 assignment 调用既有 mood owner，按统一规则结算适用的心情减免；效果只能按其 canonical 作用范围应用一次。候选影响资格、计数或作用范围时，使用 B 单元核对后的来源事实处理。

统一减免不删除干员自身或同房的真实增耗。完整中枢与辅助岗位落位后，仍由既有 mood/ETA owner 检查本班和相邻班可工作时长；这些是排班可行性检查，不是个人耗损排序。中枢尚未补齐时不把部分状态的 ETA 当成最终无解证明；失败继续由单元 A 的有界尝试处理，不替换前序已锁定成员。

删除心情固定 50/10/5 奖励和 `mood * 0.01` 混分；候选成员准入与派系分类通过单元 A/B 的事实进入。完整普通区顺序迁移仍按已有中枢计划执行，本单元只接入结构化的统一心情效果，不能用跨域分数替代“前序成员已锁定”。

## 6. 单元 D：全 profile 实际休班诊断

在全部动作、岗位和宿舍最终化后，按最终 assignment 的真实工作岗位统计完整周期。至少覆盖中枢、贸易、制造、发电、办公室、会客室；其他已表示为工作状态的位置按真实语义进入，不使用当前缺少会客室的局部工时 helper 作为完整证明。

仅采用 canonical 的两项豁免：实际选入自动化的 Lancet-2、最终班次确有菲亚交换动作的 target。required/shared/pinned、支持位、派系成员均不自动豁免；离岗不等于获得宿舍恢复。

输出具名 `cycle_work_without_rest` 质量诊断，含干员、各班房间与豁免判定，追加到报告现有 warnings。重复 finalize/断言不得重复累计；`--assert-invariants` 可检查诊断是否与最终事实一致，但休班违反本身不返回错误。原容量/绑定/ETA/恢复错误继续按自身规则阻断。

同时改写 warning 一致性检查：当前 gate 把完整 warnings 与普通缺员列表作全等比较；新增诊断后必须核对完整的已支持 warning 来源，而非继续要求“只能有缺员 warning”。finalizer 与 gate 共用具名诊断收集/渲染 owner，按最终事实重建和稳定去重，不能靠忽略整份 warnings 校验保留输出。

训练协助位当前与 rooms 的唯一占用尚未统一；实施诊断时必须记录覆盖边界，不能据本方案顺带重建全部岗位模型。

## 7. 修改边界与实施顺序

| 单元 | 主要修改落点 | 完成条件 |
|---|---|---|
| A：中枢轮换闭包 | `schedule/control_rotation.rs`（新增）、`schedule/mod.rs`、`team_rotation.rs`、`layout/orchestrate/{plan,select}.rs`、`layout/assign/control_fill.rs`、必要的 `search/control.rs` 消费入口 | 三条写入路径归一、范围显式、组约束终验、归属跨班固定 |
| B：心情映射 | `data/mood_model.json`、`mood/{mod,drain,eta}.rs` 的必要读取点 | provider/member/scope 一致，合法与非法组合可区分 |
| C：心情选择 | `search/control.rs` 的心情阶段、统一 mood 结算及 admission 消费点 | 不做候选个人耗损排序，按既有效果顺序结算，固定奖励删除 |
| D：质量诊断 | `team_rotation.rs` finalizer/gate 与最小内部诊断模块 | 所有 profile 实际出勤核对，两个豁免正确，输出不被阻断 |

路径是预计允许范围，不授权覆盖现有用户改动。每波实施前冻结基线和实际 diff，保持一个 writer；共享脏工作树不能以清理、回滚或混入提交获得“干净”。公开接口字段变化需新增授权，不纳入本设计。

顺序建议 A -> B -> C；D 可在 A 后独立实施。A 不依赖“所有心情数据已经正确”的前提，B 不依靠排序补偿，C 必须消费核对后的数据与已锁定前序事实。

## 8. 验收与证据

每个已确认问题必须有对应 Rust 最终状态检查或可复核的结算 witness，不能只看 top hit 改了。

| 问题/边界 | 具名检查建议与证明 |
|---|---|
| 未归队补位/跨班改队 | `control_rotation_membership`：反查预冻结来源与报告 teams；普通成员只在其活跃班出勤，三班实际中枢交集无普通 fallback |
| required/组最低人数丢失 | `control_plan_requirement`：从原 Plan source/bind 复核适用范围并从最终 assignment 计数；覆盖满五快捷路径、后置替换、体系工作班与休班 |
| 容量/跨岗重复/技能事实 | 保留容量和唯一性 gate，重算真实 progress/buff/tags；候选数够但被占用的反例必须拒绝 |
| coverage/deep sea 绕过 | `control_admission_source`：所有分支提交来自冻结资格；合法深海与冲突分支都有 witness，不能事后补归属 |
| 彩六/笑脸映射 | `control_mood_projection`：固定组合隔离提供者与成员数量、扩散资格及增耗，actual ETA 与数据来源一致 |
| 心情结算 | 固定组合隔离提供者与成员数量、统一减免作用范围及增耗；最终 gate 校验来源/机制事实和只结算一次，不能用候选个人耗损分数证明正确 |
| 全周期休班 | `cycle_work_without_rest`：逐班房间向量、仅两项豁免、警告不影响退出码/MAA；检查 warning 与最终实际出勤一致 |

验证类别：

1. Rust 修改后执行 `cargo fmt --all`、build；不新增、修改或运行源代码内测试。
2. 新鲜运行用户真实 `plan` 或 `layout team-rotation`，带 `--assert-invariants`；c-598/c-267 复现输入先固化进持久验收包，不用旧 binary 或旧结果充当当前通过证据。
3. Python 驱动持久 representative/high-owned box 与 layout/profile 覆盖矩阵，统一调用 Rust gate。Python 只分析输入布局覆盖、命令及 gate 结果，不解析人类文本/MAA 或重写机制。
4. 分别统计 invariant failure、solver/policy failure、输入错误和超时；运行完成的 gate 通过不能掩盖未完成 boxes，预算耗尽不能归类为已证明无解。
5. 通过 `scripts/codex/run_evidence.sh` 留存新鲜 diff、输入、命令、日志与结果。实现后再做实际 assertion diff 的 Sol 复审至 `PASS`；设计批准不是实现验收。

实施同时复核中枢/排班模块、定时轮换调用链及影响到的接口/route。文档门禁为 `generate_agent_index.py --check`、`docs_inventory.py --check`、`check_repository_facts.py`；未改变契约的页面记录“已复核，无需正文修改”。
