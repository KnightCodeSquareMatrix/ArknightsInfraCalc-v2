## 1. 压缩、交接或新会话后的第一步

处理本任务时，**先完整读本计划，再开始工具操作和继续实施**。根 AGENTS 的入口指向本页；计划完成归档后入口指向知识库使用页及归档计划。

1. 读本页的进度、当前动作、未决项和保护清单，不把旧摘要或 TODO 当当前任务。
2. 在固定 v2 目录查看 `git status --short` 和 `git rev-parse HEAD`，确认当前 main、其他 writer 的变动及本任务已提交内容。不得创建或切换分支/worktree。
3. 只读当前阶段的 owner、脚本和证据。调查阶段已完成，不重新派全仓调查；仅复核会改变结论的变化。
4. 核对已完成验收和覆盖范围；从下一动作继续。若状态变化，先更新本页再实施。
5. 阶段完成、重要发现/用户裁决、交接或压缩前，及时更新进度、验证和下一动作。已完成不能只留在聊天或 target 中。

## 2. 目标、原因和授权

用户要求调查本项目及刻意去掉的多余检查，联网搜索范式，建设 Agent 友好的 RAG；并要求：“把计划完整的写下来，包括目标、原因分段计划，并且及时更新完成进度。每次压缩之后优先回看。”

可观察目标：Agent 可以用真实中文问题，定位当前 owner、实际代码、检查删除依据、相邻保留条件和扩展后的失效前提；结果保留来源、生命周期、版本、dirty 身份及完整回取方式。历史方案不能被当作当前执行要求，检索排名不能裁决语义冲突。

原因：现有文档已有良好路由，但当前页混入旧心情预算、重试、缓存和 WIP；只加向量召回会扩大旧规则误用。优先整理内容身份和撤销关系，然后用本地检索验证是否足够，避免先造大框架。

自动化范围：本地计划、文档同步、检查删减导航、可再生成的检索索引、只读 CLI、真实问题验收、独立复核和中文提交。暂不需要用户准备环境或额外安排。只有新机制/产品裁决、无法按已有裁决解开的 canonical 冲突、外部服务费用或发布动作才需要用户决定；其余部分继续。
