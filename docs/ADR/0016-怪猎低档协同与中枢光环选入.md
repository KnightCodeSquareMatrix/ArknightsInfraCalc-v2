# ADR 0016：怪猎低档协同与中枢光环选入

> 文档角色：decision
> 生命周期状态：accepted
> 当前真源：docs/机制/CONTROL_CENTER_ASSIGNMENT.md；docs/机制/知识库引用.md
> 摘要：怪猎沿既有优先级串行选入，二人纯光环路径降至感知与龙门之后，不新增候选竞争或整体收益比较
> 代码范围：data/base_systems.json；scripts/build_base_systems_from_gongsun_xlsx.py；crates/infra-core/src/layout/system.rs；crates/infra-core/src/layout/orchestrate/
> 核验基线：96f4b0e 当前工作树（2026-11-05）；保留已有未提交改动

日期：2026-11-05。决策状态：串行优先级方向已由用户明确裁决；用户进一步指定在贸易站搜索结束后直接读实际分配，区分二人／三人。实现状态：已修改Plan与填房串行路径，release构建和终态批量验收通过；运行时数据与生成脚本未修改，独立实施复审已收口。

## 1. 用户裁决与范围

用户要求分辨夜刀、黑角、调查团的练度与二人／三人区别，调查修改方法并写ADR；随后明确问题：

> “现在的问题是，他们二人在没有启用调查团的时候，是明显不如龙门组二人的。现在他的优先级似乎有点太高，甚至会挤掉感知组的成员”

最终纠正：

> “不需要竞争，这是有优先级的串行路径。他的顺序就要放到那里”

本次修改目标是调整夜刀＋黑角的串行选入位置，尤其不能让无调查团的二人纯光环形态继承三人资源体系的高优先级。保留既有前序体系及取向的责任，不重新设计全基建排名。用户尚未要求开始代码写入。

此前Agent提出的消费者胜出／落选提交回退、迁移统一挂件执行者、完整收益比较，均不是本任务方案，已从ADR实施路线删除。

## 2. 机制与当前实现证据

技能来源为[知识库引用](../机制/知识库引用.md)规定的固定commit `977b6ab0cc0430053194f269d7b3ee0242e7be48`：`docs/2-干员技能/技能-控制中枢.md`、`技能-贸易站.md`、`技能-制造站.md`。

- 夜刀、黑角木天蓼初始解锁，两人同驻中枢有12点。调查团贸易技能初始解锁，制造技能30级解锁。两人的精二光环分别为全制造2%和全贸易7%，精一与精零在这些效果上相同。
- 无调查团消费时，双精二怪猎只剩2%／7%；有效龙门二人是3%／7%，同占两个中枢位时龙门更强。普通无条件2%／7%同效且无需怪猎伙伴条件或夜刀额外耗心情。
- 调查团是否消费资源与二人光环是否生效是不同事实，不能把账号持有调查团当成实际三人在岗。

| 代码／数据位置 | 当前实现事实 |
|---|---|
| `data/base_systems.json` | 两条怪猎变体priority15，龙门priority14，共用互斥组；贸易调查团Search槽，制造调查团固定槽 |
| `system.rs::select_tier`、`systems_by_tier_and_priority` | 按priority降序串行认领首个可行体系，成功占组 |
| `system.rs::apply_registry_claim_to_assignment` | 跳过贸易Search槽，但立即提交夜刀、黑角固定中枢槽 |
| `assign.rs::inject_search_anchor_pool_entries` | 将调查团加入候选池，未承诺其最终上岗 |
| `control_fill.rs::assign_control_inner` | 已在中枢成员成为pin，普通补位保留 |
| `plan.rs::derive_registry_binds_from_actual_assignment` | 按实际在岗者派生绑定，可能只绑定夜刀、黑角；不会据此重排体系顺序 |
| `select.rs::compile_plan_once` | 主要规则（priority≥19）先于registry，软规则后于registry |

上述事实证明当前二人形态可能保留了三人体系的高优先级。普通Plan先提交感知21，再读其scratch执行registry，所以尚不能由这些源码单独证明怪猎替换了已提交感知成员；实际轮换中的具体挤占仍待Box证据。

## 3. 串行修改方法

责任仍在Plan／registry选型，保留既有逐项准入和首次可行提交：

1. 感知及已确认前序取向先按原路径选入，怪猎不借二人光环身份提前认领其席位。
2. 有效龙门二人先于无调查团的怪猎二人纯光环路径。二人路径消费前序串行完成后的剩余容量，不抢前序成员。
3. 对普通无条件2%／7%与怪猎同效光环保留既有光环去重与顺序规则；不新增伙伴枚举或全基建比较。
4. 三人木天蓼形态保留独立的已有准入、练度与同班语义。不得把三人形态整体禁掉，也不得把“二人降序”写成未裁决的三人总排序。

当前不能采用“直接把现有15降到14以下”的差分。现有数据没有独立的二人纯光环条目，两条怪猎登记项均描述调查团消费形态；它们与龙门共用互斥组。直接降序会让可行三人也整体让位于龙门，超出用户已裁决的二人修复范围。

实施责任仍限于既有Plan选型owner，但实施前必须明确以下边界：

| 边界 | 必须满足的行为与当前缺口 |
|---|---|
| 调查团未持有、不可用或缺少适配生产设施 | 不成立三人消费形态；不得仅以中枢二人可用提前认领三人优先级 |
| 调查团可用、进入贸易候选但最终落选 | 当前选型只知道候选可用，尚不知道最终消费；不得把此状态认定为三人已启用。必须先明确串行提交时依据什么承诺消费、何时确认，不能在fill或终检事后重排中枢 |
| 实际三人在岗 | 按消费设施、调查团等级和三人同班分类；二人的降序不得改变该形态原有顺序。贸易Search与制造固定槽不能用同一个“持有”判断代替 |
| 感知启用及显式办公室取向 | 保留对应Plan前序成员；感知关闭不等于显式办公室取向失效。尚未确定二人路径在registry与后序软Rule之间的具体位置 |
| 梓兰只作为普通空位候选 | 按普通效果区的原顺序处理，不能把感知路径中的梓兰排名直接搬到普通光环之前 |
| 普通光环已满足 | 分别核对制造、贸易的实际增量；不能因为名义上有2%／7%就提前占两个位置。另一域未满足时仍按原顺序处理，不扩大成组合收益竞争 |
| pin、互斥及轮换bind | 正确分类必须先于承诺中枢位和互斥组；pin只保护已提交成员，bind只约束实际成员，二者都不负责纠正选型顺序 |

降低registry内部priority不会越过“主要Rule→registry→软Rule”的阶段边界，因此不能只用一个数字表示上述顺序。需要在实施方案中写出二人尝试的具体阶段、该阶段可用的分类事实，以及三人原路径不受影响的证据；本文尚未给出这一闭环。

生成模板还存在已核实的漂移：`build_base_systems_from_gongsun_xlsx.py`只有一条怪猎模板，priority10、互斥组`meta_chain`、双精二，无调查团槽及`bind_all`，并非当前JSON的两条priority15。后续若同步该生成入口，必须保留当前低档准入、30级制造消费与三人绑定，不能仅改数字后重新生成覆盖数据。本轮不运行生成器、不修其他模板。

不引入临时支持环境、不迁移到挂件开关、不新增消费者比较器或有／无怪猎重算；生产设施原搜索照常执行，不承担重选中枢的责任。具体调查团生产位行为、制造变体删除、影子候选、怪猎与龙门共存以及低档主动降级不在本次排序修复中追加。

## 4. 完成条件与验证

可观察完成条件：无调查团的夜刀＋黑角不先于有效龙门二人，不挤占已确认的前序感知成员；前序方案不可行或无容量时，按原串行规则继续。双低档、单精二、双精二的技能仍按原数据结算，排序不能伪造光环。

实施验收覆盖：龙门有效／缺成员／练度不足；调查团持有但未上岗／实际三人在岗；贸易初始档／制造未满30级与已满30级；感知前序启用／未启用及独立办公室取向；中枢余位不足两人／足够；普通光环两个域分别已满足／未满足；真实轮换各班成员与依赖。若具体感知挤占尚不能复现，如实报告覆盖限制。

顺序验收必须保留同输入的前序准入证据和最终岗位，不能只检查priority或结构合法性：当有效龙门或已确认前序可行、原有容量足够时，无调查团消费的怪猎二人不得先占其位置；当实际三人形态可行时，二人修复不得将其整体降序。逐班核对消费设施、技能档位与实际绑定，不能以peak有三人推定每班都有三人。这些是待执行的验收判据，当前没有终态产物证明。

源码改动后跑格式、release构建、Rust最终assignment的`--assert-invariants`与代表性、high-owned Box批量，并按选人改动做独立意图复审。不新增源码测试。此修改属于policy顺序修复，终态gate证明合法性与绑定，不证明全局最优。

## 7. 用户补充裁决：贸易搜索结束后直接读取

> “二人三人直接读啊。具体阶段就放在贸易站搜索结束，很自然的做法”

本节更新并取代第3节与第6节中“分类时点、执行阶段尚未确定”的判断：贸易站搜索结束后直接读取当前实际assignment，调查团实际在消费岗位则按三人形态处理，否则按二人路径处理。候选池、账号持有和Search槽不代替实际岗位。不新增消费者竞争、组合收益比较或有／无怪猎重算。

该节点负责沿已裁决顺序处理怪猎选入，保留前序感知／显式取向，有效龙门先于无调查团二人。旧registry不得在贸易搜索前替无消费二人提前锁定高优先级中枢位及互斥组，否则后置读取仍无法落实顺序；修复最早提前认领的owner，不在终检补偿或重排已完成中枢。

制造消费应读取同一节点已落位的固定制造槽，并核对调查团30级技能，不因调查团未在贸易站就误判为二人。当前制造变体是Plan固定槽，可在贸易搜索结束时读取；普通制造余位搜索后于贸易搜索（`assign/pipeline.rs`），其未来候选不能当成此时实际消费。保留固定制造三人原有语义，不额外扩展制造重搜。

轮换仍按各班实际岗位与绑定核对，不以peak三人推定每班三人。剩余是源码实现与验证，不再把分类时点和执行阶段列为需要用户裁决的未知项。未改源码、未跑Box，本ADR不表示实现已验收。

## 8. 用户补充裁决：两席余位延迟绑定

> “如果那个时候中枢有2人的位置空缺可以延迟绑定呀”

前序成员先行，双人路径以中枢剩余至少两席为条件，保留该空位用于贸易搜索结束后的串行选入与绑定。贸易搜索所需的真实木天蓼来源上下文与最终claim、互斥和同班绑定分开处理，不把暂时资源上下文等同于最终高优先级锁位。实际消费岗位确定后，三人形态保留原路径；无消费二人位于有效龙门之后。最终来源和绑定必须与实际名单一致。

不足两席时不挤掉前序成员；不靠后置替换满员中枢补偿。保留两个席位不意味着伪造木天蓼或按候选推定调查团上岗，不增加贸易重搜。此裁决取代Agent此前将“暂放资源来源”与“最终绑定”捆绑后提出的额外审批。源码实施进行中，未验收。
