# ADR 0015：挂件统一选入与开关边界

> 文档角色：decision
> 生命周期状态：proposed
> 当前真源：docs/自动轮换.md；docs/公孙长乐的体系分析文档/ROSEMARY_PERCEPTION_CHAIN.md；docs/公孙长乐的体系分析文档/RHINE_LAB_CHAIN.md；docs/接口/输入输出与兼容.md
> 摘要：普通挂件复用既有设施搜索决定受益者入选，由统一执行者提交或回退，不新增全域收益比较

## 1. 用户要求与完成边界

本轮用户原话：

- “挂件比较应该有一个整体的控制入选的执行者，不能各自实现一个逻辑。”
- “这里也不需要太多比较，之前结算过多严重拖累性能。现在我们的设计，能选上就代表效率最高。调查一下。”
- “按照我们现在的规则迷迭香在挂件开关关闭的时候应该启用吗？”
- “开始写入adr、astra复审。”

本次授权交付 ADR 与独立复审，不实施 solver。前两条确定统一选入责任与性能边界；迷迭香问题的回答依据既有 canonical，不把提问本身当成新的游戏或产品裁决。

## 2. 问题与已验证证据

关闭开关时，select.rs 在编译 Plan 前删除 proactive_support 角色及条件包中的同类角色，却保留主角色的固定选入、优先级及剩余规则。依赖编译在 required 为空时不生成支持依赖。结城理的 sees_receivers 角色未声明 competitive，制造搜索强制包含结城理，不与普通组合同场择优。

211 Quality Check 的 c-110-369、243、ABC 12/6/6、supportCombinationsEnabled=false 已复现：第 1、3 班断罪者＋槐琥＋结城理在经验站，实际 S.E.E.S. 成员只有结城理，贡献 25%。同一远端二进制和原始输入的本地重放与线上实际 assignment、房间效率及 daily 一致。

仅在复制的 embedded 数据中删除 sees_receivers 后，结城理保留普通候选资格但未被选中，制造加权效率 8.767 → 8.810，贸易与发电不变。补 competitive 的诊断对照得到相同成员及 daily，但本 ADR 不采用该修复：它仍由各角色选择是否二次比较，违背统一责任与避免重复结算的方向。

证据：target/codex-runs/makoto-disabled-investigation/summary.json、baseline-rotation.json、remote-rotation.json、ordinary-rotation.json、competitive-rotation.json。远端 job 为 759d92c1-fa7a-4d1b-a3ad-0d449b3f1faf，二进制 SHA-256 为 da6f332cbcc27b23651233d6b46694a5008dc2fd55ec511bdf0425da4ec519e2。

未插入候选评分日志，不能声称已实测“参选按 40%、最终按 25%”；源码人数按实际 assignment 与当前房间成员去重，已证实的缺口是固定选入。只验证上述 Box，不泛化全部 Box。

## 3. 统一选入责任

复用自动宿舍挂件已有路径：先建立临时实际支持环境，解除受益者的临时预占及必选过滤，让原设施搜索在合法候选池内选完整组合；搜索赢家包含对应受益者才提交支持角色、工作名单、锚点和依赖，落选则整体回退。设施 owner 保留技能、目标、排序及候选合法性责任；挂件执行者只准备环境、消费赢家、提交或回退，不另写效率公式或第二套排名。

既有接入点是 layout/orchestrate/rules.rs 的 complete_domain_roles 与角色递归回退。制造、贸易、发电保留各自原设施搜索适配；统一执行者决定哪些角色是可选受益者，不能让各角色通过 competitive 决定是否遵守挂件选入规则。

受控挂件路径不再为入选补排无挂件基线或全制造／全发电重算。当前候选搜索必需的真实环境 resolve 与设施结算保留，不以“减少比较”为由删掉技能状态刷新。

“选上就代表效率最高”指原设施搜索在当前合法候选池、临时实际环境及既有目标下的赢家；不意味着跨 alternative、跨房间或全基建全局最优。有序 rule/role、空位选择与已有候选裁剪继续属于 policy/heuristic，不宣称 safe reduction 或候选完备性不变。

## 4. 开关与角色边界

关闭开关只禁止主动支持落位，不禁止干员自然进驻，也不更改技能公式。必须在删除支持角色之前保留“哪些生产角色属于可选挂件受益者”的关联；这是编译期选入依据，不代表本次已承诺支持，不能伪造 active_dependencies。

关闭时在没有主动支持的真实环境中让受益者参加原设施搜索；不得退回必选过滤。开启时在可兑现的实际支持环境中参加同一搜索。两种状态均由统一执行者消费赢家，未选支持者不生成 anchor、占用、依赖或绑定。落选试案释放试案新增成员，保留原先已有成员和其他体系的占用。

可选受益者与主链硬核心必须显式区分，不能把所有含 proactive_support 的 alternative 一概删除，也不能把整条规则的所有角色一概解除必选。当前角色关系中哪些可直接复用、哪些需要补充声明，留待实现前逐项核对；不得按干员姓名或规则 ID 写补偿分支。

| 范围 | 本 ADR 的边界 |
|---|---|
| 结城理及莱茵可选受益者 | 挂件带来的预选承诺由统一执行者撤销，原设施搜索选赢家；实际人数继续真实结算 |
| 迷迭香感知主链 | 保留迷迭香 E2、黑键 E2及实际感知至少 60 的既有硬准入；关闭主动宿舍挂件后仍达标可启用，不足则不可启用 |
| 爱丽丝、车尔尼、塑心 | 开关关闭时不主动补入；自然进驻的实际效果仍由原结算消费；不把塑心当作满足 60 感知门槛的来源 |
| 自动轮换 | 宿舍 1＋1 不受总开关控制，沿用已定单受益者、显式归属及主备共享口径；本 ADR 不改变允许体系范围 |
| 深巡、鸿雪、思衡托及普通同房组合 | 保留既有豁免或独立规则，不借统一挂件选入改变其机制与准入 |

迷迭香边界来自 ROSEMARY_PERCEPTION_CHAIN.md 的启动条件与跨体系挂件资源与轮换裁决设计.md 的开关登记。主链合法时允许启用不等于取消其独立选型；感知链未启用也不禁止迷迭香以普通制造候选上岗。

## 5. 实施约束与验收

首次修复位置是 Plan 编译期可选受益者的选入 owner，不能在排班收尾按姓名移走结城理或靠警告回填。复用同一提交／回退路径，迁移后删除受控挂件的旧强制选入和整域二次比较分支；非挂件主链的既有比较不在本次删除范围。

实施验收须覆盖：开关开／关、受益者真实胜出／落选、支持容量不足、自然在场支持、试案回退无新增占用和绑定残留；迷迭香关闭挂件后实际感知达标／不足两侧；自动 1＋1 的开关豁免与原归属。使用真实 release CLI、Rust 最终 assignment 断言、代表性及 high-owned Box，并完成选人改动独立意图复审，不新增源码测试。

性能使用相同二进制构建方式、输入、参数与重复次数对照；记录原设施搜索调用数、整域 score_completed 调用数和总耗时。验收应证明迁移后的挂件路径不增加二次整域评分，不承诺未经实测的加速比例，也不把一次运行的时间变化归因为代码收益。

本 ADR 阶段只跑文档检查，不跑整体 Box gate；上述已完成单 Box 诊断不能代替未来实现验收。当前普通终态部分违规只警告并输出的另一缺口不在本次实施范围，本 ADR 不宣称已解决。
