# ADR 0009: 无人机效率转化与产出核算

> 文档角色：decision
> 生命周期状态：accepted
> 当前真源：docs/DRONES.md；docs/EFFICIENCY_MODEL.md
> 摘要：记录发电效率、无人机库存、目标分配与制造贸易额外产出的统一裁决

> 日期：2026-08-26
> 决策状态：accepted
> 实现状态：未实现，供后续 agent 按 canonical 实施
> 当前规则：[无人机生成、分配与产出结算](../DRONES.md)

## 背景

当前模型混淆了三件不同的事实：

1. `drone_cap` 驱动承曦格雷伊技能的无人机数量选择器；
2. 发电效率生成和积累无人机；
3. 使用无人机向制造或贸易目标转化额外效率。

贸易代码中的 `DRONE_TRADE_FACTOR = 0.685` 只提供固定旁路字段，不能表达无人机库存、实际消耗、目标分配或特殊组合产出。轮换 `daily.production` 也只汇总实体产线产出，无法区分无人机额外收益。

## 决策

### D1. 发电基础只计算一次

发电效率的 `1.000` 是全基建共享基础，不按物理发电站数量复制。有效发电干员的技能效率和非零心情进驻 `0.050` 才按发电站岗位累加；零心情干员两者均为零，但可以继续占位并满足显式联动。

### D2. 发电效率先转化为无人机时间资源

每架无人机基准生成时间为 `6` 分钟。有效发电效率为 `E` 时：

```text
generation_time = 6 / E minutes
generation_rate = E / 6 drones per minute
```

库存由离散时间推进，受 `drone_cap` 上限约束；消耗不得超过当前库存，消耗后才释放库存空间。

### D3. 无人机目标效率固定按二分之一转化

分配给目标的发电效率为 `A` 时，目标获得：

```text
drone_target_efficiency = A / 2
```

额外产出为目标单位日产出乘以该效率。目标单位日产出必须来自目标房间的实际配方或特殊贸易组合，特殊贸易的贸易和赤金单位产出同时适用。

### D4. 分配守恒

同一时间窗口内，所有制造和贸易目标的无人机分配总额不得超过可用无人机资源。单一无人机资源只能被消费一次；目标变化必须形成可追溯的时间片或分配记录。

### D5. 实体产出与无人机产出分层后合计

结算必须保留：

```text
physical_output
drone_extra_output
total_output = physical_output + drone_extra_output
```

`daily.production` 在明确 schema 后可以提供合计值，但必须同时保留无人机分项和库存账本，防止前端或审阅者把不含无人机的实体产出当作最终产出。

### D6. schedule 选择目标，export 只序列化

schedule/Plan 负责目标、分配效率和执行顺序；MAA export 只转换已解析的 `room_id`、`index`、`order` 和 `enable`。export 不得临时选择目标或补算产出。

### D7. 固定 `0.685` 不再是无人机领域公式

现有 `DRONE_TRADE_FACTOR = 0.685` 可暂时保留为兼容实现中的待清理路径，但不得继续作为 canonical 公式、最终产出字段或目标比较依据。实现迁移后应删除或明确隔离该路径，并用本 ADR 的库存与效率分配账本替代。

## 实施边界

后续实现按以下责任单元拆分：

1. 发电结算：统一共享基础、有效进驻 `0.050` 和技能/联动分量。
2. 无人机账本：按时间推进库存、生成、消耗、上限和首日空仓状态。
3. 目标分配：将无人机资源分配到制造/贸易，并保持总额守恒。
4. 产出汇总：计算实体产出、无人机额外产出和合计，并支持特殊贸易单位产出。
5. export：消费已解析动作，不重选目标、不重新计算。

不得使用单个布局、房间编号、当前 top hit 或固定干员名单作为补偿特判。

## 验收要求

至少覆盖以下案例：

- `E = 1.2` 时每架 `5` 分钟，空仓到 `235` 架为 `1175` 分钟；
- 无人机只分配赤金制造：`0.6 × 10000 = 6000`；
- 无人机分配可露希尔：`0.6 × 12000` 贸易和 `0.6 × 2000` 赤金同时产生；
- 同一份分配效率拆给制造和贸易时，总额不重复；
- 库存不足、满仓、消耗后释放空间和首日空仓边界；
- 252/342 的 Lancet-2 `0` 心情占位不贡献发电效率，但保留森蚺联动；
- 243 `12/6/6` 按时间片推进，不把日均稳态直接套到首日；
- MAA 目标与 schedule/Plan 一致，export 不自行改选。

## 后果

该决策会扩大 `DailyProduction` 与 rotation report 的数据契约：调用方需要区分实体产出、无人机额外产出、合计产出和库存状态。实现完成前，旧 `daily.production` 只能作为不含无人机的实体产出观察值，不能宣称为最终账号总产出。
