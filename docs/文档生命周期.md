# 文档生命周期与 Agent 维护规则

> 文档角色：canonical
> 生命周期状态：current
> 领域键：docs.lifecycle
> 当前真源：self
> 摘要：定义当前事实、调用链、接口、外部机制引用和历史材料的单一 owner，以及代码变更的文档更新责任

## 1. 目标和边界

文档的首要读者是 Agent。Agent 只看文档时，应能从症状或入口定位到：完整调用链、每阶段状态变化、实现 owner、机制出处、输出投影和验证命令。

本规则治理仓库内的求解器文档，不把游戏规则复制进来。游戏机制由 [`知识库引用.md`](知识库引用.md) 指向固定版本的 `arknights-base-vault`；本仓只说明机制如何映射进运行时和求解策略如何消费它。

## 2. 文档角色与目录

| 角色 | 目录 | 责任 |
|---|---|---|
| `canonical` | `docs/` | 裁决一个稳定领域键的求解器语义或引用合同 |
| `current-reference` | `docs/模块/`、`docs/调用链/`、`docs/接口/`、`docs/工程/` 或根 `docs/` | 记录当前代码、接口、调用链、验证和导航事实 |
| `generated-reference` | `docs/生成索引/` | 由确定性脚本重建的模块、命令、route 和反向索引 |
| `active-change` | `docs/TODO/` | 尚未吸收进 current owner 的提案、缺口和迁移工作 |
| `decision` | `docs/ADR/` | 需要长期保留的架构选择、替代方案和后果 |
| `archive` | `docs/ARCHIVE/` | 已完成、被替代或仅供追溯的材料 |
| `evidence` | `feedback/` | 用户反馈或长期证据台账；不裁决产品语义 |

目录是责任边界，不是主题标签。一个事实只能有一个 current owner；其他页只能链接和说明适用范围。

## 3. 当前页最小元数据

受治理 Markdown 在一级标题后使用连续 blockquote 元数据：

```markdown
> 文档角色：current-reference
> 生命周期状态：current
> 当前真源：docs/文档生命周期.md
> 摘要：说明这页解决什么定位问题
> 代码范围：crates/infra-core/src/trade; crates/infra-cli/src/commands
> 代码锚点：crates/infra-core/src/trade/solver.rs::solve_trade_with_shift
> 关联链路：docs/调用链/技能到房间结算.md
> 核验基线：947f1a2
```

`代码范围` 是仓库相对文件或 glob；`代码锚点` 必须指向真实文件并带稳定符号；`关联链路` 指向真实调用链页；`核验基线` 记录核对代码时的 commit 或 evidence。模块、调用链、接口页必须填写这四项，避免只有泛化模块名而没有定位入口。

## 4. 调用链页的固定内容

每个稳定链路拥有 ID，并登记在 `docs/agent-index/routes.json`。正文按以下顺序写：

1. 触发条件、CLI/API 入口和输入文件；
2. 关键类型及其所有权；
3. 阶段顺序与每阶段读取、写入、刷新或清除的状态；
4. 分支、准入、剪枝、缓存和 fallback；
5. 错误如何包装、向上返回或降级；
6. 输出字段、导出和副作用；
7. 相关模块、机制知识库引用和验证命令；
8. 已知缺口、未验证范围和不应推导的结论。

函数箭头只能作为索引，不能代替状态流说明。生成器可以确认路径存在，不能证明调用语义；跨层行为修改必须人工反查入口、分支和写入点。

## 5. 代码修改何时更新文档

代码变化不再默认要求全仓传播，但以下触点必须在同一变更中复核相应 owner：

| 代码触点 | 必须复核 |
|---|---|
| CLI/API 入口、参数、协议或输出字段 | `docs/接口/`、对应 `docs/调用链/`、route registry |
| Plan、候选准入、状态写入、resolve 或跨设施传播 | `docs/调用链/`、对应 `docs/模块/`、相关 canonical |
| 轮换 profile、bind、休息、岗位或 MAA | 排班/导出调用链和接口页 |
| 机制解释器、单位、阶段、技能映射 | 模块页、[`知识库引用.md`](知识库引用.md) 和机制差异说明 |
| 搜索、剪枝、Bake、cache 或目标 | 模块页、`QUALITY_AND_AUDIT.md`、保证等级与验证入口 |
| 仅重命名或内部重构且外部行为不变 | 检查现有锚点；若仍然成立，只在变更记录中说明无需正文修改 |

作者必须声明行为触点，而不是只依赖路径匹配。审阅者可以扩大关联页面；没有发现受影响文档时也要写出“已复核，当前描述仍成立”。

## 6. 状态与关闭

| 角色 | 合法状态 |
|---|---|
| `canonical` / `current-reference` | `current` |
| `generated-reference` | `generated` |
| `active-change` | `proposal`、`ready-on-request`、`in-progress`、`blocked` |
| `decision` | `proposed`、`accepted`、`superseded` |
| `archive` | `completed`、`superseded`、`historical` |
| `evidence` | `current`、`closed` |

关闭 active change 时，先把确认事实吸收到唯一 current owner，再拆分仍开放的工作，最后将原文移到 archive 并运行索引检查。完成页不能留在 `docs/TODO/` 只靠 banner 声明完成。

## 7. 生成索引和机械门禁

手写源是正文、route registry 和源码；生成页不得手工编辑：

```bash
python3 scripts/codex/generate_agent_index.py
python3 scripts/codex/generate_agent_index.py --check
python3 scripts/codex/docs_inventory.py --check
python3 scripts/codex/check_repository_facts.py
```

检查范围包括元数据、唯一 owner、代码锚点和关联链路存在性、Markdown 链接、CLI 命令覆盖、模块地图、生成内容和知识库引用路径。检查器不把符号匹配冒充语义证明，也不因某个路径命中就自动声称文档正确。

## 8. 文档迁移原则

- 机制正文进入知识库；本仓留下引用、运行时映射和差异。
- 当前实现与未来计划拆开；计划不能解释当前行为。
- 重复主链只保留调用链页；INDEX、模块页和接口页只路由或承担各自局部责任。
- 失效链接、绝对本机证据路径、已删除符号和“未来会实现”叙述必须修复、归档或明确标为未实现。
- 不为每个 helper 写页面；只有跨问题复用的入口、状态、边界和验证才进入调用链或模块 owner。
