## 输入类型

### 文件型 CLI 输入

`plan` 和 `layout` 命令从文件加载：

- `BaseBlueprint`：布局房间、等级、生产配置、无人机上限和场景参数；语义校验由 `BaseBlueprint::validate` 完成。
- `OperBox`：JSON 数组或 `plan` 支持的一图流 xlsx；每项必须有 id、name、elite、level、own、potential、rarity。
- 运行时表：`operator_instances.json`、`skill_table.json` 等由 `default_*_path` 定位；数据搜索和 fallback 归 `infra-core::skill_table`。

`plan` 默认使用 243 布局和 full-e2 operbox。正式调用应显式传入输入与输出路径，避免把结果写回输入目录。

### `plan.compute` 内联输入

请求 `method` 为 `plan.compute` 时，`params` 必须包含：

```json
{
  "schema_version": 4,
  "layout": { "rooms": [] },
  "operbox": [],
  "labels": { "layout": "optional", "operbox": "optional" },
  "options": {
    "rotation": "abc_12_6_6",
    "top": 20,
    "system_preferences": {},
    "maa_title": null,
    "fiammetta_enable": true,
    "assert_invariants": false
  }
}
```

`additionalProperties=false`：未知字段在 schema admission 阶段拒绝。当前支持 schema v1、v2、v3、v4；v4 是当前完整契约，包含 `fiammetta_enable` 与 `assert_invariants`。每个版本允许的轮换 profile 以对应 schema 文件为准，不能从 v4 反推旧版本也接受该值。

限制由代码和 schema 同时约束：operbox 1–1000 项、layout 房间 1–64、`top` 1–100、label 非空且不超过 200 UTF-8 字节。通过 JSON Schema 后仍执行布局唯一性、设施/产品匹配和 operbox 进度等语义校验。

## 输出类型

### `plan.compute` 外层响应

每行响应都有：`id`、`ok`、`elapsed_ms`、`solver`。成功时 `result` 包含 `schema_version`、`profile`、`rotation`、`maa` 和 `training_advice`；失败时通常 `ok=false`，外层 `error` 有 `code=PLAN_FAILED`、`stage=plan.compute`，`result.error` 同时包含业务失败信息，便于前端保留部分 rotation/profile。

`rotation` 是当前排班的结构化结果：profile、daily 三域效率、每个 shift 的时长、active/resting team、assignment、分房效率和加权效率。`profile` 是账号分析投影，不是完整 assignment 副本。`maa` 是对同一 rotation 的导出投影，导出层不重新选人。

### `plan` Worker 方法

`method=plan` 接受文件路径参数并返回 `PlanResult`：layout、operbox、owned、top、rotation、可选的 profile/MAA/output_dir 路径、daily 效率、shifts 和 warnings。它与 CLI `plan` 共用 `compute_plan`，但输出是 Worker result，不是 `plan.compute` schema。

### 文件输出

- profile：`BoxProfile`，当前 `schema_version=4`；包含 summary、domains、rotation 和 baseline rotation。
- rotation：`TeamRotationReport`，由 `--rotation-out` 写出；用于后续 `layout eval` 或人工审阅。
- MAA：`MaaSchedule`，由 `build_from_team_rotation` 生成；读取 rotation 已确认的班次，不重新选择干员。
- `layout eval --explain-json`：`schema_version=1` 的固定编制结算 trace，包含 room 结果、control events、final state 和 totals。

消费者应读取结构化 JSON，并检查 schema/version；不要从 stdout 文本或历史 fixture 推断 wire 字段。

## 兼容原则

兼容层是字段、枚举、单位、缺省和错误表达的契约。可以重写内部求解，但不能静默改变 `BaseBlueprint`、`OperBox`、`BaseAssignment`、效率分量、轮换 profile 名称和“不支持/无解”的表达。新字段应升 schema 或进入明确兼容版本；旧版本 schema 不接受未知字段。
