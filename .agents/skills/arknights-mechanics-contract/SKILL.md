# 机制契约

1. 完整读该机制的 canonical 文档（游戏机制入口见 `docs/机制/知识库引用.md`）。记下规则、单位、作用范围、时机、前置条件、排除项，以及它是精确、概率还是暂不支持。
2. 从来源数据行沿 registry / 数据加载 → L1 解释 → L2 结算 → L3 shortcut 或输出，只追到任务需要处。`data/` 只承载运行时数值，不裁决有争议的语义。
3. 找到最早放行错误结果的映射或结算 owner。前面的 owner 错了，就不要去修输出格式、fixture 或当前 top 结果。

每个改动的机制，交代：

- canonical 文档和对应的数据行；
- 负责的代码位置和受影响的输出；
- 带单位和作用范围的公式拆解；
- 前置条件、零值 / 空集、边界情况和一个相邻反例；
- 结果属于精确、policy、heuristic、approximation 还是暂不支持。

快照测试的输入如果没有单独隔离出被改的那一项，它是绿的也证明不了公式。
